**Subresource Integrity сравнивает полученный ресурс с ожидаемым криптографическим хешем.** При несовпадении браузер не использует ресурс; это не проверка качества и безопасности самого разрешённого кода.

#### Механизм и границы

- Хеш привязан к конкретным байтам версии. Если CDN меняет файл, старое `integrity` перестаёт подходить: ресурс и хеш обновляют согласованно.
- Для cross-origin ресурса с SRI нужен подходящий CORS-ответ. `crossorigin="anonymous"` задаёт режим запроса, но не добавляет разрешающий заголовок на сервере.
- SRI защищает подключённый ресурс от неожиданной подмены, но не спасает, если атакующий может изменить и HTML с доверенным хешем. CSP решает другой уровень политики.
- Обычно используют с фиксированными версиями script и stylesheet; случайную строку или хеш имени файла нельзя подставлять вместо корректного `integrity`.

#### Пример

```html
<!-- Схема подключения: HASH заменяют реальным SRI-хешем файла. -->
<script
  src="https://cdn.example.com/library.v1.js"
  integrity="sha384-HASH"
  crossorigin="anonymous"
></script>
```
