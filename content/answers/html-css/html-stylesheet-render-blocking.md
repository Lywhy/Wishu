**Стили могут задерживать отображение и исполнение зависящих от них сценариев, хотя сами обычно не останавливают разбор HTML.** Поэтому «CSS вообще не влияет на DOMContentLoaded» - слишком сильное утверждение.

<!-- wishu:answer-block -->

#### Механизм и границы

- Обычный parser-inserted script может ждать уже встреченные блокирующие таблицы стилей: скрипт способен читать вычисленные стили, для которых нужен согласованный результат.
- DOMContentLoaded не ждёт все картинки и не ждёт CSS как самостоятельную категорию ресурсов. Но отложенные сценарии, которых событие ждёт, могут зависеть от готовности стилей.
- async, defer и модули имеют собственные правила исполнения; нельзя переносить поведение обычного script на все случаи.
- Диагностируйте цепочку в Network/Performance: поздний CSS может оказаться причиной задержки скрипта, а не только первого отображения.

#### Пример

```html
<link rel="stylesheet" href="large.css" />
<script src="measure-layout.js"></script>
<!-- Скрипт может ждать предшествующую таблицу стилей. -->
```
