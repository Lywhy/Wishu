**`contenteditable` включает редактирование содержимого элемента, но не превращает его в нативный контрол формы.** Нет автоматического `value`, name-payload и constraint validation как у `textarea`.

<!-- wishu:answer-block -->

#### Механизм и границы

- Для простого многострочного текста `textarea` даёт понятную семантику, подпись, выделение и отправку данных. Contenteditable оправдан, когда нужен собственный редактор.
- У rich-text редактора отдельно проектируют модель документа, вставку, IME, выделение, отмену и доступность. Сохранённый HTML нельзя считать доверенным только потому, что он получен из своего редактора.
- `contenteditable="plaintext-only"` ограничивает форматирование в поддерживающих средах, но не добавляет поведение формы. Для пользовательского контента всё равно нужна подходящая обработка.

#### Пример

```html
<label for="comment">Комментарий</label>
<textarea id="comment" name="comment" rows="5"></textarea>
<!-- Предпочтительный вариант для обычного многострочного текста. -->
```
