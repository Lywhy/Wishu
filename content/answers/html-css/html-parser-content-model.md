Браузер строит DOM по правилам HTML-парсера и может автоматически закрыть или переставить элементы при недопустимой структуре. Исходный текст не является точной записью будущего дерева.

<!-- wishu:answer-block -->

Например, блочный раздел внутри p не становится обычным дочерним блоком абзаца: парсер завершит абзац. Нельзя вкладывать button в button или произвольные элементы между table и её строками.

Сравнивайте исходник и дерево в DevTools. Для SSR ошибка структуры особенно заметна: браузер уже исправил HTML, а React ожидает исходную модель. Исправлять нужно структуру, а не маскировать hydration mismatch.

#### Проверка исходника до исправления hydration

Закрытие p перед вложенным блочным содержимым происходит при разборе HTML. Сервер мог выдать одну строку, а React получит уже скорректированное дерево. Не подавляйте предупреждение гидратации до проверки валидности разметки. Проверяйте вкладку Elements и исходный ответ отдельно; исправление состоит в корректной структуре, а не случайной дополнительной обёртке внутри p.

```html
<!-- Корректная структура вместо <p>Текст<div>Блок</div></p> -->
<p>Вводный текст.</p>
<div>Самостоятельный блок.</div>
```
