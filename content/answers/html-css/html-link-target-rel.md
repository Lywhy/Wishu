**`noopener` ограничивает связь нового контекста с открывшим окном; `noreferrer` подавляет передачу Referer и также подразумевает `noopener`.** Это разные последствия для безопасности и аналитики.

<!-- wishu:answer-block -->

#### Механизм и границы

- В современных браузерах `target="_blank"` у обычной ссылки уже подразумевает поведение `noopener`. Явное rel может документировать намерение, но не нужно объявлять любой _blank обязательно уязвимым.
- `noreferrer` скрывает источник перехода от получателя. Выбирайте его осознанно: отсутствие Referer может влиять на аналитику и серверные правила.
- Открытие новой вкладки не должно быть неожиданным, особенно для вспомогательных технологий. Не заставляйте каждую внутреннюю ссылку открывать отдельный контекст.

#### Пример

```html
<a href="https://example.com/docs" target="_blank" rel="noopener">
  Документация (в новой вкладке)
</a>
```
