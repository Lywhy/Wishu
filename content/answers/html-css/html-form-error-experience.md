**Ошибка должна объяснять проблему текстом, быть связана с полем и появляться в подходящий момент.** `aria-invalid` сообщает ошибочное состояние, но не выполняет проверку и не показывает сообщение.

<!-- wishu:answer-block -->

#### Механизм и границы

- Связь через `aria-describedby` позволяет озвучить пояснение вместе с полем. Сохраняйте `label`: сообщение ошибки не заменяет название.
- Не помечайте все обязательные пустые поля ошибочными сразу при открытии формы. Обычно полезен показ после попытки отправки или после согласованного взаимодействия.
- После неуспешной отправки можно показать сводку с ссылками на поля и продуманно перевести фокус. Не перемещайте фокус на каждый ввод и не озвучивайте одно сообщение несколькими live regions.
- CSS `:invalid` отражает браузерное состояние ограничения, а не факт знакомства пользователя с ошибкой. Серверную ошибку нужно отдельно согласовать с отображением.

#### Пример

```html
<label for="email">Электронная почта</label>
<input id="email" name="email" type="email" aria-invalid="true" aria-describedby="email-error" />
<p id="email-error">Укажите полный адрес, например anna@example.com.</p>
```
