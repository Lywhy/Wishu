**Отладка - воспроизведение проблемы и проверка гипотез о состоянии программы.**

<!-- wishu:answer-block -->

### Как это работает

DevTools позволяют ставить breakpoints, идти по шагам, смотреть область переменных и стек, останавливаться на исключениях и изучать сеть. Условные точки и logpoints помогают не менять рабочий код ради каждого наблюдения.

Debugger запрашивает остановку, если подключён отладчик и паузы разрешены; без соответствующего инструмента он обычно не даёт видимого эффекта. Нужен небольшой воспроизводимый сценарий, а не только дополнительные console.log.

Профилирование отвечает на вопрос о времени и памяти и дополняет, но не заменяет пошаговую отладку.

### Пример и его разбор

```javascript
function inspectTotal(values) {
  const total = values.reduce((sum, value) => sum + value, 0)
  debugger // учебная точка остановки для подключённого отладчика
  return total
}
// В рабочем коде такую инструкцию убирают после расследования.
```

Точка debugger размещена после вычисления total: при остановке можно проверить values, результат `reduce` и стек вызовов. Это позволяет сравнить фактическое состояние с гипотезой. После расследования учебную остановку убирают, а не оставляют как часть поведения приложения.
