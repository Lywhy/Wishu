**`ArrayBuffer` хранит бинарные данные, а `TypedArray` и `DataView` дают представления для чтения и записи.** Несколько представлений могут обращаться к одному буферу.

### Выбор представления

| Инструмент                          | Назначение                                           |
| ----------------------------------- | ---------------------------------------------------- |
| `ArrayBuffer`                       | Сам блок байтов                                      |
| `Uint8Array`, Float32Array и другие | Работа с элементами одного числового типа            |
| `DataView`                          | Чтение разных числовых типов с явным порядком байтов |

### Отличия от обычного массива

Типизированный массив не является обычным Array. Его операции преобразуют значения согласно типу элементов.

Изменения через одно представление видны через другое представление того же участка буфера. Для сетевого формата порядок байтов нужно задавать согласно протоколу.

### Пример и его разбор

```javascript
const buffer = new ArrayBuffer(4)
const bytes = new Uint8Array(buffer)
const view = new DataView(buffer)
view.setUint16(0, 0x1234, false) // big-endian
Array.from(bytes) // [18, 52, 0, 0]
bytes[0] = 0
view.getUint16(0, false) // 52
```

`DataView` и `Uint8Array` в примере смотрят на одни и те же четыре байта. Запись 0x1234 с явно заданным big-endian создаёт байты 18 и 52, а изменение первого байта через bytes сразу меняет следующее чтение view. Это совместные представления, поэтому передача буфера не означает независимого копирования его содержимого.

### Типичная ошибка

> Считать `TypedArray` независимой копией переданного буфера или полагаться на порядок байтов платформы в протоколе.
