**В ES-модуле `await` допускается на верхнем уровне без обёртки `async`-функцией.**

<!-- wishu:answer-block -->

### Как это работает

Модуль может дождаться конфигурации или другой асинхронной инициализации до готовности своих зависимых потребителей. Это не разрешает `await` в любом обычном скрипте.

Зависимые модули ожидают завершения такого выполнения, поэтому медленная операция может задержать целую часть графа. Другие независимые части не обязаны блокироваться.

Циклы и взаимное ожидание усложняют запуск; необязательную работу часто лучше экспортировать явной `async`-функцией. В классическом script такой синтаксис недопустим.

### Пример и его разбор

```javascript
// config.js, подключённый как ES-модуль
const response = await fetch("/config.json")
if (!response.ok) throw new Error(`HTTP ${response.status}`)
export const config = await response.json()
// Модули, зависящие от config.js, ждут его завершения.
```

Config становится доступен после получения и разбора ответа. Зависимые модули ожидают эту инициализацию, поэтому ошибка или медленная сеть влияет на готовность соответствующего графа. Проверка response.ok отдельно различает HTTP-ошибку и успешный транспортный ответ.
