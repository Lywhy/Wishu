**Обычная глубокая рекурсия может переполнить стек даже при правильном базовом случае.**

### Как это работает

Универсального безопасного числа вызовов нет: предел зависит от движка, среды и формы функции. Ошибка может называться RangeError или InternalError в зависимости от реализации.

Для линейной рекурсии состояние часто переносится в переменные цикла. Для обхода дерева можно хранить ожидающие узлы в явном массиве-стеке или очереди.

Это переносит память для обхода из стека вызовов в структуру данных, но не делает расход памяти нулевым. Если нужно сохранить порядок обхода, детей кладут в стек в соответствующем обратном порядке; для циклических графов нужен учёт посещённых узлов.

### Пример и его разбор

```javascript
// Каждый узел дерева имеет необязательный массив children.
function countNodes(root) {
  const pending = [root]
  let count = 0
  while (pending.length > 0) {
    const node = pending.pop()
    count += 1
    for (const child of node.children ?? []) pending.push(child)
  }
  return count
}
countNodes({ children: [{}, {}] }) // 3
```

Массив pending в countNodes хранит ещё не обработанные узлы вместо цепочки незавершённых рекурсивных вызовов. Каждый проход забирает узел, учитывает его и добавляет детей. Для небольшого дерева из примера получается 3. Такой перенос устраняет зависимость от глубины `call` stack, но сохраняет необходимость памяти и требует отдельной защиты, если структура является графом с циклами.
