**Важны не только количество запросов, но и объём данных, задержка, приоритет и зависимости.**

### Как это работает

Уменьшают лишние загрузки, используют подходящий HTTP-кеш, сжатие и размеры ресурсов. Независимые необходимые данные можно загружать параллельно; зависимые водопады удлиняют критический путь.

Объединение всего в один огромный файл может ухудшить начальную загрузку, кеширование и разбор JavaScript. Разбиение тоже создаёт накладные расходы, поэтому выбирают границы по пользовательским сценариям.

Кеш должен учитывать актуальность и права доступа; сокращение запроса не должно означать показ чужих или устаревших данных.

### Пример и его разбор

```javascript
// Вопросы к сетевой трассе:
// Какие ресурсы нужны до первого полезного экрана?
// Можно ли убрать повторную загрузку или лишний объём?
// Какие запросы ждут друг друга без необходимости?
```

Сетевая трасса показывает, какие ресурсы лежат на критическом пути, а какие можно отложить. Удаление небольшого параллельного запроса может ничего не изменить, тогда как устранение последовательного ожидания ускорит полезный экран. Поэтому сравнивают итоговое время сценария, а не только число строк в Network.
