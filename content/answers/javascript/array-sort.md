**`sort()` изменяет массив и без compareFn сравнивает строковые представления элементов по UTF-16.** Для чисел обычно нужен явный числовой компаратор.

### Компаратор

Отрицательное значение помещает a перед b. Положительное - после b.

Ноль означает эквивалентность для сортировки. Компаратор должен задавать согласованный порядок, а не случайное или boolean-значение.

### Нюансы

Современный стандарт требует стабильной сортировки: равные элементы сохраняют исходный относительный порядок. `toSorted()` создаёт новый массив; `[...items].sort()` тоже отделяет верхний уровень.

Для строк с языковыми правилами применяют `localeCompare` или настроенный `Intl.Collator`. Конкретная временная и пространственная сложность реализации `sort` стандартом не фиксируется.

### Пример и его разбор

```javascript
const values = [10, 2, 1]
;[...values].sort() // [1, 10, 2]
;[...values].sort((a, b) => a - b) // [1, 2, 10]
values // [10, 2, 1] - сортировали копии
```

Без компаратора строка «10» располагается раньше «2», что объясняет первый результат. Разность a - b задаёт нужный числовой порядок через знак возвращаемого значения. Копирование перед `sort` сохраняет исходный values. Компаратор следует рассматривать как правило согласованного порядка, а не как произвольный предикат, отвечающий только `true` или false.

### Типичная ошибка

> Возвращать a > b из компаратора: это не описывает отрицательное значение и согласованный порядок.
