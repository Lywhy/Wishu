**`async`-функция возвращает `Promise`, а `await` приостанавливает продолжение этой функции до результата ожидаемого значения.** Главный поток при этом не обязан блокироваться.

### Что делает `await`

Успешный результат становится значением выражения `await`. Отказ выбрасывается в месте `await` и может быть перехвачен `try/catch`.

Продолжение после `await` асинхронно даже для уже выполненного Promise. Код до первого `await` выполняется при вызове функции.

`await` не превращает тяжёлый синхронный расчёт в неблокирующий: сам расчёт всё ещё занимает поток.

### Последовательность или параллелизм

Зависимые операции ожидают последовательно. Независимые можно сначала запустить, а затем дождаться вместе. Ограничение числа одновременно запущенных операций - отдельная задача.

### Пример и его разбор

```javascript
async function example() {
  console.log("до await")
  await 1
  console.log("после await")
}
example()
console.log("снаружи")
// до await → снаружи → после await
```

Example начинает работу немедленно и выводит «до `await`». На `await` продолжение приостанавливается, вызывающий код успевает вывести «снаружи», и лишь потом появляется «после `await`». Даже ожидание простого числа сохраняет асинхронную границу продолжения. Однако всё, что вычисляется до этой границы, продолжает занимать текущий поток.

### Типичная ошибка

> Говорить, что `await` останавливает выполнение всего JavaScript или сам создаёт дополнительный поток.
