**Конструктор может явно вернуть объект, который заменит результат new.**

<!-- wishu:answer-block -->

### Как это работает

В базовом классе возвращаемый примитив игнорируется, и результатом остаётся созданный экземпляр. Такая подмена часто затрудняет понимание ожидаемого прототипа и instanceof.

У производного конструктора разрешён объект или `undefined`; другой примитив вызывает TypeError. При обычном завершении или `return` `undefined` `this` должен быть уже инициализирован через super.

Явный возврат другого объекта может завершить производный конструктор без super, но это специальный случай, а не рекомендуемая модель обычного наследования.

### Пример и его разбор

```javascript
class Normal {
  constructor() {
    return 1
  }
}
new Normal() instanceof Normal // true
class Replaced {
  constructor() {
    return { custom: true }
  }
}
const value = new Replaced()
value.custom // true
value instanceof Replaced // false
```

Normal возвращает число, но результатом `new` остаётся экземпляр. Replaced возвращает отдельный объект, и именно он становится результатом, поэтому `instanceof` Replaced даёт false. При анализе конструктора нужно различать выполнение его тела и объект, который в итоге получает вызывающий код.
