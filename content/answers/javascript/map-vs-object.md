**`Map` хранит пары ключ - значение.**

<!-- wishu:answer-block -->

### Как это работает

Ключом может быть любой тип, включая объект, без преобразования в строку. Для работы используют `Set`, get, has, delete и size; обход for...of возвращает пары в порядке добавления.

Ключи сравниваются по SameValueZero, а объекты - по идентичности. Обычный объект удобен для записи с именованными полями и JSON-представления; его ключи - строки и `Symbol`.

`Map` удобен как коллекция с динамическими ключами и частыми изменениями. Запись map.key = value создаёт обычное свойство и не добавляет пару в Map.

Get возвращает `undefined` и при отсутствии ключа, и при записанном `undefined`; has различает эти случаи. `JSON.stringify` не сериализует записи `Map` автоматически.

### Как оценивать стоимость коллекции

Стандарт требует для `Map` в среднем сублинейного времени доступа относительно числа элементов, но не обещает конкретную хеш-таблицу и безусловное O(1) для любой операции. Выбор `Map` вместо Object объясняют контрактом ключей, порядком и операциями, а производительность проверяют на реальных данных. У `Map.forEach` callback получает `(value, key, map)`, а не `(key, value)`.

### Пример и его разбор

```javascript
const user = { id: 1 }
const roles = new Map()
roles.set(user, "admin")
roles.get(user) // "admin"
roles.get({ id: 1 }) // undefined: другой объект
roles.size // 1
const optional = new Map([["value", undefined]])
optional.has("value") // true
```

В roles ключом является конкретный объект user, поэтому новый литерал с тем же id не находит его запись. Сохраняется идентичность ключа, а не строковое имя поля. Пример optional дополнительно показывает отличие наличия ключа от результата get: сохранённое `undefined` не означает отсутствие записи. Для этого и существует отдельная операция has.
