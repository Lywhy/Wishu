**Циклическая зависимость ES-модулей сама по себе не запрещена.** Ошибка возникает, когда модуль читает привязку другого модуля до её инициализации.

<!-- wishu:answer-block -->

### Как рассуждать

1. Указать точку входа и граф зависимостей.
2. Различать установление связей и выполнение тел модулей.
3. Найти первое чтение значения и момент его инициализации.
4. Не путать возможность объявить функцию с безопасностью чтения всех используемых ею данных.

### Как исправлять архитектуру

Вынести общий контракт в третий модуль, передать зависимость явно или отложить чтение до фазы, где значения уже готовы. Замена const на var может скрыть TDZ, но оставить неправильный результат undefined.

### Пример и его разбор

```javascript
// Два отдельных файла. Точка входа - a.js.
// a.js
import { b } from "./b.js"
export const a = 1
console.log(b)

// b.js
import { a } from "./a.js"
export const b = a + 1 // ReferenceError: a ещё не инициализирована
```

При входе через a.js сначала требуется выполнить его зависимость b.js. Та читает a до строки export const a = 1 и попадает в TDZ. Проблема здесь в раннем чтении, поэтому исправление должно менять зависимость или фазу инициализации.

### Типичная ошибка

> Объявлять все циклы ошибкой или считать, что «живой импорт» отменяет TDZ.
