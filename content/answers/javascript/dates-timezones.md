**Date представляет момент на временной шкале через число миллисекунд от Unix epoch, а не хранит выбранный часовой пояс.** Локальные методы и форматирование интерпретируют этот момент в определённом поясе.

### Важные различия

Строка с Z или явным offset задаёт момент однозначнее, чем локальная дата и время без пояса. `toISOString()` выдаёт представление в UTC.

В стандартном формате строка только с датой и строка даты-времени без offset имеют разные правила интерпретации. День рождения или дата отпуска - календарные значения; не всегда правильно превращать их в UTC-момент.

Смена локального календарного дня не всегда равна добавлению 24 часов из-за переходов часового пояса.

### Пример и его разбор

```javascript
const meeting = new Date("2026-01-10T12:00:00+03:00")
meeting.toISOString() // "2026-01-10T09:00:00.000Z"
const formatter = new Intl.DateTimeFormat("ru-RU", {
  timeZone: "Europe/Moscow",
  dateStyle: "short",
  timeStyle: "short",
})
formatter.format(meeting) // отображение в заданном поясе
const birthday = "2000-01-10" // отдельная календарная дата
```

Offset исходной строки используется при вычислении момента, поэтому toISOString показывает 09:00 UTC. Formatter затем отображает тот же момент в Москве. Строка birthday оставлена календарной датой: для неё не нужно произвольно выбирать часовой пояс и время суток.

### Типичная ошибка

> Считать, что Date запомнил offset исходной строки, или произвольно парсить локализованные строки дат.
