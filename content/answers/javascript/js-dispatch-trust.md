**`dispatchEvent` синхронно доставляет созданное событие подходящим обработчикам. Такое событие не является полным воспроизведением реального пользовательского взаимодействия и его платформенных разрешений.**

### Как это работает

`isTrusted` сообщает о происхождении по правилам браузера, но не доказывает полномочия пользователя на сервере. Нельзя открывать доступ к данным только проверкой этого поля. CustomEvent.detail передаёт обычные данные без автоматического structured clone.

Бросок из event listener имеет свой путь сообщения об ошибке: внешний try/`catch` вокруг `dispatchEvent` не стоит считать универсальным перехватом всех listener-ошибок.

### Пример и его разбор

```javascript
const target = new EventTarget()
target.addEventListener("ready", (event) => console.log(event.isTrusted))
target.dispatchEvent(new Event("ready")) // false
// Пользовательская активация и разрешения этим не создаются.
```

Обработчик ready вызывается прямо во время `dispatchEvent` и видит `isTrusted` со значением false. Это обычная доставка программного события, которая не создаёт пользовательскую активацию. Проверка происхождения события также не заменяет серверную проверку прав пользователя.

### Типичная ошибка

> Использовать `isTrusted` как security-токен или ожидать разрешения Clipboard от искусственного click.
