**При некоторых досрочных завершениях for...of вызывает подходящий `return` итератора. Так итератор может освободить ресурс; обычный набор next-вызовов сам не создаёт такую же гарантию закрытия.**

<!-- wishu:answer-block -->

### Как это работает

`return` должен соблюдать протокол, в частности возвращать объект результата. Генератор может выполнять `finally` при закрытии. Ошибка очистки и исходное исключение взаимодействуют по правилам конкретной операции; нельзя обобщать любой случай на «`finally` всегда скрывает ошибку».

Если создаёте ресурсный iterable, явно опишите одноразовость, закрытие и поведение повторных вызовов.

### Пример и его разбор

```javascript
function* values() {
  try {
    yield 1
    yield 2
  } finally {
    console.log("очистка")
  }
}
for (const value of values()) {
  console.log(value)
  break
}
// Вывод: 1, затем очистка.
```

После первого значения break закрывает итератор и переводит генератор в finally. Поэтому «очистка» появляется без потребления второго элемента. Если вручную вызвать next один раз и просто забыть итератор, аналогичное закрытие автоматически из этого не следует.

### Типичная ошибка

> Забывать `return` у итератора, который владеет открытым ресурсом.
