**Prototype pollution - изменение прототипа через обработку недоверенных ключей, из-за которого посторонние свойства становятся видны другим объектам.** Риск особенно важен при рекурсивном слиянии и разборе путей к свойствам.

<!-- wishu:answer-block -->

### Как уменьшать риск

Проверять схему и разрешённые ключи на каждом уровне вложенности. Не доверять путям с `__proto__`, `constructor` и `prototype`.

Для словаря применять `Map` или объект без прототипа, если это соответствует задаче. Для значимых флагов использовать собственные проверенные свойства, а не доверять унаследованным значениям.

Не считать запрет одного имени полной защитой произвольного рекурсивного merge.

### Пример и его разбор

```javascript
const input = JSON.parse('{"name":"Анна","__proto__":{"isAdmin":true}}')
const allowed = new Set(["name", "theme"])
const settings = Object.create(null)
for (const [key, value] of Object.entries(input)) {
  if (allowed.has(key) && typeof value === "string") settings[key] = value
}
Object.hasOwn(settings, "isAdmin") // false
// Это плоская схема; вложенные данные требуют отдельной проверки.
```

Сам `JSON.parse` в примере создаёт данные с собственным ключом **proto**, а опасное поведение может появиться на следующем этапе обработки. Здесь разрешён только известный набор строковых полей и используется словарь без прототипа. Для вложенного ввода аналогичную проверку нужно применять на каждом уровне, куда приложение разрешает запись.

### Типичная ошибка

> Считать любую JSON-строку безопасной для последующего слияния в произвольный объект.
