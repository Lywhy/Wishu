**WebSocket устанавливает длительное двустороннее соединение: сервер и клиент могут отправлять сообщения без нового HTTP-запроса для каждого сообщения.**

### Как это работает

Браузерный объект сообщает open, message, error и close. Отправлять данные нужно после установления соединения, проверяя readyState при необходимости.

Клиент должен определить формат сообщений, завершение и повторное подключение на уровне приложения. Обычный WebSocket API не предоставляет полноценного механизма backpressure: при избыточном потоке может расти память; bufferedAmount помогает наблюдать очередь исходящих данных.

Для защищённой передачи используют wss; это отдельный протокол общения, не произвольная замена fetch.

### Поток сообщений и жизненный цикл

Перед отправкой проверяют состояние соединения; `bufferedAmount` показывает накопленные исходящие данные, но классический WebSocket API не предоставляет полноценного автоматического backpressure для входящих сообщений. Повторное подключение требует политики задержек, обработки дубликатов и восстановления подписок. Гарантии доставки и heartbeat задаются протоколом приложения, а не появляются из самого факта использования WebSocket.

### Пример и его разбор

```javascript
function connect(url, onMessage) {
  const socket = new WebSocket(url)
  socket.addEventListener("open", () => socket.send("hello"))
  socket.addEventListener("message", (event) => onMessage(event.data))
  socket.addEventListener("error", () => console.error("Ошибка соединения"))
  return () => socket.close()
}
```

Сообщение hello отправляется только после open, когда соединение уже установлено. Message передаёт приложению входные данные, а возвращённая функция закрывает канал при завершении использования. Этот минимальный пример не восстанавливает соединение и подписки. Такие гарантии, как повтор доставки и устранение дубликатов, задаются отдельным протоколом поверх WebSocket.
