**Асинхронный генератор последовательно обслуживает запросы продолжения. Создание множества next-промисов заранее не означает параллельное выполнение его тела.**

<!-- wishu:answer-block -->

### Как это работает

Такой pull-протокол помогает ограничивать скорость получения, но бездумный prefetch способен накопить ожидающие запросы и данные. Явный ограничитель параллельности нужен там, где операции действительно независимы.

`return` не является универсальным прерыванием уже выполняемого `await`: вложенной операции может понадобиться AbortSignal. Разделяйте завершение итератора и отмену I/O.

### Пример и его разбор

```javascript
async function* pages(load) {
  for (let page = 1; page <= 3; page++) yield await load(page)
}
// Поддерживаемый load определяет сеть и отмену.
// Очередь iterator.next() не распараллеливает этот цикл.
```

Тело pages переходит к следующему номеру после завершения предыдущего load и выдачи результата. Заранее созданные next лишь ставят запросы продолжения в очередь. Если нужен ограниченный параллельный загрузчик, его планирование нужно реализовать отдельно от этого последовательного генератора.

### Типичная ошибка

> Считать очередь next() эквивалентом запуска трёх независимых fetch.
