**Сеть и поток разбивают данные по своим границам, которые не обязаны совпадать с UTF-8 символом, строкой или сообщением протокола. Парсер должен сохранять незавершённый фрагмент между чтениями.**

### Как это работает

Декодер сохраняет частичные байтовые последовательности, а framing-уровень - неполную строку или запись. Это две разные задачи. Для NDJSON нужно учитывать полный разделитель и последнюю запись согласно формату.

TextDecoderStream может решить декодирование, но не превращает каждый полученный текстовый чанк в готовое сообщение.

### Пример и его разбор

```javascript
const decoder = new TextDecoder("utf-8")
let text = ""
// Для каждого byteChunk: text += decoder.decode(byteChunk, { stream: true })
// После конца: text += decoder.decode()
// Затем отдельно выделяются сообщения по контракту протокола.
```

Один decoder сохраняет неполные UTF-8 последовательности между вызовами, а заключительный decode завершает декодирование. Полученный текст ещё нужно разделить на сообщения. Граница байтового чанка не гарантирует ни целую строку, ни готовый JSON.

### Типичная ошибка

> Вызывать `JSON.parse` на каждом произвольном чанке fetch-body.
