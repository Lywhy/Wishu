**Некоторые сочетания повторений и альтернатив заставляют regex-движок проверять чрезвычайно много вариантов при неуспешном совпадении. Такой ReDoS может заблокировать выполняющий JS-поток.**

<!-- wishu:answer-block -->

### Как это работает

Ограничивайте вход, упрощайте неоднозначные шаблоны и выбирайте подходящий алгоритм либо движок для задачи. Общий `Promise`-тайм-аут не прервёт синхронный regex на том же заблокированном потоке.

Перенос в управляемый Worker может дать внешнюю возможность остановить работу, но имеет стоимость и не делает плохой шаблон хорошим. Проверка только на удачных коротких строках недостаточна.

### Пример и его разбор

```javascript
// Опасная форма для анализа, не пример для запуска на длинном вводе:
// /^(a+)+$/
// Неоднозначные повторения + поздний неуспех создают множество вариантов.
// Для конкретного простого формата часто достаточно /^a+$/ с лимитом входа.
```

Вложенные повторения допускают множество способов разделить последовательность a на группы. Если совпадение ломается ближе к концу, движок может перебрать очень много вариантов. Таймер в том же потоке не сможет прервать уже заблокировавший его синхронный поиск.

### Типичная ошибка

> Защищать синхронный regex `Promise.race` с таймером в том же UI-потоке.
