**`throw` прерывает обычное выполнение и передаёт выброшенное значение ближайшему подходящему `catch`. Конструкция `try`...`catch`...`finally` позволяет отделить выполняемую операцию, обработку ошибки и действия при выходе.**

### Как это работает

Код внутри `try` выполняется до завершения или исключения. Если возникает исключение, оставшиеся операторы этого `try` пропускаются, а управление переходит в `catch`. Обработчик может восстановиться, вернуть понятный результат либо выбросить ошибку дальше. Если ошибка появилась уже внутри `catch`, тот же `catch` не перехватывает её повторно.

`finally` выполняется при выходе из конструкции, в том числе перед завершением `return` из `try` или `catch`. Поэтому здесь удобно освобождать ресурсы. Но собственный `return` или `throw` внутри `finally` заменяет прежний исход и может случайно скрыть ошибку. Завершение процесса или закрытие среды не дают безусловной гарантии выполнения очистки.

### Пример и его разбор

```javascript
function parseAge(value) {
  const age = Number(value)
  if (!Number.isInteger(age) || age < 0) {
    throw new RangeError("Нужен целый неотрицательный возраст")
  }
  return age
}
try {
  parseAge("текст")
} catch (error) {
  console.error(error)
}
```

В примере `parseAge` отклоняет недопустимое значение через `RangeError`. После `throw` функция не доходит до `return` age: ошибка передаётся вызывающему `catch`. На практике обрабатывать её стоит там, где есть осмысленная реакция, например сообщение пользователю или отказ текущей операции.

### Нюансы и типичные ошибки

Выбросить можно любое значение, однако `Error` и подклассы дают сообщение и диагностику. Синхронный `try` не охватывает поздний callback: для `Promise` нужно ожидание внутри `try` либо отдельный `catch`. Подробности этого различия разобраны в вопросе об `async`-ошибках.
