**Replacer управляет сериализуемым представлением, reviver преобразует уже разобранные значения. Они позволяют задать предметную схему, но не восстанавливают автоматически все типы JavaScript.**

<!-- wishu:answer-block -->

### Как это работает

Reviver обходит вложенные значения по определённому порядку; возврат `undefined` может удалить свойство. Слишком общий шаблон «любая похожая строка - Date» способен изменить обычный пользовательский текст.

Большое JSON-число может потерять точность при обычном разборе. Для переносимого контракта передавайте такие значения строками и проверяйте их. Теги типов, версии и допустимые поля определяются приложением.

### Пример и его разбор

```javascript
const text = JSON.stringify({ count: 3n }, (_key, value) =>
  typeof value === "bigint" ? { type: "bigint", value: String(value) } : value,
)
// Восстановление должно проверять именно согласованную tagged-схему,
// а не превращать произвольный объект с полем type в привилегированный тип.
```

Replacer заменяет `BigInt` на согласованное объектное представление со строковым значением, которое JSON умеет передавать. Обратный шаг требует проверки схемы и допустимых полей. Само наличие type у пользовательского объекта ещё не доказывает, что его нужно превращать в специальный тип приложения.

### Типичная ошибка

> Без проверки превращать любую строку нужной формы в Date или любой tagged-object в экземпляр.
