**`async`-функция всегда возвращает `Promise`. Необработанное исключение внутри неё отклоняет этот `Promise`, поэтому вызывающий код должен наблюдать его результат через `await` или обработчик `catch`.**

### Как это работает

Обычный `try`...`catch` охватывает выполнение кода внутри своего блока. Если код лишь запустил асинхронную операцию и вышел, её последующий отказ не попадает в этот `catch`. `await` связывает продолжение текущей `async`-функции с исходом `Promise`: при отклонении управление возобновляется как исключение в точке ожидания.

Поэтому внутри `try` различаются `return` `operation`() и `return` `await` `operation`(). Первая форма передаёт возвращённый `Promise` наружу, не ожидая его отклонения локальным обработчиком. Вторая позволяет локальному `catch` обработать отказ. При этом синхронный `throw` из самого вызова `operation` перехватывался бы в обоих случаях.

### Пример и его разбор

```javascript
async function withContext(operation) {
  try {
    return await operation()
  } catch (cause) {
    throw new Error("Операция не завершилась", { cause })
  }
}
// Вызывающий код также должен обработать отклонение withContext(...).
```

В примере `withContext` ожидает `operation`. Если она завершится отказом, `catch` добавит понятный контекст, сохранив исходную причину через cause. Новый `throw` отклонит `Promise` самой `withContext`, поэтому её вызывающий код тоже обязан обработать отказ.

### Нюансы и типичные ошибки

Возврат обычного значения из `catch` превращает результат соответствующей `async`-функции в успешный, если далее не возникает ошибка. Это должно быть осознанным восстановлением. Операция, запущенная отдельно без `await`, требует собственного обработчика: соседнее ожидание её не покрывает.
