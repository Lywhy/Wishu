**Литеральный пользовательский текст нельзя вставлять в шаблон как готовую регулярную программу. `RegExp.escape` в поддерживаемой среде экранирует его для такого использования; конструктор дополнительно получает уже разобранную JS-строку.**

### Как это работает

Самодельная замена нескольких специальных знаков часто пропускает контекстные случаи, например границы escape-последовательностей. Не путайте escaping шаблона с escaping replacement-строки или HTML.

Если по задаче пользователь вводит настоящий regex, это другой контракт с ограничениями сложности и обработкой SyntaxError. Поддержку `RegExp.escape` проверяют в целевой среде, а не предполагают по наличию TypeScript-типа.

### Пример и его разбор

```javascript
const input = "a.b"
const pattern = new RegExp(RegExp.escape(input))
console.log(pattern.test("a.b")) // true
console.log(pattern.test("axb")) // false
```

Точка из a.b должна обозначать буквальный символ, поэтому escape меняет её роль в шаблоне. Итоговый `RegExp` находит a.b и отвергает axb. Без экранирования точка стала бы оператором и незаметно расширила набор подходящих строк.

### Типичная ошибка

> Считать точку из пользовательского запроса обычной буквой после прямого `new` `RegExp`(input).
