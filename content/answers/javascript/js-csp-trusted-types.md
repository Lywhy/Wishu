**CSP ограничивает допустимые источники и способы исполнения по выбранной политике. Trusted Types в поддерживаемой среде помогает контролировать поступление значений в определённые опасные DOM-sinks.**

<!-- wishu:answer-block -->

### Как это работает

Trusted policy должна действительно создавать безопасное представление; обёртка, возвращающая вход без проверки, не делает данные безопасными. Эти механизмы не заменяют контекстно правильное создание DOM и проверку доверия к содержимому.

Nonce/hash-подход и ограничения eval нужно согласовать с инфраструктурой. Политика, разрешающая всё ради устранения предупреждений, теряет смысл. Поддержку Trusted Types нельзя без проверки объявлять одинаковой во всех браузерах.

### Пример и его разбор

```javascript
function showText(untrustedText) {
  const node = document.createElement("p")
  node.textContent = untrustedText
  return node
}
// Для обычного текста не нужен HTML-parser sink.
// Доверенный HTML требует отдельной корректной политики и обработки.
```

ShowText создаёт DOM-узел и записывает данные как текст, поэтому HTML-разбор для этой задачи вообще не нужен. Если продукт действительно принимает HTML, требуется отдельная политика обработки. CSP и Trusted Types помогают ограничивать опасные пути, но не исправляют заведомо небезопасную policy автоматически.

### Типичная ошибка

> Создать Trusted Types policy, возвращающую входную строку как есть, и назвать это санитаризацией.
