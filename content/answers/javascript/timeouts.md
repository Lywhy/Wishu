**`setTimeout`(callback, delay) регистрирует однократный callback и сразу возвращает идентификатор таймера.**

<!-- wishu:answer-block -->

### Как это работает

В браузере это числовой ID для `clearTimeout`; в Node.js возвращается объект Timeout. Callback запускается позже отдельной задачей, когда истекла задержка и среда может выполнить её.

Задержка не означает точный момент: занятый поток, фоновые ограничения и состояние страницы могут отложить вызов, а закрытие страницы - не дать ему состояться. В браузере после более чем пяти уровней вложенности таймеров действует минимум 4 мс.

Даже delay: 0 не прерывает текущий стек. Следует передавать функцию, а не строку кода.

### Пример и его разбор

```javascript
const timerId = setTimeout(() => {
  console.log("позже")
}, 1000)
clearTimeout(timerId) // отмена до выполнения callback
// Измерять точное время по указанным 1000 мс нельзя.
```

В примере callback зарегистрирован на будущее, но `clearTimeout` успевает отменить его до запуска. Возвращённый timerId служит для управления регистрацией, а не является `Promise` результата. Даже без отмены число 1000 описывало бы задержку планирования с ограничениями среды, поэтому по нему нельзя вычислять гарантированный момент изменения интерфейса.
