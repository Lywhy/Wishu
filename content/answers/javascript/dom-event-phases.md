**Событие сообщает о действии или изменении и передаётся обработчикам EventTarget.**

### Как это работает

В DOM путь обычно включает погружение от внешних узлов к цели, обработку на цели и, если событие поддерживает bubbles, всплытие наружу. Capture-обработчик задаётся опцией capture: true.

Не все события всплывают одинаково: контракт конкретного типа нужно знать отдельно. Фазы не равны действию браузера по умолчанию; отмена распространения и отмена этого действия - разные операции.

На границах Shadow DOM состав пути зависит и от composed. Программный `dispatchEvent` вызывает обычные обработчики синхронно.

### Пример и его разбор

```javascript
function observe(container) {
  container.addEventListener("click", () => console.log("capture"), { capture: true })
  container.addEventListener("click", () => console.log("bubble"))
}
// При клике на вложенную кнопку capture контейнера будет раньше bubble.
```

Оба обработчика подписаны на контейнер, но участвуют в разных этапах доставки. Для клика по вложенной кнопке capture контейнера выполняется до её обработчиков, а bubble после них. Этот порядок не означает, что действие браузера автоматически отменено.
