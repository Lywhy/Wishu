**В текущем описанном алгоритме перед распространением отказа вызывается `return` синхронного итератора. Это позволяет выполнить `finally` генератора. Историческое поведение старых реализаций отличалось: нельзя переносить его на все версии среды.**

### Как это работает

Ошибка при ожидании выданного value возникает в адаптере, а не как `throw` в самой точке yield. Адаптер должен корректно закрыть исходный итератор. Если `finally` сам содержит `yield`, закрытие тоже может приостановиться: произвольная очистка не обязана полностью закончиться за один return.

Для ресурсного API явно задавайте контракт завершения. Уточняйте версию runtime, если собеседование или legacy-проект опирается на прежнюю семантику.

### Пример и его разбор

```javascript
function* values() {
  try {
    yield Promise.reject(new Error("сбой"))
  } finally {
    console.log("очистка")
  }
}
async function consume() {
  try {
    for await (const value of values()) console.log(value)
  } catch {
    console.log("ошибка")
  }
}
// В текущем описанном алгоритме consume(): очистка, затем ошибка.
// Совместимость конкретного runtime проверяется отдельно.
```

Отклонённое значение обрабатывается адаптером синхронного итератора. В актуально описанном алгоритме он вызывает `return` до передачи ошибки наружу, поэтому сначала выполняется `finally`, затем catch. Для старой среды этот пример требует отдельной проверки совместимости.

### Типичная ошибка

> Утверждать, что `finally` здесь всегда пропускается, опираясь на старую документацию.
