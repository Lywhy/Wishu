**Обычный классический script без `async`/defer в ходе парсинга приостанавливает разбор HTML ради загрузки и выполнения.**

<!-- wishu:answer-block -->

### Как это работает

Для внешнего классического скрипта defer позволяет загрузку параллельно разбору и выполнение после него в порядке документа до DOMContentLoaded. `async` выполняет готовый скрипт без гарантии порядка относительно других и может прервать разбор на время выполнения.

Поэтому зависимые скрипты нельзя произвольно помечать `async`, а head сам по себе не делает скрипт плохим: важны режим и требуемый момент. Модули type="module" по умолчанию отложены; их `async` имеет собственную семантику готовности графа зависимостей.

Defer не даёт ожидаемого эффекта для обычного inline-классического скрипта. Атрибут `async` не связан с ключевым словом `async` функции.

### Пример и его разбор

```javascript
// Пример HTML-разметки, а не вызовов JavaScript:
// <script src="/dependent.js" defer></script>
// <script src="/independent.js" async></script>
// <script type="module" src="/app.js"></script>
// Порядок исполнения выбирают по зависимостям приложения.
```

В примере dependent получает defer, потому что для зависимого классического скрипта важен порядок документа. Independent может использовать `async`, если действительно не зависит от соседей. Модульный app загружается по правилам графа модулей, а не как обычный inline-скрипт.
