**AbortSignal.any объединяет источники отмены, а AbortSignal.timeout создаёт сигнал по временному условию. Поддерживающей операции передают итоговый signal и учитывают его reason.**

<!-- wishu:answer-block -->

### Как это работает

Сигнал уже мог быть отменён до старта. Причиной не обязательно является Error с одним фиксированным именем: пользовательский abort может передать другое значение. Тайм-ауты платформы также имеют свои правила активного времени.

Для собственной операции нужно реализовать проверку/подписку и освобождение listener. Сигнал сам не убивает любую функцию и не отменяет уже совершённую серверную запись.

### Пример и его разбор

```javascript
const user = new AbortController()
const signal = AbortSignal.any([user.signal, AbortSignal.timeout(5000)])
// fetch(url, { signal }) в поддерживаемой среде.
// user.abort(reason) или тайм-аут завершит составной сигнал.
```

Итоговый signal сообщает отмену от пользователя либо от временного условия, в зависимости от того, какое сработает первым. Передавая его в fetch, приложение использует встроенную поддержку операции, а не пытается отменить `Promise` извне. Причину и уже отменённое состояние проверяют по контракту API; для старых сред требуется проверка поддержки этих методов.

### Типичная ошибка

> Считать `Promise.race` с таймером реальной отменой оставшейся работы.
