**Backpressure позволяет замедлять получение данных, когда потребитель не успевает. Очереди, pull/write и обещания готовности связывают скорость этапов, а не просто собирают весь поток в память.**

<!-- wishu:answer-block -->

### Как это работает

PipeTo и pipeThrough помогают согласовать поток, ошибки и отмену по своим контрактам. Ручной цикл должен учитывать готовность записи; бесконечный список незавершённых write может разрушить нужный предел памяти.

Потоковая форма сама по себе не гарантирует ограниченную память, если приложение всё равно сохраняет каждый чанк. Отдельно определите необходимость накопления и финального результата.

### Пример и его разбор

```javascript
async function copy(readable, writable) {
  await readable.pipeTo(writable)
}
// Реальные source/sink задают ограничения и поведение ошибок.
// Это не то же самое, что прочитать весь ресурс в один массив.
```

PipeTo связывает чтение с готовностью приёмника и возвращает `Promise` завершения передачи. Если вместо этого без ограничений собирать write-промисы или чанки, скорость источника перестанет соответствовать возможностям потребителя. Потоковый API полезен только вместе с ограниченной моделью очередей.

### Типичная ошибка

> Назвать обработку потоковой, но бессрочно складывать все чанки и write-промисы в массив.
