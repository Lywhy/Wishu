**Ключ должен учитывать всё, от чего зависит результат: аргументы, нужный `this` и значимый внешний контекст. Выбор reference- или value-семантики меняет поведение кеша.**

<!-- wishu:answer-block -->

### Как это работает

`JSON.stringify`(args) не является универсальным ключом: он теряет часть значений, может вызывать пользовательский код, не поддерживает обычным способом циклы и способен объединить разные входы.

`WeakMap` полезен для объектной идентичности, но не задаёт ограничение по числу всех возможных примитивных ключей. Продумайте инвалидирование, TTL/LRU и поведение rejected `Promise`, если кешируются асинхронные результаты.

### Пример и его разбор

```javascript
const a = { id: 1 }
const b = { id: 1 }
const cache = new WeakMap()
cache.set(a, "результат для a")
console.log(cache.has(b)) // false: другой объект.
```

Запись под объектом a не доступна по объекту b, хотя их поля совпадают. `WeakMap` использует идентичность объекта, поэтому такой кеш подходит только при соответствующем контракте. Если результат зависит ещё от настроек или `this`, эти зависимости тоже должны входить в ключ либо вызывать инвалидирование, иначе можно вернуть корректный результат для другого входа.

### Типичная ошибка

> Мемоизировать нечистую функцию только по первому аргументу и получить устаревшие ответы.
