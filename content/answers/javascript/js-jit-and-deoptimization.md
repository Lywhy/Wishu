**Движок может интерпретировать код, собирать профиль, компилировать оптимизированный вариант и откатывать предположения. Поэтому время не обязано быть постоянным с первого вызова.**

### Как это работает

ECMAScript задаёт наблюдаемое поведение, а не один обязательный JIT-конвейер. Названия стадий и эвристики зависят от конкретного движка и версии.

При измерении учитывайте прогрев, представительность входа, GC и устранение неиспользуемой работы. Не переносите результат одного микро-теста на реальную страницу или все браузеры.

### Пример и его разбор

```javascript
function sum(values) {
  let total = 0
  for (const value of values) total += value
  return total
}
// Измерение должно учитывать реальные типы и объём входных данных.
```

В sum стоимость зависит не только от длины values, но и от наблюдаемых типов и решений движка после прогрева. Измерение одного холодного вызова не описывает установившуюся нагрузку. Оптимизации должны сохранять поведение для всех допустимых входов, а не только ускорять искусственный benchmark.

### Типичная ошибка

> Объявлять конструкцию быстрее во всех средах по единственному холодному запуску.
