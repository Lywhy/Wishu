**Язык поддерживает доступ к подходящим методам примитива через объектные механизмы, но это не превращает исходное значение в постоянно изменяемый объект. `null` и `undefined` не предоставляют такой же доступ.**

### Как это работает

Запись произвольного свойства примитиву не создаёт у него сохраняемое состояние; в строгом режиме соответствующая запись вызывает ошибку. `new` String создаёт уже настоящий wrapper-объект с другой идентичностью и truthy-поведением.

Не описывайте временное boxing как обязательную дорогую heap-аллокацию при каждом вызове: движок может оптимизировать реализацию при сохранении семантики.

### Пример и его разбор

```javascript
console.log("hello".toUpperCase()) // HELLO
console.log(typeof new String("")) // object
console.log(Boolean(new Boolean(false))) // true: это объект.
```

У строки доступен метод toUpperCase, но результатом становится новое строковое значение. Явное `new` String создаёт настоящий объект, а `new` Boolean(`false`) остаётся truthy, несмотря на внутреннее false. Поэтому пользоваться методами примитива и вручную создавать объектную обёртку - разные решения. Для обычных строк и логических флагов обёртки чаще не нужны.

### Типичная ошибка

> Создавать Boolean-обёртку и ожидать falsy, потому что внутри хранится false.
