**Замыкание связывает функцию с лексическим окружением, в котором она создана. Благодаря этому функция может использовать внешние переменные даже после завершения вызова, создавшего это окружение.**

### Как это работает

При обращении к имени JavaScript ищет привязку в окружении функции и далее во внешних окружениях. Возвращённая внутренняя функция сохраняет доступ к нужным привязкам: завершение внешнего вызова само по себе этот доступ не уничтожает. Важно, что сохраняется связь с переменной, а не автоматически сделанная копия её прежнего значения.

Это позволяет скрыть состояние за небольшим API. Например, фабрика счётчика возвращает функцию увеличения, а переменная `count` остаётся недоступной напрямую вызывающему коду. Несколько функций, созданных в одном вызове фабрики, могут разделять это состояние; разные вызовы создают независимые окружения.

### Пример и его разбор

```javascript
function createCounter() {
  let count = 0
  return () => ++count
}
const a = createCounter()
const b = createCounter()
a() // 1
a() // 2
b() // 1 - другое окружение
```

В примере a вызывается дважды и последовательно меняет свой `count`: результаты равны 1 и 2. Функция b создана другим вызовом `createCounter`, поэтому её первый результат равен 1. Именно независимость окружений объясняет результат, а не имя переменной `count` в исходнике.

### Нюансы и типичные ошибки

Замыкания полезны для фабрик, обработчиков и кешей. Если достижимая функция удерживает ненужный большой объект, это может продлевать его жизнь; однако само замыкание не является утечкой памяти. Особый случай общей `var`-привязки в цикле разобран отдельно.
