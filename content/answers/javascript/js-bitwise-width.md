**Большинство побитовых операций над Number работают после преобразования к 32-битному целому. Это не произвольная целочисленная арифметика и не безопасный способ округлить любое число.**

### Как это работает

Сдвиги используют ограниченный счётчик разрядов; >>> даёт беззнаковый 32-битный результат. У `BigInt` побитовые операции имеют другую модель ширины, не допускают смешивания с Number, а >>> для `BigInt` не поддерживается.

Приёмы вроде x | 0 удобны только при явно допустимом диапазоне и могут скрыть `NaN`, бесконечности или переполнение.

### Пример и его разбор

```javascript
console.log((2 ** 32) | 0) // 0
console.log(-1 >>> 0) // 4294967295
console.log(5n & 3n) // 1n
// 5n & 3 // TypeError: нельзя смешивать Number и BigInt.
```

Число 2 ** 32 выходит за 32-битную модель и после | 0 даёт ноль. Беззнаковый сдвиг представляет -1 как 4294967295. Это показывает, почему побитовый приём нельзя использовать как замену обычному округлению произвольного Number.

### Типичная ошибка

> Заменять `Math.trunc` на | 0 без проверки диапазона.
