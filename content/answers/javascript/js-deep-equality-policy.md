### Как это работает

Решите, как сравнивать `NaN` и -0, циклы, Date, `Map`/`Set`, `Symbol`-ключи, неперечисляемые свойства и разные прототипы. Обход `getter` может иметь побочный эффект. Для графа нужна стратегия учёта пар уже сравниваемых узлов.

`JSON.stringify` не является универсальным сравнением: он теряет типы, не поддерживает часть значений и может зависеть от порядка записанных ключей. Для простых DTO можно выбрать существенно более узкий контракт.

### Пример и его разбор

```javascript
const a = { value: undefined }
const b = {}
console.log(JSON.stringify(a) === JSON.stringify(b)) // true
console.log(Object.hasOwn(a, "value"), Object.hasOwn(b, "value")) // true, false
```

Объекты a и b сериализуются одинаково, поскольку `undefined` в свойстве объекта исключается из JSON. Проверка hasOwn показывает, что их состояние всё же различается. Если для приложения это различие существенно, сравнение JSON не подходит; сначала нужно определить контракт равенства и уже по нему выбирать алгоритм.

### Типичная ошибка

> Считать совпадение JSON-текста доказательством одинакового состояния любых объектов.
