**`Math.random` подходит для многих несекретных случайных действий, но не гарантирует криптографическую непредсказуемость. Для соответствующих задач платформа предоставляет crypto.getRandomValues и другие криптографические API.**

<!-- wishu:answer-block -->

### Как это работает

Выбор источника не заменяет правильный алгоритм. Остаток от деления случайного целого может давать modulo bias, если диапазон не делит пространство равномерно. Для равномерного bounded-выбора применяют подходящую rejection sampling-стратегию.

Воспроизводимые тесты обычно требуют управляемого генератора и известного seed, а не криптографической случайности. Серверное право доступа нельзя доверять случайному клиентскому решению.

### Пример и его разбор

```javascript
const bytes = new Uint8Array(16)
crypto.getRandomValues(bytes)
// Это случайные байты, а не готовая безопасная схема авторизации.
const decorationVariant = Math.floor(Math.random() * 3)
```

Случайные байты и вариант оформления имеют разные требования. Для декора достаточно `Math.random`, а секрет требует криптографического источника и корректной схемы применения. Даже хорошие случайные байты не создают автоматически безопасную авторизацию или равномерный выбор из любого диапазона.

### Типичная ошибка

> Создавать секретный токен из `Math.random` или считать любой % безусловно равномерным.
