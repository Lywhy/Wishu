**`Function`.`prototype`.`toString` возвращает текстовое представление функции. Это способ посмотреть её исходную запись, когда она доступна, но не сериализация всей функции вместе с окружением.**

### Как это работает

У пользовательской функции с доступным исходником результат сохраняет исходный синтаксис, включая комментарии и пробелы. Однако текст описывает только запись функции: он не содержит значения внешних переменных, на которые она ссылается. Поведение определяется ещё и лексическим окружением, созданным во время выполнения.

У встроенных функций и функций, полученных через bind, обычно видно представление с [native code]. Оно не раскрывает внутреннюю реализацию. Нельзя делать бизнес-логику зависимой от конкретных пробелов или точной строки такого представления.

### Пример и его разбор

```javascript
const makeAdder = (offset) => (value) => value + offset
const addTwo = makeAdder(2)
addTwo(3) // 5
addTwo.toString() // исходный текст внутренней стрелки, без значения offset
Math.max.toString() // представление встроенной функции с [native code]
```

addTwo из примера использует `offset` со значением 2 из вызова `makeAdder`. Её `toString` показывает внутреннюю стрелочную функцию, но не добавляет в строку сохранённое значение `offset`. Поэтому сохранение только этой строки не позволяет надёжно восстановить addTwo с тем же поведением.

### Нюансы и типичные ошибки

Попытка восстановить функцию через `eval` или `Function` не восстанавливает прежнее окружение и создаёт риск выполнения недоверенного кода. Для передачи данных лучше определить явный формат, а нужное поведение выбирать из заранее известных операций.
