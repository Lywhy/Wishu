### Как это работает

`localStorage` привязан к origin и обычно переживает перезапуск браузера; `sessionStorage` дополнительно разделён по сеансу верхнеуровневой вкладки и сохраняется при её перезагрузке. Новая вкладка не является общей изменяемой сессией `sessionStorage` с исходной.

Объекты сериализуют явно, а ошибки доступа, квоты и разбора нужно обрабатывать. Данные могут быть очищены пользователем или политикой браузера; это не гарантированное бессрочное хранилище.

Storage доступен JavaScript страницы и не подходит для секретов, защищаемых от XSS. Для больших структур и асинхронных транзакций часто выбирают IndexedDB.

### Пример и его разбор

```javascript
function savePreference(value) {
  try {
    localStorage.setItem("theme", value)
    return true
  } catch {
    return false
  }
}
// sessionStorage.setItem("draft", "текст") ограничивает данные сеансом вкладки.
```

SavePreference возвращает отдельный признак успеха, поскольку доступ к хранилищу может завершиться ошибкой. Вызывающий код должен учитывать этот результат, прежде чем показывать «сохранено». Для объектов дополнительно понадобятся сериализация, обработка разбора и проверка полученной структуры.
