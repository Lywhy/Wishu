**Stack trace помогает понять цепочку вызовов, связанную с ошибкой: имена функций, файлы и позиции.**

<!-- wishu:answer-block -->

### Как это работает

Во многих движках Error.stack отражает место создания Error, а не только последующий throw. Формат свойства различается между движками и не является переносимым строковым протоколом.

Минификация усложняет чтение, поэтому source maps полезны для сопоставления исходникам. Асинхронные границы могут отображаться с дополнительной поддержкой инструментов и не выглядят как один непрерывный синхронный стек.

Для расследования нужны также сообщение, cause и контекст события без чувствительных данных.

### Пример и его разбор

```javascript
function createIssue() {
  return new Error("сбой")
}
const error = createIssue()
console.log(error.stack)
// Имена и формат строк зависят от движка; не сравнивайте весь stack как контракт.
```

Ошибка создаётся внутри createIssue, поэтому стек обычно помогает увидеть именно эту цепочку, даже если `throw` произойдёт позже. Однако формат вывода зависит от движка. Стек используют для расследования вместе с cause и сообщением, а не как стабильные данные бизнес-логики.
