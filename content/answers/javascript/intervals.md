**`setInterval` регистрирует повторные вызовы и возвращает ID, который передают clearInterval.**

### Как это работает

Реальные интервалы зависят от занятости потока и ограничений среды. JavaScript-callback одного агента не выполняются одновременно, но начатые ими асинхронные операции могут пересекаться.

Interval не ожидает `Promise` `async`-callback. Если нужно начинать следующую попытку только после завершения предыдущей, часто удобнее повторно поставить `setTimeout` после await.

При уходе со страницы или размонтировании соответствующего интерфейса интервал нужно остановить. Для анимаций обычно выбирают requestAnimationFrame.

### Пример и его разбор

```javascript
function startTicker(update) {
  const id = setInterval(update, 1000)
  return () => clearInterval(id)
}
// const stop = startTicker(update);
// stop() вызывают, когда повторная работа больше не нужна.
```

startTicker возвращает функцию остановки, замыкающую конкретный ID созданного интервала. Это связывает повторяющуюся работу с владельцем её жизненного цикла. Если update запускает запрос, следующий тик может прийти до ответа предыдущего: однопоточное выполнение callback не запрещает одновременное ожидание нескольких запросов. Для последовательного опроса планируют новую попытку после завершения старой.
