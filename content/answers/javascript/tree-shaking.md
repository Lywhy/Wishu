**Tree shaking - удаление кода, который сборщик может доказуемо исключить без изменения поведения программы. Статическая структура ES-модулей помогает определить связи импортов и используемые экспорты.**

### Как это работает

Если приложение использует один экспорт, другой не обязательно нужен в итоговом bundle. Но сборщик должен учитывать выполнение модуля и побочные эффекты: импорт может регистрировать обработчик или менять окружение, даже когда его экспорты не используются. Поэтому результат зависит от анализируемого кода, формата модулей и настроек конкретного инструмента.

Tree shaking отличается от минификации: первая оптимизация исключает ненужное, вторая компактнее записывает оставшийся код. Сжатие HTTP дополнительно уменьшает передаваемый файл. Эти этапы дополняют друг друга, но не заменяют друг друга.

### Пример и его разбор

```javascript
// helpers.js
export const double = (value) => value * 2
export const triple = (value) => value * 3
// Потребитель импортирует только double.
// Сборщик может исключить triple, если анализ доказывает безопасность.
```

В примере модуль экспортирует double и triple, а потребитель использует только double. Сборщик может исключить triple, если анализ подтверждает безопасность. Проверять это следует по production-артефакту и его содержимому, а не просто по наличию именованного import в исходнике.

### Нюансы и типичные ошибки

Описание side effects является обещанием о поведении модуля. Ошибочное обещание способно удалить необходимую инициализацию. Tree shaking также не означает автоматическое удаление любой редко вызываемой ветки.
