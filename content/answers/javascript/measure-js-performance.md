**Performance.now даёт монотонное время относительно начала временной шкалы среды и подходит для разницы длительностей.**

<!-- wishu:answer-block -->

### Как это работает

Performance.mark и measure помогают отмечать этапы в общей трассе. Для `async`-операции нужно явно решить, измеряется весь период ожидания или только синхронная работа.

Нужны повторяемые входы и несколько наблюдений, а не единственная цифра. На результат влияют прогрев, сборка мусора, другие задачи, DevTools и сниженная точность часов.

Локальный замер функции не заменяет профиль страницы и пользовательские метрики. Сам замер не должен случайно исключать важную часть работы.

### Пример и его разбор

```javascript
async function measure(operation) {
  const start = performance.now()
  const value = await operation()
  return { value, elapsedMs: performance.now() - start }
}
// Пример измеряет полное ожидание operation, а не чистое CPU-время.
```

`await` оставляет в измеряемом интервале и выполнение, и все периоды ожидания operation. Поэтому elapsedMs нельзя назвать чистым CPU-временем функции. Сначала задают смысл границ измерения, затем сравнивают несколько повторений на представительных входах.
