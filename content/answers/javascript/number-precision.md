**Number использует двоичное представление с плавающей точкой, поэтому некоторые десятичные дроби хранятся приближённо.** Ошибка округления - свойство представления, а не случайный сбой сложения.

### Как выбирать сравнение

Для приближённых вычислений задайте абсолютный и/или относительный допуск с учётом масштаба данных. `Number.EPSILON` описывает расстояние от 1 до следующего представимого числа, но не является универсальным допуском для любых величин.

Для денежных сумм часто используют целые минимальные единицы в безопасном диапазоне либо согласованную десятичную арифметику. `toFixed` возвращает строку и форматирует отображение; он не меняет представление Number.

### Пример и его разбор

```javascript
0.1 + 0.2 === 0.3 // false
function nearlyEqual(a, b, absolute = 1e-12, relative = 1e-12) {
  return Math.abs(a - b) <= Math.max(absolute, relative * Math.max(Math.abs(a), Math.abs(b)))
}
nearlyEqual(0.1 + 0.2, 0.3) // true
// Пример рассчитан на конечные числа; допуски выбирают под задачу.
```

Равенство в первой строке не выполняется из-за приближённого двоичного представления десятичных дробей. nearlyEqual вместо точного совпадения проверяет разницу с учётом абсолютного и относительного допусков. Вблизи нуля важна абсолютная часть, а при больших величинах - масштаб. Допуски являются частью задачи и не должны выбираться по одному удобному примеру.

### Типичная ошибка

> Безусловно использовать Number.EPSILON или `toFixed` для всех финансовых расчётов.
