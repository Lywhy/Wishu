### Как это работает

Асинхронная позволяет запустить работу или зарегистрировать ожидание, а результат обработать позже: например, после ответа сети, таймера или события. Неблокирующий подход позволяет продолжать другую работу, пока внешний результат ещё не готов.

Web API - возможности браузера, а не часть самого ECMAScript: сеть, таймеры и события организует среда. Готовые продолжения возвращаются к JavaScript через её планирование.

Асинхронность не гарантирует параллельный JavaScript и не делает тяжёлый синхронный расчёт дешёвым. `Promise` описывает будущий результат, но не переносит вычисление в другой поток.

### Пример и его разбор

```javascript
const order = []
order.push("начало")
setTimeout(() => order.push("таймер"), 0)
order.push("конец синхронного кода")
// Позже, после выполнения callback: начало, конец синхронного кода, таймер.
```

Регистрация таймера не выполняет его callback немедленно: программа успевает записать конец синхронного кода. Позже среда возвращает управление зарегистрированной функции. Разделение ожидания и продолжения позволяет обслуживать другие события, однако само продолжение остаётся обычным JavaScript. Поэтому асинхронное получение данных и тяжёлая обработка уже полученного массива требуют разных решений.
