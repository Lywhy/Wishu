**Запись не всегда меняет свойство в прототипе. Для обычного writable data-свойства часто создаётся собственное свойство получателя, а унаследованный `setter` выполняется с соответствующим receiver.**

<!-- wishu:answer-block -->

### Как это работает

Наследуемое data-свойство, недоступное для записи, или accessor без `setter` может запретить присваивание; строгий режим превращает соответствующий неуспех в TypeError. Правила включают расширяемость получателя и дескрипторы.

Это объясняет различие между чтением по цепочке и созданием собственного состояния. Не считайте прототип копией полей каждого экземпляра.

### Пример и его разбор

```javascript
const proto = { count: 1 }
const child = Object.create(proto)
child.count = 2
console.log(proto.count, child.count) // 1, 2
console.log(Object.hasOwn(child, "count")) // true
```

Чтение child.count сначала находит значение 1 у proto. Обычная запись создаёт собственное count у child, поэтому родитель сохраняет 1, а потомок возвращает 2. Этот результат зависит от дескриптора: унаследованный `setter` или запрет записи меняет поведение той же синтаксической конструкции.

### Типичная ошибка

> Ожидать, что child.count = 2 обязательно изменит общий proto.count.
