**Если у сериализуемого значения есть вызываемый метод `toJSON`, `JSON.stringify` сначала использует возвращаемое им представление.**

<!-- wishu:answer-block -->

### Как это работает

Метод может вернуть объект, массив, примитив или `undefined`; JSON-текст создаёт сам stringify, поэтому возвращать готовую JSON-строку обычно не нужно. `this` указывает на сериализуемый объект, аргумент key - его имя в родителе, а у корневого значения это пустая строка. Так можно явно выбрать поля для отправки или определить формат значения.

Например, Date использует `toJSON` для строкового представления даты. `JSON.parse` не восстанавливает методы, прототип класса и исходный объект автоматически.

`toJSON` меняет одну операцию сериализации и не служит общим запретом доступа к исключённым полям.

### Пример и его разбор

```javascript
const account = {
  id: 7,
  name: "Аня",
  internalNote: "для приложения",
  toJSON() {
    return { id: this.id, name: this.name }
  },
}
const text = JSON.stringify(account)
Object.keys(JSON.parse(text)) // ["id", "name"]
account.internalNote // "для приложения"
```

Сначала stringify вызывает `toJSON` и получает выбранные поля, затем сериализует уже это представление. Поэтому internalNote отсутствует в разобранном JSON, хотя остаётся доступным в исходном account. Исключение поля из транспортного формата не удаляет его из памяти и не создаёт самостоятельного ограничения доступа.
