**`WeakMap` хранит пары с ключами, которые могут быть собраны сборщиком мусора: объектами или незарегистрированными `Symbol`.**

### Как это работает

Значения могут быть любого типа. `WeakSet` хранит такие же допустимые значения без связанных данных.

Числа, строки и `Symbol.for`(...) не подходят как слабые ключи или элементы. `WeakMap` не удерживает ключ одним своим наличием записи, а `WeakSet` не удерживает элемент.

Если других путей достижимости не осталось, сборщик может освободить его, но момент не гарантируется. Это полезно для метаданных, связанных со временем жизни объекта.

`Map` и `Set`, напротив, удерживают свои записи обычными сильными связями. У слабых коллекций нет size и стандартного перечисления элементов: проверять можно конкретный известный ключ или элемент через has.

`WeakMap` даёт `Set`/get/delete, `WeakSet` - add/delete; это не полный заменитель `Map`/`Set`, если нужен обход или подсчёт. Слово weak не означает, что все произвольные значения `WeakMap` тоже хранятся как слабые ссылки.

### Пример и его разбор

```javascript
const object = {}
const metadata = new WeakMap()
metadata.set(object, { visited: true })
metadata.get(object).visited // true
const visited = new WeakSet()
visited.add(object)
visited.has(object) // true
visited.delete(object) // true
// Этот пример не предполагает запуск сборщика мусора.
```

Пока object доступен программе, метаданные можно получить по известной ссылке и проверить его присутствие в WeakSet. Возможность сборки проявляется только после исчезновения других путей достижимости и не задаёт точного времени очистки. Поэтому пример не наблюдает GC и не пытается перечислить слабую коллекцию: её контракт не предоставляет такого снимка.
