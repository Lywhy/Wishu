**`EventSource` предназначен для потока серверных событий к браузеру поверх соответствующего HTTP-формата. Он не является двусторонней WebSocket-сессией, хотя клиент может отдельно отправлять обычные запросы.**

<!-- wishu:answer-block -->

### Как это работает

У API есть механизм переподключения и event ID, но это не гарантирует exactly-once бизнес-доставку. Сервер и клиент должны согласовать восстановление, дубли и актуальность состояния.

Нативная настройка заголовков отличается от fetch, а credentials и ограничения соединений зависят от контекста. Закрывайте `EventSource` при завершении его владельца.

### Пример и его разбор

```javascript
const source = new EventSource("/events")
source.addEventListener("message", (event) => {
  // event.data разбирается согласно согласованной схеме.
})
// Когда подписка больше не нужна:
source.close()
```

Подписка получает серверные message, а close завершает её время жизни. Даже при автоматическом переподключении приложение должно понимать идентификаторы и возможные повторы. Для отправки действий клиента используют отдельные запросы либо выбирают двусторонний протокол.

### Типичная ошибка

> Считать автоматическое переподключение гарантией отсутствия пропусков или дубликатов.
