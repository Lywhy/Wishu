JSON.parse проверяет синтаксис JSON, но не бизнес-контракт. После разбора нужно проверить форму данных, типы полей и допустимые значения.

<!-- wishu:answer-block -->

JSON может содержать null, число, массив или объект с неверными полями. Ни TypeScript-утверждение типа, ни успешный HTTP-статус не доказывают корректность структуры во время выполнения.

Проверяйте данные при входе в систему: API, хранилище браузера, файл импорта. Для сложных контрактов используйте библиотеку runtime-валидации. Ошибку разбора и нарушение контракта полезно различать в диагностике; пользователю показывайте понятное сообщение без утечки приватных данных.

### Что проверить
Невалидный JSON; null; отсутствие поля; неверный тип; граничное числовое значение; корректный объект с дополнительными полями согласно принятой политике.
