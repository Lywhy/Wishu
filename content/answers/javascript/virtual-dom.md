**Virtual DOM - распространённая модель представления интерфейса в данных, которую библиотека сравнивает с предыдущим результатом перед изменением реального DOM.**

<!-- wishu:answer-block -->

### Как это работает

В React этап render вычисляет описание, а commit применяет нужные изменения. Это помогает декларативно связывать интерфейс с состоянием.

Сравнение и создание описаний сами стоят времени и памяти, поэтому гарантии «быстрее любого прямого DOM» нет. Важны структура компонентов, объём списка, идентичность элементов и реальные обновления.

Virtual DOM отличается от Shadow DOM: первое относится к организации обновлений библиотеки, второе - к границам браузерного дерева и стилей.

### Пример и его разбор

```javascript
// Декларативное описание вместо ручной последовательности DOM-операций:
const view = { type: "p", props: { children: "Привет" } }
// Это учебная модель данных, а не внутренний формат React и не реализация reconciler.
```

Объект view только иллюстрирует описание желаемого интерфейса данными. Применение изменений требует отдельного механизма библиотеки и имеет собственную стоимость. Польза декларативной модели не даёт автоматической гарантии меньшего времени выполнения любого сценария.
