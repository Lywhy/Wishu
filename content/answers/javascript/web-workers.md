**Dedicated Worker выполняет скрипт в отдельном агенте и может параллельно считать данные, не занимая JavaScript главного потока.**

### Как это работает

У него нет window и доступа к дереву DOM страницы: интерфейс меняет главный поток по полученному результату. Доступны многие API для сети и обработки данных.

Worker и страница обмениваются сообщениями через postMessage и message. Данные обычно структурированно клонируются; передача transferable, например `ArrayBuffer`, перемещает владение и отделяет буфер отправителя.

Создание Worker и обмен имеют стоимость, поэтому он полезен для подходящей тяжёлой работы, а не каждого мелкого вызова. Когда работа больше не нужна, Worker можно завершить.

### Пример и его разбор

```javascript
// Страница: модуль worker.js должен существовать отдельно.
const worker = new Worker(new URL("./worker.js", import.meta.url), { type: "module" })
worker.addEventListener("message", (event) => console.log(event.data))
worker.postMessage([1, 2, 3])
// worker.js: self.onmessage = ({ data }) => self.postMessage(data.reduce((a, b) => a + b, 0));
// worker.terminate() вызывают при завершении использования.
```

Страница отправляет массив отдельному агенту, который вычисляет сумму и возвращает сообщение. Передача не делает worker.js частью DOM: интерфейс остаётся обязанностью страницы. В примере файл должен реально существовать отдельно. При проектировании следует учитывать не только стоимость расчёта, но и клонирование данных, сопоставление ответов и завершение Worker после использования.
