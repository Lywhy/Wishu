Храните выполняющийся `Promise` по нормализованному ключу запроса. Одновременные потребители получают общую операцию; после завершения запись удаляется.

### Как это работает

Такой кеш устраняет дубли **во время выполнения**, но не заменяет кеш готовых данных с TTL и инвалидированием. В ключ должны входить параметры, влияющие на ответ, включая пользователя или область доступа.

Ошибку нельзя навсегда оставить в кеше. Отмена одного потребителя не должна неожиданно отменять запрос для остальных: определите общую политику владения.

Инвалидирование должно учитывать устаревший результат, иначе старый запрос может перезаписать новые данные.

В примере `finally` является частью возвращаемой цепочки, поэтому не создаёт отдельный проигнорированный отклонённый промис.

### Пример и его разбор

```javascript
const pending = new Map()
function loadOnce(key, request) {
  if (pending.has(key)) return pending.get(key)
  const promise = Promise.resolve()
    .then(request)
    .finally(() => {
      if (pending.get(key) === promise) pending.delete(key)
    })
  pending.set(key, promise)
  return promise
}
```

Pending получает `Promise` до фактического вызова request в продолжении, поэтому несколько потребителей успевают найти одну запись. `finally` удаляет её только если она всё ещё относится к тому же Promise. Такая проверка не даёт старой операции стереть более новую запись. После завершения следующий вызов снова запускает работу: это объединение ожиданий, а не долговременный кеш результата.

### Типичная ошибка

> Кешировать только по URL при разных пользователях или оставлять отклонённый `Promise` навсегда.
