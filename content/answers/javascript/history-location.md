**Location описывает текущий URL; assign или присваивание href инициирует навигацию, replace заменяет текущую запись истории.**

### Что важно объяснить

- History позволяет двигаться назад и вперёд и управлять записями через pushState и replaceState без загрузки нового документа.

- PushState не обновляет интерфейс сам и не вызывает popstate немедленно: приложение должно отрисовать новый маршрут.

- Popstate обрабатывает переходы по истории.

- URL для pushState ограничен тем же origin, а сервер SPA должен уметь отдавать страницу при прямом открытии маршрута.

- Эти API не заменяют проверку допустимого адреса навигации.

<!-- wishu:answer-block -->

### История не является маршрутизатором

`pushState` и `replaceState` сами не вызывают `popstate`; обработчик приложения должен обновить интерфейс при своей навигации. `popstate` связан с перемещением по истории, а новый URL для pushState ограничен тем же origin. Вызов history API не загружает новый документ автоматически. История и роутер должны согласованно восстанавливать состояние при Back/Forward.

[Документация](https://developer.mozilla.org/en-US/docs/Web/API/History_API/Working_with_the_History_API).
