**Debounce откладывает действие до паузы после серии вызовов: новый вызов перезапускает ожидание.**

<!-- wishu:answer-block -->

### Как это работает

Это удобно для поиска после ввода. Throttle ограничивает темп выполнения во время непрерывного потока, например для реакции на прокрутку.

Поведение на первом и последнем вызове зависит от выбранных leading/trailing опций. Нужно определить сохранение `this` и последних аргументов, отмену ожидающего вызова и момент очистки.

Debounce не отменяет уже начатый запрос: для него может потребоваться `AbortSignal` или защита от устаревшего ответа. Ни один приём не делает тяжёлый обработчик неблокирующим.

### Как проверить своё решение

Уточните leading и trailing до реализации. Проверьте аргументы и `this`, вызов на границе интервала, независимость двух обёрток, отмену при наличии cancel и возврат результата. Для debounce добавьте серию быстрых вызовов: выполнить нужно именно последний набор аргументов. Управляемые часы делают проверки воспроизводимыми без реального ожидания.

### Пример и его разбор

```javascript
// Простой trailing debounce, не полная библиотечная реализация.
function debounce(fn, delay) {
  let timer
  function wrapped(...args) {
    clearTimeout(timer)
    timer = setTimeout(() => fn.apply(this, args), delay)
  }
  wrapped.cancel = () => clearTimeout(timer)
  return wrapped
}
// wrapped.cancel() вызывают при завершении жизненного цикла.
```

Каждый вызов wrapped отменяет предыдущее ожидание и запоминает последние аргументы в новом callback таймера. Поэтому действие произойдёт после паузы, а не регулярно во время непрерывного потока. Метод cancel прекращает ещё не выполненный вызов. Однако уже начавшийся запрос этим не отменяется, и тяжёлая fn по-прежнему может блокировать главный поток.
