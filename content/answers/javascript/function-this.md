**У обычной функции `this` зависит от способа вызова; у стрелочной он берётся из внешнего лексического окружения.** Место объявления обычной функции само по себе не задаёт её `this`.

### Способы вызова

| Вызов                      | `this`                                           |
| -------------------------- | ------------------------------------------------ |
| `object.method()`          | `object`                                         |
| `fn()` в strict mode       | `undefined`                                      |
| `fn.call(value)` / `apply` | Явно переданное значение                         |
| Bound-функция              | Значение, зафиксированное `bind`                 |
| `new Constructor()`        | Создаваемый объект, с учётом правил конструктора |

### Где обычно ошибаются

`const fn = object.method; fn()` - уже отдельный вызов, а не вызов через объект. `call`, `apply` и `bind` не заменяют лексический `this` стрелочной функции.

Правило обычного вызова без strict mode отличается; ES-модули и тела классов уже строгие.

### Строгость вызываемой функции

При `call(3)` строгая обычная функция получает число `3`, а нестрогая оборачивает примитив в объект; `null` и `undefined` у нестрогой функции заменяются глобальным объектом её среды. Это определяется режимом самой функции, а не только режимом вызывающего кода. Стрелка не выполняет такую подстановку: собственного `this` у неё нет.

### Пример и его разбор

```javascript
"use strict"
const user = {
  name: "Анна",
  read() {
    return this?.name
  },
}
user.read() // "Анна"
const detached = user.read
detached() // undefined
detached.call(user) // "Анна"
```

После извлечения user.read в detached теряется форма вызова через объект, поэтому строгая функция получает `undefined` как this. В примере optional chaining делает это наблюдение безопасным и тоже возвращает `undefined` вместо ошибки доступа к name. Вызов через `call` явно передаёт user и восстанавливает ожидаемое чтение. `this` следует анализировать по конкретному вызову.

### Типичная ошибка

> Определять `this` по расположению функции в исходном файле вместо места вызова.
