**Beforeunload может запросить браузерное предупреждение при несохранённых изменениях.**

<!-- wishu:answer-block -->

### Как это работает

Современные браузеры требуют пользовательское взаимодействие и не показывают произвольный текст приложения. Подписку стоит держать только пока предупреждение действительно нужно.

Unload устарел и ненадёжен, особенно при мобильном завершении приложения; beforeunload тоже не гарантируется. Они могут мешать использованию back/forward cache.

Данные лучше сохранять по мере работы, а visibilitychange и pagehide использовать как дополнительные сигналы. SendBeacon подходит для небольшого завершающего сообщения, но не превращает уход со страницы в надёжную транзакцию.

### Возврат из back-forward cache

При восстановлении документа из bfcache выполнение продолжается в сохранённой странице: повторной загрузки документа может не быть. Событие `pageshow` и его `persisted` помогают отличить восстановление. `visibilitychange` полезно для сохранения состояния, но ни `unload`, ни отправка beacon не дают абсолютной гарантии, что сервер получил последние данные. Критические изменения сохраняют по мере работы.

### Пример и его разбор

```javascript
function warnUnsaved(event) {
  event.preventDefault()
  event.returnValue = "" // совместимость со старыми реализациями
}
// Добавляют только при наличии несохранённых изменений:
// window.addEventListener("beforeunload", warnUnsaved);
// После сохранения: window.removeEventListener("beforeunload", warnUnsaved);
```

Обработчик предупреждает о несохранённых изменениях, но не сохраняет их сам. Его подключают только на период такого риска и снимают после записи. Основное сохранение нужно выполнять во время работы, поскольку завершение вкладки не гарантирует доставку заключительного события.
