**Callback hell - ситуация, когда последовательность зависимых операций оформляется глубоко вложенными callback.**

<!-- wishu:answer-block -->

### Как это работает

Поток данных, обработка ошибок и завершение операции становятся трудными для чтения. Проблема связана с организацией управления, а не с самим существованием callback.

Помогают именованные функции, выделение самостоятельных шагов и единый контракт ошибок. Если API возвращает `Promise` или корректно преобразован в него, цепочка `then` либо `async`/`await` делает последовательность явной.

Независимые операции можно запускать параллельно через `Promise.all`, а зависимые нужно ожидать последовательно. `await` не превращает произвольный callback API в `Promise` API автоматически.

### Пример и его разбор

```javascript
// Здесь оба сервиса уже возвращают Promise.
async function loadDashboard(userId, services) {
  const user = await services.loadUser(userId)
  const orders = await services.loadOrders(user.id)
  return { user, orders }
}
// Ошибки передаются отклонением возвращаемого Promise.
```

loadOrders зависит от user.id, поэтому два `await` в примере намеренно последовательны. Такая запись делает зависимость видимой и сохраняет единый `Promise` с результатом или ошибкой. Простое удаление `await` ради параллельности нарушило бы контракт. Сначала выделяют зависимые шаги и путь ошибок, а затем выбирают форму callback, цепочки или `async`/await.
