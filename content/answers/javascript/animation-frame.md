**`requestAnimationFrame` запрашивает однократный callback перед подходящим обновлением отображения.**

<!-- wishu:answer-block -->

### Как это работает

Для продолжения анимации запрашивают следующий кадр. Частота зависит от экрана, состояния вкладки и браузера, поэтому жёсткая модель «каждые 16 мс» неверна.

Callback получает временную метку, позволяющую вычислять изменение по прошедшему времени, а не по количеству кадров. В фоне вызовы часто приостанавливаются.

`cancelAnimationFrame` отменяет ожидающий запрос, но не прерывает уже выполняемый callback. Тяжёлая работа внутри кадра всё ещё ухудшает отзывчивость.

### Пример и его разбор

```javascript
function scheduleVisualUpdate(update) {
  const id = requestAnimationFrame((timestamp) => update(timestamp))
  return () => cancelAnimationFrame(id)
}
// Для непрерывной анимации следующий кадр запрашивают явно.
```

Возвращённая очистка отменяет ожидающий кадр, а update получает временную метку для расчёта состояния. Один вызов `requestAnimationFrame` планирует один callback. Для движения на разных экранах прогресс считают по времени, а не прибавляют фиксированное расстояние на каждый кадр.
