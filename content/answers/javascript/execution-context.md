**Execution context - абстрактная модель текущего выполнения кода в спецификации, а не доступный из JavaScript обычный объект.**

<!-- wishu:answer-block -->

### Как это работает

Она связывает исполняемый код с функцией или модулем, Realm и лексическим/переменным окружением; `this` определяется через соответствующие правила и записи окружения. Вызов функции создаёт контекст, который становится текущим; при возврате выполнение продолжается в предыдущем.

Контексты организуются стеком, но детали его физического хранения зависят от движка. Замыкание может удерживать окружение после возврата, а генератор - приостанавливать и возобновлять выполнение.

Контекст выполнения не нужно смешивать со значением this.

### Пример и его разбор

```javascript
function outer(value) {
  return function inner() {
    return value
  }
}
const read = outer(42)
read() // 42: окружение value доступно после возврата outer
// Это иллюстрация окружения, а не способ прочитать внутренний execution context.
```

После возврата outer её обычное выполнение закончено, но inner продолжает читать value из сохранённого окружения. Это объясняет замыкание без предположения, что весь вызов outer всё ещё лежит на активном стеке. Модель контекста и время жизни окружения связаны, но не тождественны.
