**Замыкание сохраняет доступ к привязке переменной, а не снимок её значения.**

### Как это работает

В цикле с var все созданные функции обращаются к одной переменной. Если вызвать их после завершения цикла, они прочитают её окончательное значение.

В заголовке обычного for с let создаётся новая привязка счётчика для каждой итерации, поэтому функции сохраняют разные значения. Альтернатива - передать текущее значение в отдельный вызов функции, создающий собственный параметр.

Это правило областей видимости, а не особенность таймеров: ошибка воспроизводится и без асинхронного кода. Та же причина действует в for с var и `setTimeout`: поздние callback обычно читают одну уже изменившуюся привязку после завершения цикла.

Таймер не сохраняет значение счётчика автоматически; let в заголовке цикла или отдельный параметр вызова создаёт нужную независимую привязку.

### Пример и его разбор

```javascript
const shared = []
for (var i = 0; i < 3; i += 1) shared.push(() => i)
shared.map((read) => read()) // [3, 3, 3]

const separate = []
for (let j = 0; j < 3; j += 1) separate.push(() => j)
separate.map((read) => read()) // [0, 1, 2]
```

Функции из shared вызываются после завершения цикла и читают одну общую i, уже равную 3. В separate каждая функция связана со своей итерационной привязкой j, поэтому получается последовательность 0, 1, 2. Таймеры для воспроизведения не нужны: причина находится в области переменных, а не в особом поведении асинхронности.
