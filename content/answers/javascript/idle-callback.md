**RequestIdleCallback планирует невысокоприоритетную работу на свободное время главного потока.**

<!-- wishu:answer-block -->

### Что важно объяснить

- Deadline.timeRemaining сообщает доступный бюджет, didTimeout - запуск по истечении заданного timeout.

- Большую работу нужно дробить и прекращать, когда бюджет исчерпан.

- Поддержка API не универсальна, поэтому нужен выбор по возможностям и подходящий fallback.

- Без timeout важная работа может долго не начаться; при срабатывании timeout свободного времени всё равно может не быть.

- Callback не выполняется в другом потоке.

- Для необходимых визуальных изменений лучше согласовать работу через requestAnimationFrame.
