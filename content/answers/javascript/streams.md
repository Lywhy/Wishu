**ReadableStream выдаёт последовательность чанков, WritableStream принимает их.**

### Как это работает

Это позволяет обрабатывать данные постепенно, не собирая весь результат в памяти. Reader или writer получает блокировку потока на время работы; read возвращает `Promise` с value и done, write сообщает о завершении записи чанка.

PipeTo связывает чтение и запись с обработкой backpressure, ошибок и завершения по своему контракту. Отмена чтения, abort записи и освобождение блокировки - разные действия.

Для ручной записи важно ожидать write, чтобы не создавать неограниченную очередь. Fetch response.body - один из примеров читаемого потока.

### Пример и его разбор

```javascript
async function transfer(readable, writable) {
  await readable.pipeTo(writable)
}
// Ошибку transfer(...) обрабатывает вызывающий код.
// Само pipeTo по умолчанию управляет передачей и закрытием назначения.
```

PipeTo связывает источник и назначение, чтобы очередная порция передавалась с учётом готовности приёмника. Ожидание его `Promise` охватывает всю передачу, а не один чанк. Ошибка должна быть обработана вызывающим кодом. Если заменить это бесконечным чтением в массив, сам факт наличия Stream уже не сохранит ограниченную память.
