**`queueMicrotask`(callback) ставит короткий callback в очередь микрозадач.**

<!-- wishu:answer-block -->

### Как это работает

Он выполнится после текущего синхронного кода на подходящей контрольной точке, раньше перехода к следующей задаче. Это удобно для согласованного отложенного завершения текущего шага, но не для длительных вычислений.

В отличие от `Promise.resolve`().then(callback), метод не создаёт возвращаемый `Promise`: результат `queueMicrotask` - `undefined`. Исключение callback сообщается как обычная необработанная ошибка, а исключение обработчика `then` отклоняет созданный им Promise.

Постоянное добавление микрозадач может задержать таймеры и рендеринг.

### Пример и его разбор

```javascript
const order = []
queueMicrotask(() => order.push("микрозадача"))
order.push("синхронно")
// После контрольной точки: ["синхронно", "микрозадача"].
```

Синхронная запись появляется в order сразу, а отложенная - на контрольной точке микрозадач. Это позволяет завершить текущую операцию перед коротким продолжением, не ожидая очередного таймера. Но непрерывное добавление таких продолжений не даёт браузеру перейти к другим задачам. Поэтому `queueMicrotask` не используют как способ разделить длительное вычисление для отзывчивого UI.
