**Директива "use strict" в начале скрипта или тела обычной функции включает строгий режим для этого кода.**

<!-- wishu:answer-block -->

### Как это работает

Он превращает некоторые молчаливые неудачи в ошибки: например, присваивание необъявленному имени вызывает ReferenceError, а запись в неизменяемое свойство - TypeError. При отдельном вызове строгой обычной функции `this` остаётся `undefined`.

ES-модули и тела классов уже выполняются в строгом режиме. Это не статическая проверка типов и не гарантия безопасности приложения.

Директиву нельзя размещать внутри функции с rest, параметрами по умолчанию или деструктуризацией: получится SyntaxError; строгий режим для такой функции можно унаследовать от модуля или внешнего строгого кода.

### Пример и его разбор

```javascript
function readThis() {
  "use strict"
  return this
}
readThis() // undefined
readThis.call(null) // null
// В ES-модуле строгий режим уже включён без директивы.
```

Строгая readThis не подставляет глобальный объект вместо отсутствующего получателя, поэтому обычный вызов даёт undefined. Через `call`(`null`) она получает именно null. Это свойство самой вызываемой функции, а не случайная настройка вызывающего кода. Для ES-модулей строгий режим уже действует, но он не превращает JavaScript в статически типизированный язык.
