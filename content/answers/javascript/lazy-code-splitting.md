**Code splitting делит код на части, которые могут загружаться отдельно.**

### Как это работает

Lazy loading откладывает загрузку или инициализацию до необходимости: открытия маршрута, диалога или приближения изображения к viewport. Разбиение само по себе не означает, что все чанки загружаются лениво.

Dynamic import часто задаёт границу ленивой загрузки модуля, а атрибут loading="lazy" применим к некоторым ресурсам HTML. Нужно продумать состояние ожидания и отказа, стоимость первого открытия и кеширование.

Слишком мелкие чанки или задержка критического ресурса могут ухудшить результат вместо ускорения.

### Пример и его разбор

```javascript
async function openEditor(renderEditor) {
  const { createEditor } = await import("./editor.js")
  renderEditor(createEditor())
}
// Нужны реальный editor.js, состояние загрузки и обработка ошибки.
```

Модуль editor запрашивается только при вызове openEditor, что откладывает его загрузку до потребности. Сборщик при этом должен поддержать соответствующее разбиение. Первое открытие может потребовать ожидания, поэтому интерфейсу нужны состояние загрузки и понятная обработка отказа.
