**Модуль обычно вычисляется один раз для своей идентичности в соответствующем графе/среде. Разные записи, разрешающиеся к одному модулю, разделяют его состояние; другой URL может означать другую инстанцию.**

<!-- wishu:answer-block -->

### Как это работает

Query-части и правила host имеют значение. Нельзя безоговорочно обещать один экземпляр на весь процесс, все Worker и все iframe: у них разные контексты и загрузчики.

Dynamic import возвращает пространство имён, а повторный вызов экспортированной функции всё равно выполняет её тело. Не путайте кеш модуля с кешем результатов функций или HTTP-кешем ресурса.

### Пример и его разбор

```javascript
// state.js
let count = 0
export const next = () => ++count
// Два импортёра одной module identity разделяют count.
// Это не обещает общую переменную между независимыми Worker.
```

Экспорт next замыкает одно состояние count для конкретной инстанции модуля. Два импортёра той же идентичности наблюдают последовательные изменения. Независимый Worker имеет собственное окружение, поэтому модульный singleton не заменяет протокол обмена состоянием между контекстами.

### Типичная ошибка

> Использовать модульный singleton как автоматическое общее состояние всех браузерных контекстов.
