**Длительная задача главного потока задерживает ввод и отображение.**

### Как это работает

Работу делят на ограниченные порции, после которых управление возвращается планировщику. Длительность свыше 50 мс обычно относят к long task, но комфортный бюджет взаимодействия может требовать меньших порций.

`await` `Promise.resolve` только добавляет продолжение в микрозадачи и не гарантирует переход к рендерингу или вводу. Отложенная задача, например через таймер, создаёт возможность для другой работы; браузер всё ещё выбирает порядок.

Размер порции подбирают измерением, учитывают отмену и изменение данных. Независимое CPU-вычисление может быть лучше перенести в Worker.

### Пример и его разбор

```javascript
async function processChunks(items, handle) {
  for (let start = 0; start < items.length; start += 100) {
    const end = Math.min(start + 100, items.length)
    for (let index = start; index < end; index += 1) handle(items[index])
    if (end < items.length) await new Promise((resolve) => setTimeout(resolve, 0))
  }
}
// Размер 100 условный: дорогой handle требует другой порции.
```

После каждой порции пример создаёт новую задачу через таймер. В отличие от бесконечной цепочки микрозадач, это даёт планировщику возможность выполнить другую работу. Число 100 не является универсальным бюджетом: его выбирают по стоимости handle и требованиям отзывчивости.
