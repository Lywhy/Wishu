**В DevTools сравнивают состояние памяти до и после повторяемых действий: открыть и закрыть экран, добавить и убрать компонент.**

### Как это работает

Heap snapshots помогают увидеть оставшиеся объекты и пути удержания, allocation-профиль - места выделений. Важен устойчивый рост после освобождения сценария, а не любой краткий пик.

Нужно искать владельца ссылки: detached DOM, listener, кеш или замыкание. Сама консоль и сохранённые отладочные ссылки могут удерживать исследуемые объекты.

Сравнивать полезно одинаковые сценарии в похожих условиях; один снимок без истории редко объясняет причину. Принудительная сборка в инструменте не является доступным приложению общим контрактом.

### Пример и его разбор

```javascript
// Сценарий ручного исследования в DevTools:
// 1. Снимок исходного состояния.
// 2. Несколько открытий и закрытий одного экрана.
// 3. Сравнение снимков и поиск retaining path у оставшихся объектов.
// Это инструкция для анализа, а не запущенный замер проекта.
```

Повторное открытие и закрытие одного экрана создаёт сравнимую нагрузку. Если число оставшихся объектов растёт, retaining path помогает найти конкретного владельца ссылки. Одна большая куча без такого сценария ещё не доказывает утечку.
