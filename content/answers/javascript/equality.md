**Строгое равенство === сравнивает значения без преобразования их типов. Нестрогое == следует отдельному алгоритму и в некоторых сочетаниях типов сначала выполняет преобразование.**

### Как это работает

Поэтому сравнение числа со строкой может дать разные результаты: === сразу различает их типы, а == может перейти к числовому сравнению. Это не означает, что == просто вызывает Number для обоих аргументов: у `null` и `undefined`, объектов и других сочетаний есть собственные правила.

Для объектов оба оператора проверяют идентичность, если сравниваются два объекта. Два отдельно созданных объекта не равны лишь потому, что их свойства совпадают. Для примитивов также важны числовые исключения: `NaN` не равен себе, а положительный и отрицательный ноль строго равны.

### Пример и его разбор

```javascript
console.log(0 === "0") // false
console.log(0 == "0") // true
const first = { value: 1 }
const second = first
console.log(first === second) // true
console.log(first === { value: 1 }) // false
```

В примере проследите, где сравниваются разные типы, а где две ссылки на один объект. Если нужно сравнение содержимого, следует отдельно определить его правила: какие поля учитывать, как обрабатывать вложенность, даты и циклы. Замена === на == эту задачу не решает.

### Нюансы и типичные ошибки

Обычно выбирают ===, чтобы не зависеть от неявных преобразований. Проверку `value` == `null` иногда намеренно используют для `null` и `undefined`; в браузере у document.all есть историческое исключение. `Object.is` и `SameValueZero` рассматриваются в отдельном вопросе.
