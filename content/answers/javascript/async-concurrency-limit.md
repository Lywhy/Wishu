**Ограничение параллелизма задаёт число одновременно начатых, но ещё не завершённых операций.** `Promise.all(items.map(fn))` сам не ограничивает запуски: `Map` уже вызывает fn для всех элементов.

<!-- wishu:answer-block -->

### Идея пула

1. Создать не больше limit обработчиков.
2. Каждый берёт следующий индекс, запускает операцию и ожидает её.
3. Сохранять результат по исходному индексу, если важен порядок.
4. После завершения всех обработчиков вернуть массив результатов.

### Политика ошибок

Пример отклоняется при ошибке одного обработчика. Уже запущенные операции сами не отменяются; для полной политики отмены нужен отдельный контракт с `AbortSignal` или сбор ошибок.

### Критерии корректной реализации

Функции операций передаются до запуска; готовые `Promise` уже нельзя ограничить задним числом. Число активных операций не превышает limit, а свободные слоты используются.

Порядок результатов отделён от порядка завершения. Политика ошибки задана явно: остановка очереди или сбор всех результатов. Уже начатые операции требуют обработки поздних отклонений.

Проверьте пустую очередь, limit = 1, limit больше длины массива, обратный порядок завершения, синхронный `throw` и rejected Promise.

### Пример и его разбор

```javascript
async function mapLimit(items, limit, fn) {
  if (!Number.isInteger(limit) || limit < 1) throw new RangeError("limit >= 1")
  const results = new Array(items.length)
  let next = 0
  async function worker() {
    while (next < items.length) {
      const index = next++
      results[index] = await fn(items[index], index)
    }
  }
  await Promise.all(Array.from({ length: Math.min(limit, items.length) }, worker))
  return results
}
```

Переменная next выдаёт свободный индекс каждому обработчику до его `await`, поэтому одна позиция не берётся дважды в обычном агенте. Каждый worker ожидает текущую fn и лишь затем берёт следующую. Результаты записываются по индексу входа, независимо от порядка завершения. При ошибке показанная реализация не обещает отменить другие worker или уже начатые операции.

### Типичная ошибка

> Заворачивать уже запущенные `Promise` в группы и считать, что это ограничивает начало работы.
