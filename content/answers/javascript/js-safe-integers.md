Безопасное целое Number лежит в диапазоне от -(2 ** 53 - 1) до 2 ** 53 - 1. За ним не все соседние целые различимы в формате Number.

<!-- wishu:answer-block -->

### Как это работает

Проблема касается не только последнего арифметического действия: точность может быть потеряна ещё при чтении литерала или JSON. Позднее преобразование Number в `BigInt` уже не восстановит исходные цифры.

Передавайте большие идентификаторы строками или создавайте `BigInt` из точного строкового представления. Для денег отдельно определите масштаб и правила округления: один `BigInt` без модели единиц не решает все десятичные задачи.

### Пример и его разбор

```javascript
const max = Number.MAX_SAFE_INTEGER
console.log(max + 1 === max + 2) // true
console.log(Number.isSafeInteger(max)) // true
const exact = BigInt("9007199254740993")
```

За безопасной границей соседние математические целые могут представляться одним Number, поэтому два разных сложения дают равный результат. `BigInt` создаётся из строки, сохраняя исходные цифры. Если сначала разобрать их в неточный Number, последующее преобразование уже не восстановит потерянную информацию.

### Типичная ошибка

> Создать неточный Number и надеяться исправить его через `BigInt`(number).
