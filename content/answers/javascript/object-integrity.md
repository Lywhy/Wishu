**`Object.preventExtensions` запрещает добавлять новые собственные свойства, но существующие можно изменять или удалять, если позволяют их дескрипторы. `Object.seal` дополнительно делает существующие собственные свойства неконфигурируемыми: их нельзя удалить или перенастроить, но writable data-свойства ещё можно изменять.**

### Как это работает

`Object.freeze` дополнительно делает data-свойства недоступными для записи. Все три метода меняют сам объект и возвращают его; повторно разрешить расширение нельзя. `Object.isExtensible`, `Object.isSealed` и `Object.isFrozen` позволяют проверить состояние.

При запрещённых присваиваниях строгий режим вызывает TypeError, тогда как нестрогий может молча проигнорировать запись. Ограничения поверхностные: вложенные объекты автоматически не замораживаются.

`getter` замороженного объекта может возвращать изменяющиеся данные, а `setter` остаётся вызываемым; freeze не превращает объект в чистое неизменяемое значение и не блокирует всякое внутреннее состояние встроенных коллекций.

### Пример и его разбор

```javascript
const config = { count: 1, nested: { enabled: true } }
Object.preventExtensions(config)
Object.isExtensible(config) // false
config.count = 2 // пока разрешено
Object.seal(config)
Object.isSealed(config) // true
Object.freeze(config)
Object.isFrozen(config) // true
config.nested.enabled = false // вложенный объект не заморожен
```

Ограничения усиливаются поэтапно: запрет расширения блокирует новые свойства, seal также запрещает удаление и перенастройку, freeze дополнительно закрывает запись в собственные data-свойства. Это поверхностные гарантии. Если поле содержит вложенный объект, изменение его содержимого остаётся отдельной операцией и не запрещается заморозкой внешнего контейнера.
