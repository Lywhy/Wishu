**Различия заметны у `NaN` и знакового нуля.** `Object.is` считает `NaN` равным `NaN`, но различает +0 и -0. SameValueZero считает равными и `NaN`, и знаковые нули.

### Сравнение алгоритмов

| Пара               | ===     | Object.is | SameValueZero |
| ------------------ | ------- | --------- | ------------- |
| `NaN`, `NaN`       | `false` | `true`    | `true`        |
| `+0`, `-0`         | `true`  | `false`   | `true`        |
| Два разных объекта | `false` | `false`   | `false`       |

### Где это встречается

`includes`, `Set` и `Map` используют семантику SameValueZero. `indexOf` использует строгое равенство, поэтому не находит NaN.

Ни один из этих алгоритмов не сравнивает содержимое разных объектов.

### Пример и его разбор

```javascript
;[NaN].includes(NaN) // true
;[NaN].indexOf(NaN) // -1
new Set([NaN, NaN, +0, -0]).size // 2
Object.is(+0, -0) // false
```

Один и тот же `NaN` находится через `includes`, но отсутствует с точки зрения `indexOf`, поскольку методы используют разные отношения равенства. `Set` объединяет оба `NaN` и оба знаковых нуля в две группы. Это правила сравнения значений, а не глубокий анализ содержимого: отдельно созданные объекты останутся разными элементами коллекции.

### Типичная ошибка

> Ожидать, что все методы коллекций используют тот же алгоритм, что ===.
