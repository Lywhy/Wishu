**ReferenceError связан с недоступной привязкой, например TDZ или необъявленным именем.**

### Как это работает

TypeError - с недопустимой для значения операцией, RangeError - с недопустимым диапазоном. SyntaxError описывает ошибку синтаксического разбора, URIError - некорректное кодирование или декодирование URI.

Error служит общим базовым типом, AggregateError объединяет несколько причин, например в `Promise.any`. EvalError существует как стандартный тип, но не означает, что любой сбой eval будет именно им.

Лучше проверять нужный контракт и тип, чем разбирать локализуемый message как стабильный код ошибки.

### Ошибки обычной работы и ошибки очистки

`AggregateError` представляет набор ошибок, а `SuppressedError` в поддерживающей explicit resource management среде связывает сбой очистки с предшествующей ошибкой через `error` и `suppressed`. У обычного `Error` поле `cause` помогает сохранить причину при добавлении контекста. Эти формы не взаимозаменяемы; детали `using` разобраны отдельно в вопросе [об управлении ресурсами](/questions/js-using-disposal).

### Пример и его разбор

```javascript
const errors = [
  new TypeError("Нужна строка"),
  new RangeError("Значение вне диапазона"),
  new AggregateError([new Error("сбой")], "Несколько причин"),
]
errors.map((error) => error.name)
// ["TypeError", "RangeError", "AggregateError"]
```

Все три объекта примера являются ошибками, но их name показывает разный класс проблемы. AggregateError дополнительно хранит набор причин. Для программной обработки выбирают тип или отдельный согласованный code, а не полагаются на точный текст сообщения конкретного движка.
