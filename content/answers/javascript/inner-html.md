**При записи innerHTML браузер разбирает строку как HTML и заменяет дочернее содержимое элемента.**

<!-- wishu:answer-block -->

### Что важно объяснить

- При чтении возвращается сериализация его разметки.

- Старые дочерние узлы и их связи с интерфейсом заменяются, что может нарушить сохранённые ссылки и обработчики на прежних узлах.

- Недоверенные данные в такой строке могут привести к XSS, например через событийные атрибуты; отсутствие исполнения вставленного script не делает разметку безопасной.

- Для текста выбирают textContent.

- Если требуется HTML, используют проверенную очистку с подходящей политикой; Trusted Types может ограничить места вставки, но сам по себе не очищает любую строку.
