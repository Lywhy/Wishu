**При записи `innerHTML` браузер разбирает строку как HTML и заменяет дочернее содержимое элемента.**

<!-- wishu:answer-block -->

### Как это работает

При чтении возвращается сериализация его разметки. Старые дочерние узлы и их связи с интерфейсом заменяются, что может нарушить сохранённые ссылки и обработчики на прежних узлах.

Недоверенные данные в такой строке могут привести к XSS, например через событийные атрибуты; отсутствие исполнения вставленного script не делает разметку безопасной. Для текста выбирают textContent.

Если требуется HTML, используют проверенную очистку с подходящей политикой; Trusted Types может ограничить места вставки, но сам по себе не очищает любую строку.

### Пример и его разбор

```javascript
function showMessage(container, untrustedText) {
  container.textContent = untrustedText
}
// Строка с <img ...> здесь будет текстом, а не новым HTML-элементом.
```

В showMessage выбран `textContent`, поэтому даже строка с HTML-тегами отображается как данные. При замене на `innerHTML` тот же ввод стал бы разметкой и потребовал бы другого контракта безопасности. Выбор API определяется необходимостью интерпретировать HTML, а не только удобством записи.
