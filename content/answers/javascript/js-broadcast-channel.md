**`BroadcastChannel` обменивается сообщениями между подходящими контекстами с учётом origin и современных границ storage partition. Сообщения передают данные по протоколу, а не единую живую ссылку на объект.**

<!-- wishu:answer-block -->

### Как это работает

Определите версию сообщения, идентификатор операции и обработку дублей или устаревшего состояния. Новый участник не получает автоматически всю историю канала.

Закрывайте канал после использования. Наличие одного origin не позволяет игнорировать контекст partition, lifecycle вкладок и авторизацию самого приложения.

### Пример и его разбор

```javascript
const channel = new BroadcastChannel("draft-updates")
channel.onmessage = (event) => {
  /* Проверить схему event.data и актуальность. */
}
channel.postMessage({ type: "changed", id: "draft-1", revision: 2 })
// После завершения владельца: channel.close()
```

Сообщение передаёт идентификатор и ревизию, чтобы получатель мог проверить актуальность обновления. Оно не превращает объект отправителя в общую изменяемую ссылку. Для вновь открывшейся вкладки текущее состояние получают отдельно: канал сам не воспроизводит прошлую историю.

### Типичная ошибка

> Ожидать общего объекта или автоматического replay истории при открытии новой вкладки.
