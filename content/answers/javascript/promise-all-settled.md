**`Promise.all` принимает iterable значений и `Promise` и выполняется массивом результатов, когда все входы успешны.**

<!-- wishu:answer-block -->

### Как это работает

При первом наблюдаемом отклонении отклоняется общий Promise. Порядок результатов соответствует порядку входов, а не скорости завершения.

AllSettled ждёт завершения всех входов и возвращает записи со status и value либо reason. Он подходит, когда нужен полный отчёт, включая ошибки отдельных операций.

Пустой набор даёт успешный пустой массив у обоих. Эти методы не отменяют оставшуюся работу и не запускают переданные функции: операции нужно вызвать отдельно.

### Ситуация на собеседовании

На экране независимо загружаются профиль, рекомендации и статистика. Определите, можно ли показать частичный результат. Если да, соберите allSettled, отдельно обработайте status каждого элемента и покажите ошибки только соответствующих блоков. all сам по себе не отменяет оставшиеся запросы при отклонении.

**Самопроверка:** что увидит пользователь при одном отказе, при трёх отказах и при медленном ответе? Не превращается ли ошибка обязательного профиля в тихо успешный экран?

### Ошибка до создания входного набора

Аргументы вычисляются до вызова метода. В `Promise.allSettled([makeRequest()])` синхронный `throw` внутри `makeRequest` произойдёт ещё до `allSettled` и не станет записью его отчёта. Если нужно превратить такой сбой фабрики в отказ `Promise`, границу можно задать как `Promise.resolve().then(() => makeRequest())`. Это не ограничивает параллелизм и не отменяет начатые операции.

### Пример и его разбор

```javascript
async function summarize() {
  const values = await Promise.all([Promise.resolve(1), 2])
  const report = await Promise.allSettled([
    Promise.resolve("ok"),
    Promise.reject(new Error("ошибка")),
  ])
  return { values, statuses: report.map((item) => item.status) }
}
// values: [1, 2]; statuses: ["fulfilled", "rejected"].
```

Summarize получает обычный массив значений от all, но от allSettled - отдельные записи исходов. Отказ одного входа во втором случае не мешает получить отчёт по остальным. Это выбор модели экрана: обязательный общий успех либо частичная доступность блоков. Ни один агрегатор сам по себе не останавливает работу других запросов.
