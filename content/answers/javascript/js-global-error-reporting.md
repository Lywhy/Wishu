**Error-события и необработанные отклонения `Promise` имеют разные пути сообщения. Unhandledrejection относится к `Promise` без подходящей обработки на момент проверки среды, а не ко всем исключениям страницы.**

<!-- wishu:answer-block -->

### Как это работает

Причина отклонения может быть любым значением, не только Error. Ошибка обработчика события не становится автоматически rejected `Promise`, ожидаемым внешним try/catch. Позднее добавление обработчика имеет собственные последствия.

Глобальный reporter помогает диагностике, но не заменяет локальное восстановление. Ограничьте утечку приватных данных и не скрывайте проблемы одним preventDefault.

### Пример и его разбор

```javascript
window.addEventListener("unhandledrejection", (event) => {
  const reason = event.reason
  // Сформировать безопасную диагностику; не считать reason всегда Error.
})
// Владелец конкретной операции всё равно должен обработать её отказ.
```

Reporter получает reason без предположения о его типе, поскольку `Promise` может отклониться строкой или другим значением. Это последний диагностический уровень. Восстановление после конкретного отказа остаётся обязанностью кода, который начал операцию и знает её предметный контекст.

### Типичная ошибка

> Ожидать, что window.onerror перехватит и обработает любые отклонения Promise.
