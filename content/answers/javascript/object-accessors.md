**`getter` выполняется при чтении свойства, `setter` - при присваивании.**

<!-- wishu:answer-block -->

### Как это работает

Они позволяют представить вычисление или проверку значения как обычный доступ к полю: obj.value и obj.value = next. `getter` не принимает параметры, `setter` принимает один; вызывать их отдельными скобками не нужно.

Внутри accessor `this` обычно указывает на объект, через который выполняется доступ, в том числе при наследовании. Если `getter` читает то же свойство или `setter` записывает в него без отдельного хранилища, возникает рекурсия.

`getter` без `setter` не допускает обычную запись: в строгом режиме это TypeError. Чтение accessor может иметь побочные эффекты, что важно учитывать при копировании и сериализации.

### Пример и его разбор

```javascript
const user = {
  _name: "Аня",
  get name() {
    return this._name
  },
  set name(value) {
    this._name = value.trim()
  },
}
user.name = "  Оля  "
user.name // "Оля"
// _name - соглашение об имени, а не приватное поле.
```

Обращение к name выглядит как обычное чтение или присваивание, но выполняет `getter` или setter. В примере `setter` сначала нормализует строку, затем сохраняет её в отдельном поле. Префикс подчёркивания обозначает договорённость разработчиков: он сам по себе не запрещает внешнему коду менять это поле напрямую.
