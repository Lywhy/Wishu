**Если два компонента должны согласованно использовать одно значение, его владельцем делают ближайшего общего родителя.** Он передаёт значение вниз через props и предоставляет обработчики изменения.

<!-- wishu:answer-block -->

#### Как это работает

Не стоит поднимать каждое локальное поле в корень приложения. Чем ближе состояние к месту использования, тем проще его жизненный цикл и меньше область обновления. Context или внешний store полезны при реальной необходимости доступа из удалённых ветвей.

#### Пример

```tsx
function SearchPanel() {
  const [query, setQuery] = useState("")
  return (
    <>
      <SearchInput value={query} onChange={setQuery} />
      <Results query={query} />
    </>
  )
}
```

#### Разбор примера

SearchInput и Results получают один query от SearchPanel. Первый сообщает о вводе через callback, второй вычисляет представление из того же значения. Это устраняет необходимость синхронизировать две независимые копии и оставляет состояние рядом с его общей областью использования.

#### Типичная ошибка

> Оставить независимые копии выбора у соседей и пытаться синхронизировать их цепочкой эффектов.
