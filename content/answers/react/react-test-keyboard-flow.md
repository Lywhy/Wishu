**Клавиатурный тест должен пройти последовательность фокуса и действий, а затем проверить видимый результат.**

<!-- wishu:answer-block -->

#### Как это работает

UserEvent.tab и keyboard помогают моделировать путь без вызова `onClick` напрямую. jsdom не доказывает реальный layout и всю браузерную модель фокуса; критичные сценарии модалок дополнительно проверяют в браузере.

#### Пример

```jsx
await user.tab()
expect(screen.getByLabelText("Имя")).toHaveFocus()
await user.type(screen.getByLabelText("Имя"), "Анна")
await user.keyboard("{Enter}")
```

#### Разбор примера

Tab подтверждает достижимость поля, type задаёт значение, а Enter проверяет нативный путь отправки. Прямой вызов `onSubmit` обошёл бы фокус и клавиатурную связь формы. Сложное поведение модального фокуса дополнительно проверяют в браузере.

#### Типичная ошибка

Проверить только доступность кнопки мышью и пропустить невозможность дойти до неё клавиатурой.
