**Виртуализация отображает видимую часть списка и небольшой запас, имитируя общий размер прокручиваемой области.** Это уменьшает число одновременно смонтированных компонентов и DOM-узлов. Обычный overflow со скроллом сам по себе не уменьшает количество созданных элементов.

#### Как это работает

Нужно учитывать стабильные ключи, высоту элементов, фокус, поиск и доступность. Состояние строки не стоит терять при её размонтировании вне окна: важные данные хранят по ID выше. Для небольшого списка дополнительная сложность может не окупиться.

#### Что происходит вне окна

Строка может размонтироваться, поэтому её важный ввод храните по ID вне краткоживущей строки. Согласуйте прокрутку к выбранной записи, таб-навигацию и сообщения о размере списка. Наличие overflow или content-visibility не является самой виртуализацией: они не гарантируют уменьшения числа React-компонентов.

#### Пример

```tsx
// Упрощённая модель с фиксированной высотой строки; не готовая библиотека.
const visibleRows = rows.slice(start, end)
return (
  <div style={{ height: rows.length * rowHeight, position: "relative" }}>
    <div style={{ position: "absolute", top: start * rowHeight }}>
      {visibleRows.map((row) => (
        <Row key={row.id} row={row} />
      ))}
    </div>
  </div>
)
// start/end вычисляются по scroll-контейнеру; фокус и доступность требуют отдельной реализации.
```

#### Разбор примера

В примере в React попадает только срез записей видимого окна, а не весь исходный массив. Условная высота строки является важным ограничением. Для переменных размеров, фокуса и доступности лучше использовать подходящую библиотеку, сохраняя черновики вне временных строк.

#### Типичная ошибка

> Хранить единственную копию редактируемого значения внутри временной строки: после выхода из окна и remount черновик может исчезнуть.
