**В Testing Library getBy ищет элемент сразу и бросает ошибку при отсутствии, queryBy возвращает `null` при отсутствии, findBy возвращает Promise и ожидает появления.** Для исчезновения используют подходящее ожидание, а не фиксированную паузу произвольной длительности.

<!-- wishu:answer-block -->

#### Как это работает

Обновления React должны завершиться перед проверкой результата. await act из React помогает обработать связанные обновления; многие операции Testing Library уже используют его. Следует ожидать асинхронные действия и проверять содержимое после завершения, а не скрывать предупреждения act или увеличивать таймер без причины.

#### Пример

```tsx
const user = userEvent.setup()
render(<SaveForm />)
await user.click(screen.getByRole("button", { name: "Сохранить" }))
expect(await screen.findByText("Сохранено")).toBeVisible()
expect(screen.queryByRole("alert")).not.toBeInTheDocument()
// Тестовый источник отвечает успешно; matchers предоставляет тестовая настройка.
```

#### Разбор примера

GetBy проверяет немедленно доступную кнопку, findBy ожидает сообщение после действия, queryBy подтверждает отсутствие предупреждения. Каждый запрос соответствует своему времени и ожиданию. Произвольный sleep не доказывал бы завершение нужного обновления.

#### Типичная ошибка

> Не дождаться findBy/waitFor или поместить повторяющееся пользовательское действие внутрь waitFor.
