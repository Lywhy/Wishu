**ReactNode подходит для разнообразного допустимого содержимого, ReactElement - для элемента, string - для строго текстового контракта.**

<!-- wishu:answer-block -->

#### Как это работает

Тип выбирают по разрешённому использованию, а не по популярности записи. ReactNode включает пустые значения, поэтому сам по себе не гарантирует видимого ребёнка. ReactElement не доказывает наличие нужного DOM-узла после рендера.

#### Пример

```tsx
type NoticeProps = { children: React.ReactNode }
function Notice({ children }: NoticeProps) {
  return <aside>{children}</aside>
}
```

#### Разбор примера

Notice принимает и текст, и элементы, и пустое содержимое, потому что таков ReactNode. Если пустое уведомление недопустимо по требованиям, одной этой аннотации недостаточно. ReactElement сузил бы форму, но не гарантировал видимый результат вложенного компонента.

#### Типичная ошибка

Требовать ReactElement от компонента, который должен принимать обычную строку.
