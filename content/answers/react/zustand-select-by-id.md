**Selector может замкнуть текущий prop ID и вернуть только соответствующую запись из store.**

<!-- wishu:answer-block -->

#### Как это работает

Изменение другой записи не обязано менять результат, если нужный объект сохранил ссылку. Обработайте отсутствие ID после удаления. Не возвращайте новый объект-обёртку без необходимости: это меняет результат сравнения.

#### Пример

```jsx
const item = useItems((state) => state.itemsById[itemId])
return item ? <p>{item.title}</p> : <p>Запись удалена</p>
```

#### Разбор примера

Selector замыкает актуальный itemId и возвращает одну запись без дополнительной обёртки. Если меняется другая запись, а ссылка выбранной сохраняется, результат подписки остаётся прежним. После удаления выбранной записи получается undefined, поэтому предусмотрен запасной UI. Такая точечная подписка полезна при иммутабельном обновлении коллекции, а не при изменении объектов на месте.

#### Типичная ошибка

Подписаться на весь store ради одного названия и затем удивляться обновлениям от несвязанных полей.
