**Провайдер и потребитель должны ссылаться на один объект Context; два вызова createContext создают разные каналы независимо от названия.**

<!-- wishu:answer-block -->

#### Как это работает

Дублирование модуля сборщиком или разные пути импорта могут дать две копии объекта. Проверяйте единую точку объявления, зависимости и настройку bundler. Значения по умолчанию иногда скрывают такую ошибку; проверяющий хук помогает обнаружить её раньше.

#### Пример

```jsx
// contexts/theme.ts - одна общая точка объявления
export const ThemeContext = createContext(null)
// Provider и useContext импортируют этот же экспорт.
```

#### Разбор примера

Один экспорт ThemeContext используется и для передачи, и для чтения значения. Повторный createContext дал бы другой объект, даже при том же имени и default. При ошибках сборки поэтому проверяют пути импорта и дублирование зависимости.

#### Типичная ошибка

Скопировать createContext в файл потребителя, чтобы «подключить» существующий провайдер.
