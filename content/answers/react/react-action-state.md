**`useActionState` принимает action-функцию и начальное состояние, возвращает текущее состояние, функцию отправки action и isPending.** Action получает предыдущее состояние первым аргументом, затем payload; возвращённый результат становится новым состоянием.

<!-- wishu:answer-block -->

#### Как это работает

Переданная в `<form action={formAction}>` функция получает `FormData` и запускается в Action-контексте. Для ручного вызова вне action-prop требуется соответствующий Transition. `useActionState` не переносит код автоматически на сервер: серверное выполнение требует Server Function и поддерживающей инфраструктуры. Ожидаемые ошибки валидации удобно возвращать как данные.

#### Контракт результата

Ожидаемые ошибки полей удобно вернуть данными с понятной связью с контролами. Неожиданное исключение и обычный результат `{ error: ... }` - разные исходы. Состояние pending должно быть доступно и не закрывать путь восстановления после ошибки. `useActionState` координирует Actions, но не доказывает идемпотентность серверной мутации и не отменяет проверку прав. При нескольких способах вызова соблюдайте Action/Transition-контекст.

[Проверка аргументов и прав Server Actions](/questions/next-server-actions) разобрана в каноническом вопросе; `useActionState` не заменяет эту серверную границу.

#### Пример

```tsx
function NameForm() {
  const [message, formAction, pending] = useActionState(
    async (_previous, data) =>
      String(data.get("name") ?? "").trim() ? "Имя принято" : "Введите имя",
    "",
  )
  return (
    <form action={formAction}>
      <label>
        Имя
        <input name="name" />
      </label>
      <button disabled={pending}>Проверить</button>
      <p aria-live="polite">{message}</p>
    </form>
  )
}
```

#### Разбор примера

Action возвращает сообщение, которое становится новым состоянием формы. Pending блокирует повторную отправку, а `aria-live` сообщает результат. Здесь выполняется локальная проверка, а не автоматическая Server Function: серверное сохранение потребовало бы отдельной реализации.

#### Типичная ошибка

> Вызвать возвращённый dispatchAction произвольно вне Action-контекста и ожидать корректный pending; ручной запуск требует соответствующего Transition.
