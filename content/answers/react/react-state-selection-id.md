**ID связывает выбор с актуальной записью, не создавая независимую копию её полей в state.**

<!-- wishu:answer-block -->

#### Как это работает

Нужный объект вычисляют из текущей коллекции. Тогда переименование записи отражается и в панели выбора. Если выбранная запись удалена, определите fallback: снять выбор, показать недоступность или выбрать соседнюю.

#### Пример

```jsx
const [selectedId, setSelectedId] = useState(null)
const selected = rows.find((row) => row.id === selectedId) ?? null
```

#### Разбор примера

Selected вычисляется на каждом render из текущих rows. Переименование записи поэтому сразу видно в выбранной карточке. При удалении find возвращает отсутствие, и интерфейс может осмысленно снять выбор вместо показа отдельного устаревшего объекта.

#### Типичная ошибка

Хранить selectedUser целиком и забывать обновлять его после изменения коллекции users.
