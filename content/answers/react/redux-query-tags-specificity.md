**Теги описывают зависимости кеша: общий тег списка и тег конкретного ID позволяют выбрать область инвалидирования.**

<!-- wishu:answer-block -->

#### Как это работает

Изменение записи может затрагивать и её карточку, и агрегированный список. Тег не является ключом query и не объединяет сущности между endpoint. Слишком общий invalidatesTags вызывает лишние refetch, слишком узкий оставляет устаревшие данные.

#### Пример

```jsx
const configuration = {
  providesTags: (result) =>
    result
      ? [...result.map((item) => ({ type: "Post", id: item.id })), { type: "Post", id: "LIST" }]
      : [{ type: "Post", id: "LIST" }],
}
```

#### Разбор примера

Тег конкретного ID позволяет связать изменение записи с запросами, которые её предоставили. Отдельный LIST-тег удобен для изменения состава списка, например добавления нового элемента. Важно проектировать providesTags и invalidatesTags совместно: тег не является путём к объекту и не патчит его поля. Активные подходящие query обычно запрашиваются заново, а не становятся единым нормализованным графом.

#### Типичная ошибка

Инвалидировать только ID после создания записи, хотя новый элемент отсутствует в кеше списка.
