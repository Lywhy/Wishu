**Состояние рассматривается как неизменяемый снимок.** Изменение существующего объекта ломает предыдущие снимки; передача той же ссылки setter может быть пропущена по `Object.is`. Вместо мутации создают новое значение.

<!-- wishu:answer-block -->

#### Как это работает

Spread копирует только один уровень, поэтому для вложенного изменения копируется каждый объект по пути к полю. Для массива удобны map, filter и немутирующие методы. Иммутабельность нужна также для корректной работы мемоизации и отладки.

#### Пример

```tsx
setUser((user) => ({ ...user, address: { ...user.address, city: "Казань" } }))
setItems((items) => items.map((item) => (item.id === id ? { ...item, done: true } : item)))
```

#### Разбор примера

Обновление города заменяет и user, и address, сохраняя остальные ветки. Map аналогично создаёт новый объект только для выбранного item. Так предыдущие снимки остаются пригодны для сравнения и отладки, а неизменённые записи не требуют бессмысленного копирования.

#### Типичная ошибка

> Скопировать внешний объект, но изменить вложенный объект по прежней общей ссылке.
