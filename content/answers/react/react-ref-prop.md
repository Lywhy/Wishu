**В React 19 функциональный компонент может получить ref через props и передать его вложенному DOM-элементу.** Для такого кода обёртка forwardRef не нужна. В React 18 и более старом подходе функциональному компоненту для этого требовался forwardRef.

<!-- wishu:answer-block -->

#### Как это работает

Получивший ref компонент решает, какой узел или API открыть родителю. Обычный prop с произвольным названием, например inputRef, также возможен, но это другой контракт. Ref предназначен для императивных задач, а не для передачи обычных данных вместо props.

#### Пример

```tsx
function TextField({ ref, ...props }) {
  return <input {...props} ref={ref} />
}
```

#### Разбор примера

TextField принимает ref и направляет его на реальный input. Родитель сможет вызвать focus после commit, не зная внутреннего имени переменной. Такая форма предполагает React 19; совместимость со старыми версиями требует другого способа передачи ref.

#### Типичная ошибка

> Считать ref автоматически доступным DOM-потомку: пользовательский компонент должен явно передать его нужному узлу.
