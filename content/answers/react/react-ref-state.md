**`useRef` сохраняет стабильный объект current между рендерами, но изменение current не запрашивает новый рендер.** State используют для данных, от которых должен зависеть видимый UI.

<!-- wishu:answer-block -->

#### Как это работает

Ref подходит для DOM-узла, идентификатора таймера и служебного номера запроса. State подходит для отображаемого счётчика, выбранного пункта и ошибок формы. Не рассчитывайте, что ref.current в массиве зависимостей станет подпиской: изменение ref не запускает render и проверку зависимостей.

Чтение и запись ref при рендере обычно нарушают чистоту. Узкое исключение - предсказуемая инициализация, не меняющая смысл вычисления. DOM-ref назначается после commit и очищается при удалении соответствующего узла. Для динамического узла часто полезен callback ref с управлением ресурсом.

#### Пример

```jsx
const timerRef = useRef(null)
const [running, setRunning] = useState(false)
function start() {
  if (timerRef.current !== null) return
  timerRef.current = setInterval(tick, 1000)
  setRunning(true)
}
// tick - обработчик приложения; таймер также очищают при unmount.
```

#### Разбор примера

TimerRef не даёт запустить второй interval при повторном нажатии, а running отвечает за отображаемый статус. Это разные роли одного действия. При остановке и unmount нужно явно очистить ID, иначе ref лишь сохранит ссылку на продолжающий работать ресурс.

#### Типичная ошибка

Изменить ref.current и ожидать обновления текста либо читать ещё не смонтированный input в том же обработчике после setter.
