**`useReducer` полезен, когда состояние имеет несколько связанных полей, а обновления описываются событиями предметной области.** dispatch передаёт action, reducer вычисляет следующее состояние на основе предыдущего.

<!-- wishu:answer-block -->

#### Как это работает

Reducer должен быть чистым и не мутировать вход. Запросы и другие эффекты выполняются отдельно. `useReducer` сам по себе не делает состояние глобальным и не уменьшает количество рендеров автоматически; его преимущество - явные и проверяемые переходы.

#### Пример

```tsx
function reducer(state, action) {
  switch (action.type) {
    case "increment":
      return { ...state, count: state.count + 1 }
    case "reset":
      return { count: 0 }
    default:
      return state
  }
}
```

#### Разбор примера

Increment сохраняет прочие поля и меняет count, а reset намеренно задаёт новый начальный объект. Reducer описывает только переход. Если событие требует запроса, его выполнение организуют снаружи, не смешивая вычисление state с внешней командой.

#### Типичная ошибка

> Запустить побочный эффект или сгенерировать случайный ID внутри reducer вместо передачи необходимых данных через action.
