**`hydrateRoot` подключает React к уже созданному сервером HTML, связывая его с клиентским деревом и обработчиками.** Серверный и первый клиентский результат должны совпадать; для пустого клиентского контейнера используют createRoot.

<!-- wishu:answer-block -->

#### Как это работает

Различия часто вызывают случайные числа, текущая дата, зависимость от window или разных локалей в первом рендере и недопустимая вложенность HTML. Решение - одинаковые исходные данные или осмысленная граница клиентского содержимого. suppressHydrationWarning предназначен для узких неизбежных различий и не исправляет ошибочную модель рендера.

#### Первый клиентский результат

Проверяйте не только данные, но и DOM после работы HTML-парсера: неправильный p/table/button может изменить структуру до гидратации. `useId` решает подходящие связи идентификаторов, но не исправляет разный набор компонентов. Browser-only API нельзя бездумно читать в первом серверном рендере. Флаг suppressHydrationWarning - узкий escape hatch, а не стратегия синхронизации всей страницы.

#### Пример

```tsx
hydrateRoot(container, <App initialData={initialData} />)
// container уже содержит серверный результат того же App и initialData.
```

#### Разбор примера

Один и тот же `initialData` должен породить одинаковый первоначальный App на сервере и клиенте. `hydrateRoot` не является универсальным исправлением произвольной разметки. Если дерево пустое и серверного React-HTML нет, нужен другой контракт корня - createRoot.

#### Типичная ошибка

> Скрыть mismatch через suppressHydrationWarning, не исправив различие первоначального серверного и клиентского результата.
