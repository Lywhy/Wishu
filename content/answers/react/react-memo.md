**memo позволяет React пропустить рендер из-за родителя при неизменившихся props.** По умолчанию значения props сравниваются через `Object.is`; одинаковое содержимое нового объекта не даёт прежней ссылки.

### Как это работает

- Собственное state и используемый Context могут обновить компонент независимо от memo. Мемоизация не исправляет нечистый render и не является условием корректности.

- Новые объекты, массивы и функции способны нарушить сравнение. Сначала измерьте проблему и проверьте композицию, затем стабилизируйте действительно значимые зависимости.

- Пользовательский comparator должен учитывать всё, что влияет на вывод и поведение, включая функции. Иначе можно сохранить обработчик со старым замыканием.

- Сравнение тоже стоит времени; глубокое сравнение больших данных может оказаться дороже рендера. При включённом React Compiler часть ручной мемоизации может стать лишней, но это не меняет корректность модели.

### Пример

```jsx
const Price = memo(function Price({ amount }) {
  return <span>{amount}</span>
})
// amount - примитив: равное число не создаёт новую ссылку.
// Новый options={{ currency: 'RUB' }} был бы другим prop.
```

### Типичная ошибка

Вернуть true из comparator только по id, хотя callback или отображаемая сумма уже изменились.
