**`getState` читает текущий снимок, а `getInitialState` возвращает первоначальный снимок, сохранённый при создании store.**

<!-- wishu:answer-block -->

#### Как это работает

Это полезно для осмысленного reset и согласованных тестов. Не мутируйте initial-объект: иначе исходный снимок перестанет быть надёжной базой. Persisted-восстановление и текущее runtime-состояние имеют отдельный жизненный цикл.

#### Пример

```jsx
store.setState(store.getInitialState(), true)
// Сброс допустим, если initial snapshot содержит нужные actions.
```

#### Разбор примера

Текущий state может много раз измениться, но `getInitialState` предназначен для исходной базы экземпляра. Показанный reset заменяет всё состояние, поэтому начальный снимок должен включать необходимые actions. Это не копирование: если мутировать сохранённые объекты, можно испортить и базу восстановления. Persist-гидратацию и возвращение к состоянию после неё следует проектировать отдельно от обычного первоначального снимка.

#### Типичная ошибка

Сохранить `getState` после пользовательских изменений и затем называть этот объект исходным состоянием.
