**React Profiler показывает работу дерева React, а браузерный Performance позволяет увидеть JS, layout, paint, сеть и длинные задачи вместе.**

<!-- wishu:answer-block -->

#### Как это работает

Сначала воспроизведите одно медленное действие и определите доминирующую фазу. Дешёвый render не исправит огромный layout, а уменьшение сетевого waterfall не обязано снизить actualDuration. Сравнивайте повторные замеры в одинаковых условиях.

#### Пример

```jsx
<Profiler id="results" onRender={recordRender}>
  <Results />
</Profiler>
// Параллельно анализируют ту же операцию в Performance браузера.
```

#### Разбор примера

RecordRender наблюдает стоимость Results, а Performance объясняет остальное время того же действия. Если задерживает layout сторонней карты, стабилизация props списка не устранит причину. Поэтому сначала сопоставляют границы измерений, затем выбирают оптимизацию.

#### Типичная ошибка

Оптимизировать props при задержке, вызванной изображением или синхронным layout стороннего виджета.
