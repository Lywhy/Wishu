**Props делают зависимости явными и подходят для близких компонентов.** Context удобен для данных, нужных в разных ветвях, например темы или текущего пользователя. Он передаёт значение, но сам не задаёт стратегию обновлений или кеширования.

<!-- wishu:answer-block -->

- Внешний store полезен при сложных общих переходах и подписках на отдельные части данных. Серверные данные дополнительно требуют кеша, повторных запросов и инвалидирования. Выбор начинают с владельца и жизненного цикла данных, а не с помещения всего состояния в глобальное хранилище.

#### Redux Toolkit и Zustand: критерии выбора

| Потребность                                        | Что оценить                                                    |
| -------------------------------------------------- | -------------------------------------------------------------- |
| Небольшое локальное состояние                      | Начать с владельца компонента и useState/useReducer            |
| Передача значения вниз по дереву                   | Context как транспорт; сам по себе не задаёт selector-подписки |
| Внешний клиентский store с прямыми actions         | Zustand: явный жизненный цикл и узкие selectors                |
| Согласованный событийный поток и Redux-инструменты | Redux Toolkit: slices, middleware, selectors и диагностика     |
| Запросы и согласование server state                | RTK Query или другой query-кеш; не путать с локальным UI-state |

Это критерии проектного выбора, а не правило «маленький проект - одна библиотека, большой - другая». Учитывайте командные соглашения, отладку, область экземпляров и требования к server state. Обе библиотеки требуют корректной иммутабельности и подписок.
