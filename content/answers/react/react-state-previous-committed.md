**Предыдущее зафиксированное значение можно сохранить в ref после commit, если оно нужно для сравнения, а не как второй владелец текущего UI.**

<!-- wishu:answer-block -->

#### Как это работает

Запись в эффекте обновит ref для следующего рендера без дополнительного setter. Чтение ref в render может конфликтовать с современными правилами чистоты; для отображаемого предыдущего значения выбирайте явную модель state. Для решения задачи часто достаточно сохранённой предыдущей версии внутри обработчика или reducer. Не делайте универсальный usePrevious без определения момента снимка.

#### Пример

```jsx
useEffect(() => {
  const previous = previousValue.current
  if (previous !== value) reportChange(previous, value)
  previousValue.current = value
}, [value])
```

#### Разбор примера

Эффект сравнивает новое зафиксированное value с сохранённым предыдущим и лишь затем обновляет ref. Для первого запуска нужно заранее выбрать исходное значение и смысл отчёта. Если reportChange является реактивным prop, его зависимость также должна быть выражена честно.

#### Типичная ошибка

Писать previousValue.current = value в render, получая побочный эффект от незавершённой попытки.
