**Проверки хуков помогают сохранить порядок вызовов и корректные реактивные зависимости, а не только единый стиль.**

<!-- wishu:answer-block -->

#### Как это работает

Нарушение порядка связывает состояние с неправильным вызовом. Пропущенная зависимость сохраняет устаревшее замыкание. Предупреждение исправляют изменением структуры кода. Исключения вроде API use не переносят на обычные хуки.

#### Пример

```jsx
// Вместо условного вызова useEffect:
useEffect(() => {
  if (!enabled) return
  return subscribe()
}, [enabled])
```

#### Разбор примера

Вызов хука остаётся безусловным, а enabled выбирает поведение подписки внутри эффекта. Так сохраняются и порядок вызовов, и реактивность входа. Правило зависимостей не требует случайных перезапусков: оно показывает, какие данные setup действительно использует.

#### Типичная ошибка

Массово отключить правило зависимостей вместо разбора причины повторной синхронизации.
