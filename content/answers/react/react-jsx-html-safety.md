**Строка внутри `{value}` отображается как текст и не интерпретируется как HTML-разметка.** `dangerouslySetInnerHTML` явно меняет этот контракт: браузер получает HTML, доверие к которому должен обеспечить разработчик.

<!-- wishu:answer-block -->

### Как это работает

- Для комментария пользователя обычно нужен обычный текстовый вывод: строка с тегом не должна создавать элемент.

- Для доверенного форматированного HTML используйте проверенную санитизацию с разрешённым набором тегов и атрибутов. Регулярное выражение для удаления одного тега не является полноценной защитой.

- Безопасный текстовый вывод не делает безопасными все соседние контексты: отдельно проверяют URL, источники HTML и способы передачи данных скриптам. React не является универсальным санитайзером приложения.

### Пример

```jsx
function Comment({ text }) {
  return <p>{text}</p>
}
// Строка '<img src=x onerror=alert(1)>' останется текстом.
// HTML вставляют только после отдельной проверки доверия:
// <div dangerouslySetInnerHTML={{ __html: sanitizedHtml }} />
```

### Типичная ошибка

Считать любое содержимое CMS безопасным только потому, что оно получено от собственного API.
