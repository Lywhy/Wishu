**`useEffect` синхронизирует компонент с внешней системой после commit.** Он нужен для ресурса или подписки, а не как универсальное место для любого кода после рендера.

<!-- wishu:answer-block -->

### Как это работает

- Setup создаёт синхронизацию. Перед новым setup при изменившихся зависимостях React вызывает предыдущий cleanup; cleanup также выполняется при размонтировании.

- Каждому таймеру, подписке или соединению нужна соответствующая очистка. Cleanup замыкает значения своего запуска, поэтому отключает именно прежний ресурс.

- При включённых соответствующих проверках `StrictMode` в разработке может выполняться дополнительный цикл setup/cleanup. Исправляйте симметрию ресурса, а не скрывайте повторный setup флагом ref.

- Эффекты не выполняются при серверном рендеринге. Нет универсальной гарантии «всегда после paint»: для визуальной работы и блокировки показа отдельно анализируют `useLayoutEffect`.

- Производные значения вычисляют в render, действие клика выполняют в обработчике. Это уменьшает каскады рендеров и делает зависимости понятными.

### Пример

```jsx
useEffect(() => {
  const timer = setInterval(() => setSeconds((value) => value + 1), 1000)
  return () => clearInterval(timer)
}, [])
```

### Типичная ошибка

Считать [] гарантией единственного вызова за всю жизнь приложения или забыть cleanup при повторном подключении.
