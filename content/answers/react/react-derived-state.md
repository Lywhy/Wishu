**Если значение однозначно получается из текущих props или state, его обычно вычисляют при рендере.** Отдельное состояние для полной строки имени или отфильтрованного списка создаёт второй источник истины, который легко забыть обновить.

<!-- wishu:answer-block -->

#### Как это работает

Эффект, копирующий результат вычисления в state, сначала показывает старое значение и инициирует дополнительный рендер. Дорогое чистое вычисление можно мемоизировать при подтверждённой необходимости. Независимый пользовательский черновик при этом действительно может требовать собственного состояния.

#### Пример

```tsx
const fullName = firstName + " " + lastName
const visibleItems = items.filter((item) => item.title.includes(query))
```

#### Разбор примера

FullName всегда соответствует двум текущим полям, а visibleItems текущему запросу. Дополнительный setter для этих результатов потребовал бы синхронизации и мог бы отстать от исходных данных. Если фильтрация действительно дорогая, оптимизируют вычисление, а не создают второго владельца результата.

#### Типичная ошибка

> Копировать props в state и поддерживать две версии одного вычисляемого значения без самостоятельного пользовательского черновика.
