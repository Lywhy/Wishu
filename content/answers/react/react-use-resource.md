**use(promise) читает результат ресурса во время рендера.** Пока Promise ожидает, компонент приостанавливается и управление получает Suspense; при отклонении ошибка передаётся Error Boundary. В отличие от async/await, use интегрируется с повторным вычислением React.

#### Как это работает

На клиенте нельзя бездумно создавать новый некешированный Promise при каждом рендере: нужен стабильный ресурс из поддерживаемого источника. use разрешён в условиях и циклах внутри компонента или хука, но не оборачивается в try/catch. Серверные async-компоненты обычно могут использовать await напрямую.

#### Пример

```tsx
function Profile({ userPromise }) {
  const user = use(userPromise)
  return <h2>{user.name}</h2>
}
// userPromise стабильно принадлежит интеграции данных; выше размещены Suspense и Error Boundary.
```

#### Разбор примера

Profile читает переданный стабильный Promise. Pending передаёт ожидание Suspense, rejected - ошибку соответствующей границе, fulfilled - данные для name. Новый fetch при каждом вызове Profile нарушил бы владение ресурсом, даже если обернуть вычисление в JSX.

#### Типичная ошибка

> Создавать новый Promise запроса при каждом render вместо ресурса со стабильным владельцем и сроком жизни.
