**ID сущности и версия её данных имеют разную семантику: первый выбирает сеанс редактирования, вторая сообщает об обновлении того же объекта.**

<!-- wishu:answer-block -->

#### Как это работает

Key по entityId может намеренно сбросить форму при переходе к другой записи. Key по каждой версии сервера будет стирать черновик на фоновом обновлении. Если данные поменялись в том же сеансе, задайте политику конфликта: принять обновление нетронутых полей, предупредить или пересоздать по явной команде.

#### Пример

```jsx
<Editor key={document.id} initialDocument={document} />
// document.version проверяется отдельно для конфликта сохранения.
```

#### Разбор примера

Ключ document.id отличает переход к другой записи от получения новой версии той же записи. Сохранённый Editor поэтому может удерживать черновик при refetch. Решение принять `remote`-обновление или показать конфликт остаётся отдельной логикой сеанса.

#### Типичная ошибка

Использовать updatedAt как key формы и терять ввод при каждом refetch.
