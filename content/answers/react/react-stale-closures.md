**Функция захватывает значения из рендера, в котором создана.** Если таймер из эффекта с [] читает count, он продолжит читать начальный снимок. Это обычное замыкание JavaScript, проявляющееся из-за жизненного цикла React.

#### Как это работает

Если требуется обновление от предыдущего состояния, помогает функциональный updater. Если эффект должен пересинхронизироваться, нужны корректные зависимости. Ref подходит для последних данных, не определяющих представление; им не следует маскировать пропущенные реактивные зависимости.

#### Выбор исправления

Updater нужен для вычисления нового state из предыдущего. Зависимости нужны для реактивной пересинхронизации. Ref подходит служебному значению, не определяющему UI. В React 19.2+ Effect Event выделяет событие эффекта с актуальными данными; он не предназначен для сокрытия нужных зависимостей. Не выбирайте один приём для всех случаев: сначала выясните, должно ли изменение значения перезапускать внешнюю связь.

#### Пример

```tsx
useEffect(() => {
  const timer = setInterval(() => setCount((value) => value + 1), 1000)
  return () => clearInterval(timer)
}, [])
```

#### Разбор примера

Интервал не читает count из замыкания: он передаёт React правило прибавления к актуальному предыдущему значению. Если же callback должен учитывать изменяемый шаг, его нельзя просто забыть в зависимостях. Выбор исправления зависит от того, что именно должно оставаться реактивным.

#### Типичная ошибка

> Считать, что callback автоматически видит новое state, хотя он замкнул значения прежнего render.
