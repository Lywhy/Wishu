**Поверхностное объединение persisted-state может заменить вложенный объект целиком и потерять поля, добавленные в новой версии приложения.**

<!-- wishu:answer-block -->

#### Как это работает

Выберите явный merge или миграцию по схеме. Глубокий универсальный merge тоже не знает смысл массивов, удалений и несовместимых типов. Проверяйте восстановленные данные до использования и сохраняйте актуальные actions.

#### Пример

```jsx
const configuration = {
  merge: (persisted, current) => ({
    ...current,
    ...persisted,
    settings: { ...current.settings, ...persisted.settings },
  }),
  // persisted предварительно проверен и имеет ожидаемую схему.
}
```

#### Разбор примера

Если сохранено только settings.theme, простая замена settings потеряла бы новый settings.density из текущих defaults. Вложенный spread сохраняет начальные поля и поверх них накладывает проверенные сохранённые. Это пример для конкретной схемы, а не универсальный глубокий merge. Массивы, удалённые поля и недопустимые значения требуют отдельных правил, а функции действий должны остаться актуальными.

#### Типичная ошибка

Применить spread верхнего уровня и ожидать сохранения всех новых вложенных настроек.
