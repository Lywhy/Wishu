**`getByRole` с доступным именем связывает тест с тем, как пользователь находит элемент, а не с его CSS-реализацией.** Такой запрос также помогает заметить отсутствие доступного имени.

<!-- wishu:answer-block -->

#### Как это работает

У кнопки обычно есть роль button, а имя берётся из доступного содержимого или подходящего ARIA-контракта. Не у всех контролов одинаковый набор неявных ролей: например, для password полезен `getByLabelText`. Выбирайте запрос по семантике элемента.

CSS-классы могут измениться при редизайне без изменения поведения. Test id уместен как осознанный запасной контракт, когда семантический запрос не подходит.

#### Пример

```jsx
render(<button type="button">Сохранить</button>)
const button = screen.getByRole("button", { name: "Сохранить" })
await user.click(button)
// user создаётся через userEvent.setup() в тесте.
```

#### Разбор примера

Кнопка находится по роли и тексту «Сохранить», поэтому отсутствие доступного имени станет заметным. Класс оформления не участвует в контракте. Действие user.click также нужно ожидать, прежде чем проверять последующие изменения.

#### Типичная ошибка

Добавить test id ко всем элементам и перестать замечать, что видимый контрол не имеет корректного имени.
