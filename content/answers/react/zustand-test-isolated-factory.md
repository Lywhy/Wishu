#### Как это работает

React-подписки должны увидеть reset в корректной act-границе. Persist может снова восстановить старые данные из тестового storage после сброса памяти, поэтому изолируйте и хранилище, и незавершённую гидратацию. Подписки и таймеры также очищаются отдельно.

Изолированный тест проверяет поведение через публичные actions/selectors, а не приватное устройство библиотеки.

#### Пример

```jsx
const store = makeStore(testInitialState)
render(
  <StoreProvider store={store}>
    <Editor />
  </StoreProvider>,
)
// Следующий тест получает новый store и свой storage.
```

#### Разбор примера

Новый store на сценарий не наследует значения предыдущего теста, а Provider передаёт его проверяемому дереву. Для persist также нужен изолированный storage: иначе свежая память может восстановить старые сохранённые данные. React-обновления проверяют через допустимые act-границы и наблюдаемое поведение. Очистка DOM сама по себе не отменяет подписки, таймеры и асинхронную работу внешнего store.

#### Типичная ошибка

Очистить только DOM, оставив singleton-store и `localStorage` от предыдущего теста.
