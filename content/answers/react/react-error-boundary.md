**Error Boundary изолирует ошибку поддерживаемого React-вычисления в дочернем дереве и показывает fallback.** Она не является глобальным try/catch для любых событий и Promise приложения.

<!-- wishu:answer-block -->

#### Как это работает

Классическая реализация использует `getDerivedStateFromError` для состояния fallback и `componentDidCatch` для диагностики. Можно выбрать готовую границу библиотеки или маршрутизатора. Обычные исключения обработчика события, произвольного timer-callback и отдельно запущенного Promise обрабатываются в соответствующем потоке.

Граница не ловит собственную ошибку и не заменяет серверную обработку SSR. Ошибки ресурсов Suspense и поддерживаемых React Actions имеют отдельную интеграцию. Размещайте границу так, чтобы сохранялись навигация и путь восстановления. Повторная попытка требует сброса ошибки и понятного контракта повторного получения ресурса.

Логируйте диагностический контекст без лишних персональных данных. Ожидаемую ошибку валидации формы обычно показывают как состояние формы, а не аварийный fallback.

#### Пример

```jsx
class Boundary extends Component {
  state = { failed: false }
  static getDerivedStateFromError() {
    return { failed: true }
  }
  render() {
    return this.state.failed ? <p>Не удалось показать блок</p> : this.props.children
  }
}
// <Boundary><Reports /></Boundary>
```

#### Разбор примера

Boundary переключает failed при поддерживаемой ошибке потомка и сохраняет запасной UI. Её собственный render тоже может ошибиться, и тогда нужен предок выше. Ожидаемый отказ обычного async-обработчика следует обработать в самом потоке операции.

#### Типичная ошибка

Ожидать, что reject запроса в `onClick` автоматически окажется в ближайшей границе, или бесконечно повторять тот же неудачный ресурс.
