**Version отмечает версию сохраняемого формата, `migrate` преобразует старые данные при несовпадении версии.** Это не миграция PostgreSQL и не автоматическая валидация.

<!-- wishu:answer-block -->

#### Как это работает

- Определите, что делать со старым именем поля и отсутствующими значениями. Неподдерживаемый формат можно безопасно сбросить.
- Не утверждайте persistedState as NewState без проверки. Данные могли быть повреждены или изменены пользователем.
- Отдельно учитывайте merge с текущим начальным состоянием: частичная вложенная запись не обязана глубоко сохранить новые поля.

#### Пример

```text
Версия 1: { dark: true }
Версия 2: { theme: "dark" }
Миграция: проверить boolean dark и построить новое поле theme.
```

#### Разбор примера

При переходе от dark к theme нужно преобразовать смысл поля, а не просто переименовать TypeScript-тип. Миграция проверяет старую структуру, строит значение нового формата и выбирает fallback для повреждённых данных. Если версия не совпала и подходящей миграции нет, старые данные нельзя молча считать текущими. Отдельно определяют, как полученный результат объединяется с новыми начальными настройками.

#### Типичная ошибка

> Переименовать поле в коде и надеяться, что старый `localStorage` сам обновится.
