**Server Components выполняются в отдельной серверной среде, в том числе при сборке или обработке запроса, и передают результат в клиентское дерево.** Их код не требуется отправлять в браузер. Они могут обращаться к серверным данным, но не используют клиентское состояние и эффекты.

#### Как это работает

SSR формирует HTML и является отдельным механизмом: Client Components тоже могут предварительно рендериться на сервере. Директива "use client" обозначает границу клиентского графа модулей, а не обещание выполнения только в браузере. Для RSC нужна поддержка сборщика или фреймворка; обычное Vite SPA не получает её автоматически.

#### Передача через границу

Допустимость props определяется протоколом React, а не одним JSON.stringify. Подробный контракт и примеры поддерживаемых значений собраны в [вопросе о сериализации Server/Client Components](/questions/next-props-serialization). Это общая RSC-граница, используемая в том числе Next.js.

#### Пример

```tsx
// Только в поддерживающей RSC-интеграции.
async function UserPage({ id }) {
  const user = await loadUserOnServer(id)
  return <h1>{user.name}</h1>
}
// loadUserOnServer - серверный API приложения; права проверяются отдельно.
```

#### Разбор примера

UserPage читает данные в поддерживаемой RSC-среде, затем передаёт отображаемый результат. Серверная функция компонента не становится браузерным callback. Интерактивную кнопку отделяют клиентской границей, а обычный Vite SPA не получает такой механизм от async перед компонентом.

#### Типичная ошибка

> Добавить async обычному SPA-компоненту и ожидать серверного исполнения без поддержки RSC в инфраструктуре.
