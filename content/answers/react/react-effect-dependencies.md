**Без массива эффект запускается после каждого commit компонента.** С [] он не пересинхронизируется из-за изменений props или state. С массивом React сравнивает зависимости через `Object.is` и пересинхронизирует эффект при изменении хотя бы одной из них.

#### Как это работает

В массив включают все реактивные значения, прочитанные setup: props, state и функции либо переменные тела компонента. Нельзя скрывать зависимость ради редкого запуска. [] не означает гарантированный единственный вызов за жизнь приложения: повторное монтирование и проверки StrictMode запускают setup заново.

#### Меньше лишних пересозданий

Если объект настроек создаётся только для подписки, его часто можно построить внутри setup из простых реактивных значений. Независимые внешние процессы удобнее разделить на эффекты с отдельным cleanup, а не управлять несколькими связями одним большим эффектом. Не отключайте lint только ради желаемой частоты запуска: зависимость следует из чтения реактивных значений, а не выбирается как расписание.

#### Пример

```tsx
useEffect(() => {
  const connection = connect(roomId)
  return () => connection.disconnect()
}, [roomId])
// connect - стабильный API внешней интеграции.
```

#### Разбор примера

`roomId` определяет конкретную внешнюю подписку. При смене комнаты React сначала отключает соединение прежнего запуска и затем создаёт новое. Если убрать `roomId` из массива, интерфейс мог бы показывать новую комнату, продолжая получать события старой.

#### Типичная ошибка

> Убрать прочитанный prop из зависимостей ради запуска один раз: эффект продолжит синхронизировать прежний снимок.
