**`rejectWithValue` задаёт ожидаемый типизированный payload ошибки, а throw обычно попадает в сериализованное поле error lifecycle-action.**

<!-- wishu:answer-block -->

#### Как это работает

Используйте прикладной payload для ошибок валидации, не бросая наружу сырой ответ с секретами. При unwrap отказ также становится выброшенным результатом для вызывающего кода. Тип payload сам не проверяет внешний JSON; сначала нормализуйте ответ.

#### Пример

```jsx
if (!response.ok) {
  return rejectWithValue({ message: "Проверьте данные формы" })
}
return response.json()
```

#### Разбор примера

Ожидаемый отказ, например ошибки полей формы, удобно передать через `rejectWithValue` в заранее оговорённой структуре. При обычном throw `createAsyncThunk` формирует сериализованную ошибку, и payload может отсутствовать. Поэтому обработчик должен различать эти случаи. unwrap выбрасывает payload отклонённого результата либо сериализованную ошибку, но не делает непроверенный серверный JSON достоверным.

#### Типичная ошибка

Ожидать, что rejected action всегда имеет одинаковый payload независимо от способа отказа.
