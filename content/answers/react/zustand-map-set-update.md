**Map и Set изменяемы, поэтому обычное обновление Zustand должно создавать новые экземпляры коллекций.**

<!-- wishu:answer-block -->

#### Как это работает

Selectors сравнивают результаты по выбранному контракту идентичности. Мутация прежней коллекции способна оставить потребителя без ожидаемого обновления. При persist JSON требует отдельного представления Map/Set. Иммутабельное обновление и сериализация - две самостоятельные задачи.

#### Пример

```jsx
set((state) => ({
  selected: new Set(state.selected).add(id),
}))
```

#### Разбор примера

new Set копирует прежнюю коллекцию, после чего add изменяет только новую. Selector видит другую ссылку, а старый снимок остаётся неизменным. Для Map действует тот же принцип с новым Map и set/delete. Persist добавляет отдельную задачу: стандартный JSON не хранит структуру этих коллекций, поэтому требуется явное представление и обратное восстановление.

#### Типичная ошибка

Считать добавление нового ключа в прежний Map созданием нового снимка.
