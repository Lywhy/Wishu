**Несколько reducers могут независимо обработать одно событие; action не адресуется единственному slice.**

<!-- wishu:answer-block -->

#### Как это работает

Например, logout может очистить сессию, приватный кеш и локальный выбор. Это не разрешает одному reducer напрямую менять state другого. Каждая часть вычисляет свой результат из своего входа.

#### Пример

```jsx
builder.addCase(loggedOut, () => initialState)
// Другой slice также может обработать loggedOut.
```

#### Разбор примера

Событие loggedOut может очистить несколько независимых slices. Каждый обрабатывает его у себя и возвращает свою часть начального состояния; ни один не должен напрямую изменять соседний slice. Так одно доменное событие согласованно описывает переход всего store. При этом отмена запросов и очистка внешнего storage требуют отдельной обработки вне чистых reducers.

#### Типичная ошибка

Связать очистку нескольких slices цепочкой несогласованных действий без единого события намерения.
