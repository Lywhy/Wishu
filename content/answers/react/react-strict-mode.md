**StrictMode включает дополнительные проверки в разработке: React повторно вызывает чистые вычисления и выполняет дополнительный цикл setup/cleanup эффектов там, где применима эта проверка.** Это помогает обнаружить мутации и утечки подписок.

<!-- wishu:answer-block -->

#### Как это работает

Это не требование выполнять бизнес-операцию дважды в production. Если эффект создаёт дублирующиеся соединения, исправляют cleanup. Ref-флаг «уже запускали» обычно скрывает проблему, а не делает повторное монтирование безопасным.

#### Пример

```tsx
useEffect(() => {
  const connection = connect(roomId)
  return () => connection.disconnect()
}, [roomId])
// Проверка setup -> cleanup -> setup не оставляет второе соединение.
```

#### Разбор примера

Проверочная последовательность подключение, отключение, подключение оставляет одно живое соединение. При отсутствии cleanup их стало бы два. Это помогает выявить ошибку владения ресурсом в разработке, а не требует отключать StrictMode ради внешне одного вызова.

#### Типичная ошибка

> Отключить StrictMode, чтобы скрыть повторный запрос, вместо проверки cleanup и правильного места запуска операции.
