**React сохраняет локальное состояние, пока сохраняется идентичность компонента в дереве: позиция, тип и key.** Новый вызов функции при рендере сам по себе не означает новый экземпляр.

<!-- wishu:answer-block -->

### Как это работает

- Смена типа или key в позиции создаёт новое состояние. Это удобно для полного сброса формы при выборе другой сущности, но не для каждого обновления props.

- Если родитель удаляет `<Editor />` условием, Editor размонтируется. Если сам Editor возвращает null, его собственное состояние сохраняется, пока сам компонент остаётся в дереве; исчезнувшие потомки при этом размонтируются.

- Скрытие CSS не удаляет компонент. Однако эффекты и подписки продолжают жить по своему контракту; скрытие не равно специальному Activity.

- Определение функции компонента внутри другого компонента создаёт новый тип при его повторном вызове. Для черновика, который должен пережить реальное размонтирование, нужен внешний владелец или хранилище.

### Пример

```jsx
function Workspace({ documentId }) {
  return <Editor key={documentId} documentId={documentId} />
}
// Другой documentId сбросит локальное состояние Editor.
// Без смены key обновление documentId само по себе этого не обещает.
```

### Типичная ошибка

Добавить key={Date.now()} для исправления устаревшего состояния и получить постоянную потерю ввода.
