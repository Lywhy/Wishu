**Состояние связано с позицией компонента в дереве React с учётом его типа и key.** При сохранении идентичности новый рендер получает прежнее состояние. При удалении компонента или смене типа либо ключа в этой позиции состояние создаётся заново.

<!-- wishu:answer-block -->

- Изменение key полезно для полного сброса формы при выборе другой записи. Определение компонента внутри другого компонента создаёт новый тип при каждом вызове внешнего компонента и может приводить к неожиданному сбросу состояния.

<!-- wishu:answer-block -->

### Осмысленный сброс
Key по ID записи помогает начать новую форму для другой сущности, но смена key при каждом обновлении стирает ввод и DOM-состояние. Если draft должен пережить уход со страницы или размонтирование, вынесите его к владельцу с подходящим временем жизни и храните по ID. Скрытие CSS, return null и удаление компонента из дерева имеют разные последствия; не используйте случайный key как исправление любого устаревшего state.
