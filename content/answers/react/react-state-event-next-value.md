**Если следующее значение известно из события, вычислите его в локальную переменную и используйте и для setter, и для следующего действия.**

<!-- wishu:answer-block -->

#### Как это работает

Setter не меняет переменную текущего рендера. Если расчёт зависит от конкурентных предыдущих обновлений, используйте чистый updater и отдельно спроектируйте побочный эффект; не отправляйте запрос из updater.

#### Пример

```jsx
function change(event) {
  const next = event.target.value
  setQuery(next)
  reportQuery(next)
}
```

#### Разбор примера

Next читается из события один раз, затем используется и для будущего UI, и для отчёта. Поэтому reportQuery не получает прежний query из замыкания. Это решение относится к значению, уже известному из события, а не к побочным эффектам внутри updater.

#### Типичная ошибка

После setQuery(next) передавать в отчёт старый query из замыкания.
