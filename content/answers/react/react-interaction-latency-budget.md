**Полную задержку взаимодействия измеряют от пользовательского ввода до нужного видимого результата, отдельно связывая её с этапами работы.**

<!-- wishu:answer-block -->

#### Как это работает

Отметьте начало действия и наблюдаемый результат, а затем используйте React Profiler и браузерный trace для объяснения причин. Performance.measure до ближайшего rAF не всегда доказывает завершённый paint, а actualDuration не включает всю сеть и layout.

Зафиксируйте данные, устройство, режим сборки и повторения. Смотрите распределение, а не единственный удобный замер; не суммируйте перекрывающиеся вложенные метрики.

#### Пример

```jsx
performance.mark("filter:start")
// Метка результата ставится в согласованной точке измеряемого сценария.
// Далее trace объясняет JS, React, layout и paint, а не подменяет их одной цифрой.
```

#### Разбор примера

Filter:start обозначает начало сценария, но ещё не определяет его конец. Нужно выбрать наблюдаемый результат и затем связать трассу с render, layout и paint. Быстрый промежуточный callback сам по себе не доказывает, что пользователь уже увидел обновление.

#### Типичная ошибка

Назвать время сетевого запроса временем render или доказывать отзывчивость только числом commit.
