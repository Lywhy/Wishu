**Повторная загрузка должна различать начальную пустоту и обновление уже полезных данных, сохраняя понятный путь восстановления.**

<!-- wishu:answer-block -->

#### Как это работает

Можно оставить последний успешный результат и отдельно показать refresh-error. Новая попытка получает собственную идентичность запроса. Устаревший отказ не должен перезаписать успех новой попытки; кнопка retry не должна молча стирать пользовательские фильтры.

#### Пример

```jsx
const refreshing = status === "pending" && data !== null
return (
  <>
    <Results rows={data ?? []} />
    {refreshError && <Retry onClick={reload} />}
  </>
)
```

#### Разбор примера

Results сохраняет последний data, пока интерфейс отдельно показывает проблему обновления. Refreshing можно использовать для доступной индикации ожидания. Чтобы не показать ошибку старой попытки после нового успеха, результаты связывают с конкретным запросом.

#### Типичная ошибка

Сбрасывать весь экран до пустоты при каждом retry или применять позднюю ошибку прежней попытки.
