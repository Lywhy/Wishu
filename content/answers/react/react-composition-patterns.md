Children подходит для переданного содержимого, render prop - для настраиваемого представления на основе данных, хук - для повторного использования логики, а HOC оборачивает компонент и меняет его внешний контракт.

#### Как это работает

Выбирайте минимальную форму, которая выражает зависимость. Не превращайте простую вложенность в инфраструктуру cloneElement и скрытого внедрения props. Хук не делится состоянием автоматически между разными вызовами.

HOC может быть нужен при работе с существующей библиотекой, но требует аккуратного обращения с props, refs, именами и идентичностью. Не создавайте новый тип обёртки внутри рендера. Предпочтение хуков не означает, что любой render prop ошибочен.

#### Пример

```tsx
function EmptyState({ title, children }) {
  return (
    <section>
      <h2>{title}</h2>
      {children}
    </section>
  )
}
// Контейнер отвечает за рамку представления, вызывающий код - за действия.
;<EmptyState title="Ничего не найдено">
  <button>Сбросить фильтры</button>
</EmptyState>
```

#### Разбор примера

EmptyState получает готовое содержимое и не знает, как именно работает сброс фильтров. Это простая композиция представления. Если бы контейнер должен был передать в содержимое вычисленные данные, осмысленным следующим шагом мог бы стать render prop, а не скрытое клонирование детей.

#### Типичная ошибка

> Заменять любую композицию HOC либо ожидать общего состояния от двух независимых вызовов хука.
