**При перекрывающихся оптимистичных операциях один старый snapshot не подходит для отката: он может стереть более новое изменение.**

#### Как это работает

Храните подтверждённую базу и список ожидающих операций с ID, затем вычисляйте отображение применением актуальных операций. При завершении удаляйте только соответствующую операцию и учитывайте серверную версию. Для ошибок можно повторно получить канонические данные вместо рискованного обратного patch.

`useOptimistic` предоставляет модель временного отображения в Action-контракте, но идентичность операций и бизнес-порядок всё равно нужно определить.

#### Пример

```jsx
const visible = pendingOperations.reduce(applyOperation, confirmedData)
// Отказ операции A удаляет A, не возвращая состояние до более поздней B.
```

#### Разбор примера

Visible вычисляется поверх confirmedData из ещё ожидающих операций. Отказ A удаляет именно A, сохраняя более позднюю B. Обновлённая серверная база требует повторного применения актуальных операций по предметным правилам, а не возврата всего объекта к одному oldData.

#### Типичная ошибка

При падении первого запроса записать oldData поверх уже подтверждённого результата второго.
