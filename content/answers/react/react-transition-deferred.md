**`useTransition` позволяет пометить обновление как несрочное и получить isPending.** `useDeferredValue` принимает значение и даёт отстающую версию для менее срочной части интерфейса. В обоих случаях React может прервать фоновую работу ради более срочного взаимодействия.

#### Как это работает

Значение управляемого текстового input обновляют сразу; дорогой результат можно отложить. Это не debounce с фиксированной задержкой, не отмена запросов и не перенос тяжёлого синхронного кода в Worker. Для выигрыша при дорогом дочернем рендере также может требоваться мемоизация соответствующей границы.

#### Асинхронный action

StartTransition вызывает функцию сразу; помеченные обновления могут обрабатываться как несрочные. По текущему контракту обновления state после await при необходимости пометить transition оборачивают в новый startTransition. Это ограничение не следует маскировать неверными ожиданиями от pending.

Сетевые операции и тяжёлый синхронный цикл не становятся отменяемыми или выполняемыми в отдельном потоке. Сам value управляемого текстового поля обновляйте срочно; откладывать можно тяжёлую зависимую область.

#### Пример

```tsx
const [query, setQuery] = useState("")
const deferredQuery = useDeferredValue(query)
return (
  <>
    <input aria-label="Поиск" value={query} onChange={(event) => setQuery(event.target.value)} />
    <MemoizedResults query={deferredQuery} />
  </>
)
// MemoizedResults - чистая дорогая область с осмысленной memo-границей.
```

#### Разбор примера

Query обновляется сразу для контролируемого поля, а `deferredQuery` может отстать для дорогого списка. Отдельная мемоизированная граница позволяет не вычислять весь список в срочном render. Задержка определяется работой планировщика, а не фиксированными 300 миллисекундами.

#### Типичная ошибка

> Считать Transition таймером или способом ускорить любой синхронный расчёт. Он меняет приоритет обновлений, но не переносит JavaScript в другой поток.
