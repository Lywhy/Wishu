**Один экспорт созданного store обычно переиспользуется импортирующими его потребителями как один экземпляр модуля.**

<!-- wishu:answer-block -->

#### Как это работает

Вызов фабрики create/`createStore` в двух местах создаёт два хранилища. Дубликаты пакета, разные runtime-среды и SSR-запросы требуют отдельного анализа; браузерный singleton не является безопасной моделью приватного серверного состояния.

#### Пример

```jsx
export const usePreferences = create(() => ({ theme: "light" }))
// Потребители импортируют этот экспорт, а не повторяют create().
```

#### Разбор примера

Импорт готового экспорта переиспользует уже созданный экземпляр в рамках соответствующего runtime и экземпляра модуля. Одинаковый creator, вызванный дважды, не связывает данные между результатами. На сервере процесс может обслуживать разных пользователей, поэтому общий модульный store с приватными данными опасен. Граница совместного состояния должна быть выбрана явно, а не получаться случайно из расположения файла.

#### Типичная ошибка

Скопировать одинаковый creator в два файла и считать получившиеся stores общими.
