**Trigger mutation возвращает результат операции, unwrap позволяет обрабатывать успех/ошибку привычным async-потоком, а reset очищает локальное состояние результата хука.**

<!-- wishu:answer-block -->

#### Как это работает

Reset не откатывает выполненную сервером мутацию. Mutation-состояния разных экземпляров хука не следует автоматически считать общими; общий fixedCacheKey имеет отдельный контракт. После успеха согласуйте кеш через tags или целевое обновление.

#### Пример

```jsx
const [save, { reset }] = useUpdatePostMutation()
try {
  await save({ id, title }).unwrap()
} catch (error) {
  showSaveError(error)
}
// reset() убирает результат этого mutation-состояния.
```

#### Разбор примера

reset очищает состояние результата mutation-hook, например старую ошибку или признак успеха. Уже выполненное серверное изменение он не отменяет. unwrap позволяет обработать отказ вызова в try/catch; если нужен настоящий откат данных, это отдельная операция с серверным контрактом. После успешной мутации актуальность query-кеша обеспечивают теги или явное обновление.

#### Типичная ошибка

Назвать reset кнопкой отмены уже сохранённой записи.
