`flushSync` заставляет React синхронно применить обновления из callback, чтобы следующий императивный код видел обновлённый DOM. Это выход для интеграции, а не обычный способ читать новый state после setter.

<!-- wishu:answer-block -->

#### Как это работает

Сначала выясните, действительно ли внешний API требует DOM до конца текущего callback и можно ли выразить задачу обычным lifecycle. `flushSync` может ухудшать отзывчивость, выполнять связанную pending-работу и показывать fallback при приостановке.

Не вызывайте его во время render или эффекта как универсальное исправление. Для расчёта следующего значения в обработчике обычно достаточно обычной переменной и setter.

#### Пример

```tsx
import { flushSync } from "react-dom"
function appendAndScroll(setItems, listRef, item) {
  flushSync(() => setItems((items) => [...items, item]))
  listRef.current?.lastElementChild?.scrollIntoView({ block: "nearest" })
}
// Императивная интеграция; применять только при обоснованной необходимости.
```

#### Разбор примера

После `flushSync` добавленная строка уже доступна следующей DOM-команде прокрутки. Это конкретная императивная потребность, а не способ переписать снимок items в замыкании. Если задачу можно выполнить естественным lifecycle без принудительной синхронности, такой вариант обычно проще.

#### Типичная ошибка

> Оборачивать все setState во `flushSync` ради предсказуемого console.log.
