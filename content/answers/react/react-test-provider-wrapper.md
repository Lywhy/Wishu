**Тестируйте потребителя с настоящим минимальным провайдером и управляемыми начальными данными вместо глобального мока `useContext`.**

<!-- wishu:answer-block -->

#### Как это работает

Так проверяется реальный контракт подписки и границы дерева. Wrapper должен создаваться с изолированным состоянием для теста; общие singleton-stores могут переносить изменения между сценариями. Не включайте весь production App без необходимости.

#### Пример

```jsx
render(<Profile />, {
  wrapper: ({ children }) => <User.Provider value={testUser}>{children}</User.Provider>,
})
```

#### Разбор примера

Profile читает настоящий User Context от минимального wrapper. Так сохраняется механизм выбора провайдера и доступ к контролируемым данным. Для изменяемого общего store тест должен создавать собственный экземпляр, иначе сценарии могут влиять друг на друга.

#### Типичная ошибка

Замокировать все вызовы `useContext` одной заглушкой и случайно изменить несвязанные контексты.
