**Клиентский guard скрывает экран или меняет маршрут, но право читать и изменять защищённые данные проверяется на сервере.**

<!-- wishu:answer-block -->

#### Как это работает

Пользователь может вручную вызвать API, изменить URL или модифицировать клиентский state. Loader, выполняющийся в браузере, также не является доверенной серверной границей. Серверный loader требует проверки сессии и доступа к конкретной сущности.

Не передавайте приватные данные до проверки только потому, что экран потом скроется. Redirect решает навигацию, а не авторизацию ресурса.

#### Пример

```jsx
// На сервере до чтения проекта:
const user = await requireSession(request)
await requireProjectAccess(user.id, projectId)
return loadPrivateProject(projectId)
```

#### Разбор примера

RequireSession и requireProjectAccess выполняются до выдачи private project. Пользователь не получает данные только потому, что его клиент показал нужный маршрут. Сервер проверяет доступ к конкретной записи при каждом защищённом обращении.

#### Типичная ошибка

Ограничиться `<Navigate to="/login" />` и оставить незащищённый endpoint с приватными данными.
