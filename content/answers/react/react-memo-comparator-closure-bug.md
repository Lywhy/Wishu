**Comparator, игнорирующий изменившуюся функцию-prop, может оставить в ребёнке обработчик, замкнувший старые данные родителя.**

<!-- wishu:answer-block -->

#### Как это работает

Равенство id не означает равенство поведения. Если callback меняется вместе с режимом или разрешением, его нельзя исключать из сравнения без другого доказанного контракта. Глубокое сравнение также может быть дорогим и не анализирует смысл функций.

Сначала исправьте структуру props и измерьте стоимость рендера. Если custom comparator остаётся, перечислите все влияющие на вывод и поведение входы.

#### Пример

```jsx
const View = memo(
  Button,
  (before, after) => before.id === after.id && before.onClick === after.onClick,
)
// Реальный comparator также учитывает остальные значимые props.
```

#### Разбор примера

Comparator сравнивает не только id, но и `onClick`, поэтому новая функция не скрывается за совпавшей записью. Это сохраняет актуальное поведение. Если Button использует другие props, они тоже должны участвовать в корректном критерии равенства.

#### Типичная ошибка

Сравнивать только отображаемую подпись, когда callback уже должен работать с новым пользователем.
