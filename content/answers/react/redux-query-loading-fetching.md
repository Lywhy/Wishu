**IsLoading отражает первый запрос без доступных данных, а isFetching - активную загрузку, в том числе при уже показанном результате.**

<!-- wishu:answer-block -->

#### Как это работает

Это позволяет не заменять полезный список полным skeleton при refetch. Учитывайте data и currentData при смене аргумента: прежние данные и данные текущего ключа имеют разный смысл. Одного флага недостаточно для всех UX-состояний.

#### Пример

```jsx
const { data, isLoading, isFetching } = useGetPostsQuery(topic)
if (isLoading) return <Skeleton />
return <List rows={data ?? []} updating={isFetching} />
```

#### Разбор примера

При первой загрузке данных ещё нет, поэтому skeleton заменяет список. Во время повторного запроса можно оставить текущий результат и показать неблокирующий индикатор обновления. При смене аргумента data может представлять прежний доступный результат; currentData относится к текущему аргументу. Если смешивать эти понятия, интерфейс способен выдать сведения другого пользователя или раздела за актуальные.

#### Типичная ошибка

Скрывать всю страницу при каждом isFetching и терять контекст пользователя.
