Jsdom реализует значительную часть DOM API, но не полноценный визуальный браузерный layout. Проверка разметки и обработчиков не доказывает размеры, clipping, scrolling или поведение всех нативных виджетов.

#### Как это работает

Для вычисления данных и семантического поведения подходит компонентный тест, для зависимостей от геометрии и взаимодействия платформы нужен реальный браузер. Осмысленная подмена измерения проверяет вашу реакцию на заданный размер, а не реальность самого измерения.

Тест по доступной роли полезен, но не является полным accessibility-аудитом. Разделяйте проверку бизнес-логики, пользовательского пути и визуальных/платформенных ограничений.

#### Пример распределения проверок

| Проверка                               | Подходящая среда                |
| -------------------------------------- | ------------------------------- |
| Кнопка раскрывает доступное содержимое | Компонентный тест               |
| Панель не выходит за узкий viewport    | Реальный браузер                |
| Скринридер понятно объявляет ошибку    | Проверка с assistive technology |

#### Разбор примера

Таблица разделяет семантическое действие, геометрию и опыт assistive technology. Подмена прямоугольника позволяет проверить реакцию на заданный размер, но не подтверждает реальный CSS. Среда теста должна реализовывать именно проверяемую часть платформы.

#### Типичная ошибка

> Считать замоканный getBoundingClientRect доказательством правильного CSS-макета.
