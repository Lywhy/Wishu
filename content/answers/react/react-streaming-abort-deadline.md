**Потоковый SSR должен иметь политику тайм-аута и освобождения ресурсов, а abort рендера не равен произвольному откату всех серверных запросов.**

<!-- wishu:answer-block -->

#### Как это работает

`renderToPipeableStream` позволяет abort для незавершённой работы; поддерживаемые области могут получить клиентский путь завершения вместо бесконечного ожидания сервера. Управляйте отдельно HTTP-ответом, таймером, отключением клиента и отменой собственных источников данных. После отправки заголовков их статус нельзя менять как до начала ответа.

Решите, какая shell допустима и какие ошибки логируются без чувствительных данных.

#### Пример

```jsx
const stream = renderToPipeableStream(<App />, options)
const timer = setTimeout(() => stream.abort(), 8000)
// По завершении ответа очищают timer; источники данных имеют собственную отмену.
```

#### Разбор примера

Таймер ограничивает ожидание незавершённого render, вызывая abort. По окончании ответа или отключении клиента его нужно очистить, а собственные источники данных отменить отдельно. Этот механизм не возвращает назад уже выполненные серверные мутации.

#### Типичная ошибка

Оставить незавершённый render и таймер после disconnect либо ожидать отката мутаций от abort.
