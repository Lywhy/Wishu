**Push создаёт новую запись истории, а replace заменяет текущую; выбор определяет ожидаемое поведение кнопки «Назад».**

<!-- wishu:answer-block -->

#### Как это работает

Переход к новой странице обычно должен оставлять путь назад. Исправление или нормализация текущего URL может использовать replace. Частый ввод поиска не всегда должен создавать запись на каждый символ; это UX-контракт конкретного экрана.

#### Пример

```jsx
navigate("/login", { replace: true })
// Вместо добавления ещё одной записи текущая заменяется.
```

#### Разбор примера

Replace удаляет текущий шаг из ожидаемого пути возврата к нему, а не очищает всю историю. Это может быть уместно для перенаправления на login, но зависит от сценария. Универсальное применение replace к любому переходу разрушило бы полезную навигацию назад.

#### Типичная ошибка

Использовать replace везде и лишить пользователя осмысленного возврата.
