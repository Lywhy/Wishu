**Push создаёт новую запись истории, а replace заменяет текущую; выбор определяет ожидаемое поведение кнопки «Назад».**

<!-- wishu:answer-block -->

### Механизм и границы

- Переход к новой странице обычно должен оставлять путь назад. Исправление или нормализация текущего URL может использовать replace.

- Частый ввод поиска не всегда должен создавать запись на каждый символ; это UX-контракт конкретного экрана.

### Пример

```jsx
navigate("/login", { replace: true })
// Вместо добавления ещё одной записи текущая заменяется.
```

### Типичная ошибка

Использовать replace везде и лишить пользователя осмысленного возврата.
