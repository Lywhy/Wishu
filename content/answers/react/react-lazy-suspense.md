**lazy откладывает загрузку компонента, а Suspense задаёт интерфейс ожидания для поддерживаемых приостанавливаемых ресурсов.** Обычный fetch в `useEffect` сам по себе Suspense не активирует.

#### Как это работает

lazy объявляют на уровне модуля. Loader возвращает Promise модуля с default-компонентом; React кеширует загрузку и её результат. Fallback размещают вокруг области, которую пользователь воспринимает как самостоятельную. Навигацию и полезный контекст не обязательно скрывать вместе с ней.

Ошибка загрузки относится к Error Boundary, а не к бесконечному loading. Сброс границы не означает, что ранее неудачный lazy-import автоматически загрузится заново. Для данных нужна поддерживающая интеграция и стабильное владение ресурсом. Граница не делает запросы параллельными и не устраняет waterfall автоматически.

Первую приостановку до mount отличают от обновления уже показанного дерева. Transition или deferred value могут помочь сохранить полезное прежнее содержимое.

#### Пример

```jsx
const Reports = lazy(() => import("./Reports.jsx"))
function Page() {
  return (
    <Suspense fallback={<p>Загружаем отчёты…</p>}>
      <Reports />
    </Suspense>
  )
}
// Reports.jsx должен экспортировать компонент по умолчанию.
```

#### Разбор примера

Reports объявлен вне Page, поэтому не создаёт новый тип при каждом render. Suspense показывает ожидание загрузки этого ресурса, но не ловит произвольный эффектный fetch. Отказ импорта требует Error Boundary и осмысленного восстановления.

#### Типичная ошибка

Создавать lazy внутри Page при каждом рендере или считать fallback обработчиком любого async-запроса.
