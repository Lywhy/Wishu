**Каждый обработчик видит снимок state своего рендера.** Повторная запись count + 1 использует этот же снимок, а функциональные updater последовательно вычисляют значения из очереди.

<!-- wishu:answer-block -->

### Как это работает

- При count=0 три вызова setCount(count + 1) запрашивают значение 1. Три updater setCount(n => n + 1) дают 3.

- Можно смешивать замену и updater: setCount(5), затем setCount(n => n + 1) дают 6. Последующая замена снова перекроет накопленный результат.

- Updater должен быть чистым. Не отправляйте в нём аналитику и запросы; в разработке React может повторно вызвать его для проверки.

- Batching уменьшает число промежуточных обновлений, но не меняет снимок в уже выполняющемся обработчике. Современная группировка распространяется и на многие async-callback, но не обещает единственный render для любого сценария. Setter не возвращает Promise ожидания commit.

### Пример

```jsx
function increment() {
  setCount((n) => n + 1)
  setCount((n) => n + 1)
  setCount((n) => n + 1)
  // count здесь всё ещё из текущего рендера.
}
```

### Типичная ошибка

Использовать await setCount(...) как способ получить новое значение или помещать побочные эффекты в updater.
