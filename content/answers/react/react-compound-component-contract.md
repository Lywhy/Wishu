**Составной компонент разделяет общий контракт на Root и связанные части, которые получают состояние через Context.**

<!-- wishu:answer-block -->

#### Как это работает

Например, TabsRoot хранит выбранный tab, а Trigger и Panel используют согласованный ID. Части должны обнаруживать отсутствие Root и поддерживать доступную клавиатурную модель. Context не создаёт ARIA и обработчики автоматически. Для обычного продукта часто правильнее использовать готовую доступную библиотеку и расширять её контракт.

#### Пример

```jsx
<TabsRoot value={tab} onValueChange={setTab}>
  <TabsTrigger value="code">Код</TabsTrigger>
  <TabsPanel value="code">...</TabsPanel>
</TabsRoot>
```

#### Разбор примера

Trigger и Panel используют одно значение code и общий Root, поэтому могут согласованно выбирать активную вкладку. Общие имена компонентов сами эту связь не обеспечивают. Клавиатура, фокус и ARIA остаются обязанностью реализации или выбранной доступной библиотеки.

#### Типичная ошибка

Считать набор компонентов составным API только из-за одинакового префикса, не согласовав состояние и идентичность.
