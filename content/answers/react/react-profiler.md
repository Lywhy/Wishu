**Сначала воспроизводят конкретное медленное действие и измеряют его.** React DevTools Profiler и компонент Profiler показывают работу дерева React; браузерный Performance показывает также JavaScript, сеть, layout и paint. Большое число рендеров не обязательно означает заметную задержку.

#### Как это работает

После обнаружения причины выбирают адресное изменение: локализацию состояния, уменьшение дорогой работы, мемоизацию или ограничение количества элементов. Измерение повторяют на сопоставимых данных. Режим разработки и StrictMode добавляют накладные расходы; программное профилирование production требует специальной сборки.

#### Пример

```tsx
function onRender(id, phase, actualDuration) {
  console.log({ id, phase, actualDuration })
}
return (
  <Profiler id="catalog" onRender={onRender}>
    <Catalog />
  </Profiler>
)
```

#### Разбор примера

Profiler измеряет выбранное поддерево Catalog, а не весь путь от клика до готового кадра. Его данные сопоставляют с тем же действием в браузерной трассе. Только после обнаружения дорогого участка выбирают изменение и сравнивают повторные замеры.

#### Типичная ошибка

> Назвать actualDuration полным временем реакции пользователя, игнорируя сеть, браузерный layout и paint.
