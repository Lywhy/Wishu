**Фильтрацию списка, объединение строк и другие преобразования данных делают при рендере.** Отправку формы или запись покупки, вызванную нажатием, обычно выполняют в обработчике события: там известна причина действия.

<!-- wishu:answer-block -->

#### Как это работает

Эффект нужен для поддержания связи с внешней системой, например подпиской, а не для связывания каждого setState с другим setState. Удаление избыточного эффекта устраняет промежуточное устаревшее представление и облегчает работу с зависимостями.

#### Пример

```tsx
const visible = items.filter((item) => item.title.includes(query))
return <Results items={visible} />
```

#### Разбор примера

Visible вычисляется из текущих items и query в том же render. Поэтому нет промежуточного кадра со старым результатом и последующего setter. Отдельный эффект понадобился бы для внешней подписки, а не для обычной фильтрации уже доступных данных.

#### Типичная ошибка

> Хранить вычисляемый список вторым state и обновлять его эффектом, создавая промежуточный устаревший render.
