**Идентификатор отложенного действия сохраняют в setup и отменяют через clearTimeout при очистке эффекта.**

<!-- wishu:answer-block -->

#### Как это работает

Это предотвращает выполнение ещё не сработавшего таймера при смене зависимостей или unmount. Cleanup не откатывает действие, которое уже произошло; внешний API может иметь собственную отмену.

#### Пример

```jsx
useEffect(() => {
  const timer = setTimeout(() => notify(message), 3000)
  return () => clearTimeout(timer)
}, [message])
```

#### Разбор примера

Новая message завершает предыдущий запуск эффекта и отменяет его ещё не сработавший таймер. Следовательно, уведомление относится к последнему актуальному сообщению. Если notify передаётся как изменяемый prop, его также нужно включить в корректный контракт зависимостей.

#### Типичная ошибка

Оставить старый таймер при смене message и показать несколько устаревших уведомлений.
