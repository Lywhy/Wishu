**Пользовательский хук - функция с именем use..., которая может вызывать другие хуки.** Он выделяет повторяющуюся логику состояния или синхронизации и возвращает удобный интерфейс вызывающему компоненту.

#### Как это работает

Два независимых вызова хука получают независимые состояния. Общие данные появляются только при подключении к общему источнику, например Context или store. Хороший хук выражает конкретную задачу, а не скрывает произвольный callback эффекта с неясными зависимостями.

#### Контракт для потребителя

Хук должен принимать необходимые реактивные входы и сам поддерживать корректную симметрию подписки. Если возвращаемый callback используется потребителем как зависимость, стабильность его ссылки должна быть осмысленным контрактом. Не называйте useMount обёртку, которая скрывает необходимые зависимости и отключает проверку. Два вызова хука разделят состояние только при явном общем источнике, а не из-за одинакового имени функции.

#### Пример

```tsx
function useToggle(initialValue = false) {
  const [value, setValue] = useState(initialValue)
  const toggle = () => setValue((current) => !current)
  return [value, toggle]
}
```

#### Разбор примера

Каждый вызов useToggle создаёт свою ячейку value. Повторно используется правило переключения, а не единственное общее boolean-значение. Если потребителям нужна синхронность, хук должен явно подключаться к общему владельцу или получать значение и команды извне.

#### Типичная ошибка

> Ожидать общего state от двух вызовов одного custom hook. Общими становятся правила работы, а не автоматически ячейки состояния.
