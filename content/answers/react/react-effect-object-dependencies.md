**Объект, созданный в теле компонента, получает новую ссылку при каждом рендере.** Эффект сравнивает зависимости через `Object.is`, поэтому одинаковые поля не делают такой объект прежней зависимостью.

<!-- wishu:answer-block -->

#### Как это работает

Если объект нужен только эффекту, создайте его внутри setup и перечислите используемые примитивные props. Если вызываемая функция нужна только в setup, её также часто можно определить внутри эффекта. Это меняет структуру кода, а не скрывает реальную зависимость.

`useMemo` и `useCallback` могут помочь в отдельных случаях, но не должны быть первой заплаткой. Не убирайте читаемое реактивное значение из массива ради желаемой частоты запуска.

#### Пример

```jsx
useEffect(() => {
  const connection = createConnection({ serverUrl, roomId })
  connection.connect()
  return () => connection.disconnect()
}, [serverUrl, roomId])
// createConnection - внешний API; настройки создаются в setup.
```

#### Разбор примера

Объект настроек создаётся только при запуске setup из serverUrl и roomId. Повторный render с теми же значениями не добавляет новую объектную зависимость. При настоящей смене комнаты очистка закрывает прежнее соединение, сохраняя честную реактивную связь.

#### Типичная ошибка

Подавить проверку зависимостей и оставить устаревший `roomId` либо добавить `JSON.stringify` без анализа контракта.
