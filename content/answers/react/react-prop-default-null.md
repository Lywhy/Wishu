**Значение по умолчанию при деструктуризации применяется к undefined, но не к явно переданному null.**

<!-- wishu:answer-block -->

#### Как это работает

Отсутствующий prop также даёт undefined. Если null должен означать отсутствие значения, отдельно определите такой контракт. Оператор ?? обрабатывает и null, и undefined, сохраняя 0 и пустую строку; || дополнительно заменит все falsy-значения.

#### Пример

```jsx
function Badge({ count = 1 }) {
  return <span>{String(count)}</span>
}
// <Badge /> -> 1; <Badge count={null} /> -> null.
```

#### Разбор примера

String делает различие явно видимым: пропуск count приводит к «1», а null к «null». Без String пустое значение в children могло бы просто не дать текста. Если продукт хочет одинаковую обработку обоих случаев, её нужно выразить через отдельную нормализацию.

#### Типичная ошибка

Считать деструктуризацию универсальной нормализацией всех пустых значений.
