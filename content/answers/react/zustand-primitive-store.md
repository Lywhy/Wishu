**Для примитивного state обновление задаёт новое примитивное значение; методы actions тогда обычно хранят вне самого числа.**

<!-- wishu:answer-block -->

#### Как это работает

Полная замена особенно важна, когда форма state не является объектом с полями. Типизируйте публичный setter и не ожидайте merge полей числа. При необходимости данных вместе с actions удобнее объектный state.

#### Пример

```jsx
const scoreStore = createStore(() => 0)
scoreStore.setState((value) => value + 1, true)
```

#### Разбор примера

Здесь всё состояние равно числу, поэтому selector должен читать само значение, а не state.count. Updater увеличивает прежнее число, а true явно обозначает замену. Функции управления можно хранить вне такого state. Если нужны несколько полей и actions в одном контракте, объектная форма удобнее; поверхностное объединение полей не имеет смысла для числового значения.

#### Типичная ошибка

Обращаться к count-полю у store, который по контракту хранит само число.
