**Оптимистичный интерфейс показывает ожидаемый результат до ответа сервера.** useOptimistic помогает построить временное представление поверх подтверждённых данных во время Action; после завершения источником истины остаётся базовое состояние.

<!-- wishu:answer-block -->

- При успехе нужно обновить подтверждённые данные или инвалидировать их кеш. При ошибке временный результат должен исчезнуть либо получить понятный статус неуспеха. Повторные и параллельные операции требуют стабильных идентификаторов и согласования порядка. Оптимистичный подход не подходит, если действие нельзя безопасно предположить успешным.

### Проверка сценария
Сопоставляйте временную запись с подтверждённой через стабильный ID операции. Проверьте отказ, два быстрых действия, обратный порядок ответов и обновление базовых данных извне. После подтверждения временный результат не должен дублировать запись.

UseOptimistic помогает с временным представлением, но не решает произвольный конфликт серверных версий. Продумайте доступный статус pending/ошибки и сохранение пользовательского намерения при повторной попытке.
