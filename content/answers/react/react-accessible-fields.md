**Label связывают с input через `htmlFor` и id или вкладывают input в label.** Для повторяемых экземпляров компонента `useId` даёт согласованные идентификаторы, в том числе при корректном SSR. Placeholder не заменяет постоянную подпись.

#### Как это работает

Текст ошибки связывают через aria-describedby и обозначают недопустимое значение aria-invalid. Сообщение должно объяснять исправление; при отправке можно переводить фокус на ошибочное поле. `useId` не предназначен для key списка: ключ берут из идентичности данных.

#### `useId` не является ключом данных

`useId` подходит для связанных id внутри переиспользуемого компонента. Он не заменяет ключ записи в списке, ID серверной сущности и случайный идентификатор бизнес-операции. При SSR дерево и параметры корней должны быть согласованы; для нескольких независимых корней учитывают identifierPrefix. Не выносите `useId` внутрь цикла: выделите компонент строки или поля.

#### Пример

```tsx
function EmailField({ error }) {
  const id = useId()
  return (
    <>
      <label htmlFor={id}>Email</label>
      <input
        id={id}
        type="email"
        aria-invalid={Boolean(error)}
        aria-describedby={error ? id + "-error" : undefined}
      />
      {error && <p id={id + "-error"}>{error}</p>}
    </>
  )
}
```

#### Разбор примера

Один `useId` связывает label и input, а производный идентификатор подключает текст ошибки только при её наличии. Так сообщение относится к конкретному полю даже при нескольких экземплярах. Эти идентификаторы не описывают идентичность записей списка.

#### Типичная ошибка

> Показать красную подпись без программной связи с полем: зрячий пользователь увидит ошибку, но вспомогательная технология может её не связать с вводом.
