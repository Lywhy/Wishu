**Проверьте не только появление fallback, но и способ восстановления, который действительно обновляет ошибочный ресурс или состояние границы.**

<!-- wishu:answer-block -->

### Механизм и границы

- Тестовый потомок может бросить ошибку при выбранном prop; затем выполните предусмотренную кнопку retry или смену идентичности.

- Ожидаемая диагностика теста не должна маскировать все будущие console.error. Rejected lazy-ресурс может требовать отдельной политики повторного получения.

### Пример

```jsx
render(
  <Boundary>
    <MayFail fail />
  </Boundary>,
)
expect(screen.getByText("Не удалось показать блок")).toBeVisible()
// Затем проверяется публичный retry-контракт конкретной Boundary.
```

### Типичная ошибка

Доказать восстановление, полностью заменив всё тестируемое приложение другим деревом.
