**startTransition задаёт приоритет обновлений React, но сам по себе не гарантирует порядок завершения сетевых операций.** Медленный старый ответ может прийти после быстрого нового.

#### Как это работает

Если несколько действий запускают запросы, отдельно определите политику: последний выбор побеждает, очередь или запрет параллельной отправки. Для политики последнего выбора можно использовать номер запроса и проверять его перед применением ответа. Это не отменяет выполненную сервером мутацию.

По текущему контракту обновление после await, которое должно оставаться transition, может требовать нового startTransition. Более высокоуровневые Actions помогают с отдельными сценариями, но не превращают произвольную сеть в транзакционную очередь.

#### Пример

```jsx
const latest = useRef(0)
async function choose(id) {
  const request = ++latest.current
  const data = await loadItem(id)
  if (request !== latest.current) return
  startTransition(() => setItem(data))
}
// loadItem - API приложения; ошибки обрабатываются отдельно.
```

#### Разбор примера

Каждый choose получает номер, а применить данные может только последняя актуальная попытка. Transition затем задаёт приоритет её обновления. Эти два шага независимы: приоритет не отменяет сеть и не выбирает за приложение правильный ответ.

#### Типичная ошибка

Считать `isPending` доказательством того, что устаревший запрос больше не сможет применить результат.
