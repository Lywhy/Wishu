**Полезный тест проверяет наблюдаемое поведение: доступное содержимое, действие пользователя и результат.** Запросы по роли, доступному имени и label одновременно отражают способ использования интерфейса и выявляют часть ошибок семантики.

<!-- wishu:answer-block -->

#### Как это работает

Проверка конкретного `useState`, приватной функции или точного количества рендеров часто привязывает тест к реализации. Для формы важнее сценарии успешной отправки, валидации и ошибки, чем большой snapshot разметки. Сетевые границы подменяют предсказуемо, сохраняя проверку реального пользовательского потока.

#### Пример

```tsx
const user = userEvent.setup()
render(<NameForm />)
await user.type(screen.getByLabelText("Имя"), "Анна")
await user.click(screen.getByRole("button", { name: "Сохранить" }))
expect(await screen.findByText("Сохранено")).toBeVisible()
// Тестовая интеграция задаёт успешный ответ; пример не запускался.
```

#### Разбор примера

Тест вводит данные через доступное имя, отправляет форму пользовательским действием и ждёт видимый успех. Он не зависит от названия внутреннего setter. Перестройка компонентов без изменения этого поведения не должна автоматически делать сценарий неверным.

#### Типичная ошибка

> Проверять приватные переменные и точное число render вместо наблюдаемого поведения и доступного результата.
