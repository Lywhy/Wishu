**`useMemo` кеширует результат чистого вычисления, `useCallback` - ссылку на функцию.** Зависимости сравниваются через `Object.is`. Вызов сохранённого callback всё равно выполняет его тело; `useCallback` не кеширует результат вызова.

#### Как это работает

Мемоизация оправдана для дорогого вычисления или стабильного входа мемоизированного потребителя. Она добавляет зависимости и стоимость сопровождения. React вправе сбросить кеш, поэтому на нём нельзя основывать корректность состояния. Мутации зависимостей также ломают ожидаемое поведение.

#### Пример

```tsx
const visible = useMemo(() => items.filter((item) => item.active), [items])
const onSelect = useCallback((id) => setSelectedId(id), [])
```

#### Разбор примера

Visible хранит результат фильтрации до смены items. OnSelect хранит функцию, но каждый её вызов всё равно выполнит setter. Пустые зависимости callback допустимы здесь благодаря стабильному setter, а не потому, что любой обработчик можно навсегда замкнуть.

#### Типичная ошибка

> Добавить пустые зависимости для стабильной ссылки и случайно сохранить устаревшие props внутри callback.
