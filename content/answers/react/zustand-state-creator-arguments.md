**State creator получает set для обновления, get для текущего снимка и api с инструментами конкретного store.**

<!-- wishu:answer-block -->

#### Как это работает

Creator возвращает начальное состояние, часто вместе с actions. Не читайте get как уже готовое начальное состояние во время его собственного построения. Создание store и последующий вызов action - разные моменты.

#### Пример

```jsx
const useCounter = create((set, get) => ({
  count: 0,
  increment: () => set({ count: get().count + 1 }),
}))
```

#### Разбор примера

Creator вызывается при создании store и строит начальный объект. increment выполняется позже, когда store уже существует, поэтому get().count здесь читает готовое состояние. Третий аргумент api предоставляет методы именно этого экземпляра, например getInitialState. Чтение get во время построения начальных полей принципиально отличается от чтения внутри позднее вызванного action и может встретить ещё не созданные данные.

#### Типичная ошибка

Вычислять начальное поле через get().ещёНеСозданноеПоле и считать creator обычным action.
