**Флаг replace=true заменяет весь снимок, поэтому отсутствующие в next поля, включая actions, исчезают.**

<!-- wishu:answer-block -->

#### Как это работает

Обычный set для объектного state выполняет поверхностное объединение; полная замена - явное другое поведение. Для reset используйте продуманный начальный снимок, содержащий нужный API, а не случайный объект из storage.

#### Пример

```jsx
store.setState({ count: 1 }, true)
// Если increment был частью state, в новом снимке его больше нет.
```

#### Разбор примера

Полная замена сохраняет только переданный объект. Если до неё increment был полем состояния, после замены на { count: 1 } этого поля уже нет. Пример намеренно показывает опасный вызов; корректный TypeScript-контракт может его отклонить как неполное состояние. Для восстановления обычно используют полный проверенный снимок либо обычный merge, а не произвольный объект из storage.

#### Типичная ошибка

Восстановить persisted-данные с replace=true и затем потерять методы store.
