**В Data Router action обрабатывает мутацию маршрута, после которой router может обновить связанные loader-данные.**

<!-- wishu:answer-block -->

#### Как это работает

Пользовательская форма через поддерживаемые Form/submit API связывает pending-состояние и результат с навигацией. Обычный fetch внутри `onClick` не становится router action автоматически. Revalidation должна следовать контракту режима и настройкам, а не предположению, что любой POST обновляет всё.

#### Пример

```jsx
<Form method="post">
  <input name="title" />
  <button>Сохранить</button>
</Form>
// В конфигурации маршрута отдельно определён action.
```

#### Разбор примера

Form отправляет title в action соответствующего маршрута. После мутации обновление loader-данных организуется Router по его правилам. Обычный нативный form или fetch вне этой интеграции не получает такой контракт только из-за метода POST.

#### Типичная ошибка

Сделать мутацию вне router и ожидать, что useLoaderData сам узнает об изменении сервера.
