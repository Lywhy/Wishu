Если ребёнок появляется только после запроса родителя, его эффект начинает загрузку позже. Независимые операции оказываются последовательными из-за устройства дерева, а не из-за реальной зависимости данных.

<!-- wishu:answer-block -->

#### Как это работает

Поднимите запуск независимых операций на общий уровень, используйте подходящий route loader, кеш или поддержку фреймворка. Дедупликация, отмена, повторная загрузка и инвалидирование должны иметь одного понятного владельца.

Не каждый запрос нужен параллельно: сначала отличите независимость от настоящей зависимости по ID. Suspense описывает ожидание, но не обязан автоматически запускать все ресурсы раньше. Конкретные loaders и query-библиотеки не являются возможностями одного React.

#### Пример

```tsx
async function loadDashboard(loadProfile, loadStats) {
  const profilePromise = loadProfile()
  const statsPromise = loadStats()
  const [profile, stats] = await Promise.all([profilePromise, statsPromise])
  return { profile, stats }
}
// Предполагается независимость операций и выбранная общая политика ошибки.
```

#### Разбор примера

Оба загрузчика вызываются до первого await, поэтому независимое ожидание перекрывается. Promise.all задаёт общий успешный исход, но не делает синхронную обработку параллельной. Если stats действительно требовал ID из profile, такую зависимость нельзя было бы убрать этим приёмом.

#### Типичная ошибка

> Добавлять `useMemo` вокруг fetch и считать решёнными дедупликацию и срок жизни серверных данных.
