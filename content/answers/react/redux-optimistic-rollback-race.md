**Обратный patch старой оптимистичной мутации может перетереть более новое изменение той же кеш-записи.**

<!-- wishu:answer-block -->

#### Как это работает

Для простого одиночного сценария undo удобен, но перекрытие требует политики порядка или восстановления канонического ответа. При гонке иногда безопаснее инвалидировать связанные теги и заново запросить данные, чем применить старый inverse patch.

`updateQueryData` меняет существующую запись endpoint+args, а не весь глобальный кеш сущности. Серверная версия остаётся отдельной частью согласованности.

#### Пример

```jsx
const patch = dispatch(
  api.util.updateQueryData("getPost", id, (draft) => {
    draft.title = nextTitle
  }),
)
// При конфликтующих запросах рассматривают invalidation/refetch вместо слепого patch.undo().
```

#### Разбор примера

`updateQueryData` применяет локальный patch к существующему результату конкретного endpoint и аргумента. Если затем другой запрос изменил те же поля, inverse patch первой операции может восстановить слишком старое значение. Для перекрывающихся ошибок полезно восстановить серверную истину через invalidation/refetch либо вести явный порядок версий. Сам объект patch не знает бизнес-приоритет нескольких изменений.

#### Типичная ошибка

Считать каждый undo независимым от остальных изменений того же объекта.
