**readOnly запрещает редактирование поддерживаемого поля, а disabled отключает контрол и обычно исключает его из отправки формы.**

<!-- wishu:answer-block -->

#### Как это работает

Read-only текстовое поле обычно остаётся доступным для фокуса и копирования. readOnly подходит не всем контролам: для select нужен другой контракт. Заблокированный UI не запрещает ручной вызов API.

#### Пример

```jsx
<>
  <input name="id" value={id} readOnly />
  <input name="draft" value={draft} disabled />
</>
// В FormData id может присутствовать, disabled draft - нет.
```

#### Разбор примера

Id остаётся не редактируемым, но может участвовать в FormData. Draft отключён и потому не является обычным отправляемым полем. Если его значение нужно серверу, модель отправки должна передать его явно, а не надеяться на disabled-контрол.

#### Типичная ошибка

Ожидать, что disabled-поле будет отправлено как обычное значение формы.
