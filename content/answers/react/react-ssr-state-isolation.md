На сервере модуль может обслуживать несколько запросов. Изменяемый singleton с данными пользователя способен смешать запросы и раскрыть данные другой сессии. Владелец состояния должен соответствовать границе запроса.

<!-- wishu:answer-block -->

#### Как это работает

Создавайте пользовательский store или снимок для конкретного дерева/запроса и передавайте только разрешённое начальное состояние. Клиент должен начать с согласованного снимка, иначе возможны расхождение интерфейса и mismatch.

Это не запрещает любой общий серверный кеш, но у него должны быть явные ключи, область доступа и политика жизни. Context передаёт значение по дереву, а не автоматически создаёт изоляцию на каждый запрос за вас.

#### Пример

```tsx
function createRequestSnapshot(session) {
  return { user: { id: session.user.id, name: session.user.name } }
}
// Создаётся для текущего запроса и передаётся его дереву.
// Модульный let currentUser для всех запросов не подходит.
```

#### Разбор примера

Фабрика создаёт отдельный объект из текущей session и выбирает разрешённые поля пользователя. Его передают только соответствующему дереву. Общая переменная currentUser имела бы другое время жизни и могла бы смешать параллельные серверные запросы.

#### Типичная ошибка

> Хранить текущую серверную сессию в изменяемом глобальном store и надеяться на разделение React-компонентами.
