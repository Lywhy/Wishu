**Setter `useState` заменяет сохранённое значение целиком.** Он не объединяет поля объекта автоматически, в отличие от объектной формы setState у классового компонента.

<!-- wishu:answer-block -->

#### Как это работает

Для изменения одного поля сформируйте новый объект с сохранением нужных остальных полей. Функциональный updater полезен, если результат зависит от предыдущего состояния. Spread копирует только один уровень: вложенную изменяемую ветку тоже нужно заменить.

Типизация может подсказать пропущенное поле, но не изменяет поведение API. В JavaScript потеря поля будет обычным результатом замены объекта.

#### Пример

```jsx
const [profile, setProfile] = useState({ name: "Анна", city: "Тула" })
setProfile((previous) => ({ ...previous, city: "Казань" }))
// name сохранён. setProfile({ city: 'Казань' }) потерял бы name.
```

#### Разбор примера

Updater берёт предыдущий профиль и меняет только city в новом объекте. Без spread setter сохранил бы объект только с городом. Это поведение `useState` не зависит от того, помог ли TypeScript заметить пропущенное name заранее.

#### Типичная ошибка

Считать `{city: nextCity}` частичным обновлением `useState` или изменять profile.city напрямую.
