**Внешняя запись во время render может сохраниться, даже если React прервал вычисление и никогда не показал его результат.**

<!-- wishu:answer-block -->

### Механизм и границы

- Конкурентный рендер допускает повтор и отмену вычисления до commit. Если компонент изменил общий кеш, следующий потребитель может увидеть данные от незафиксированной попытки.

- Вычисление локального нового объекта допустимо, но публикация в глобальное изменяемое хранилище - другой контракт. Пользовательскую команду выполняют в обработчике; чтение Suspense-ресурса организует поддерживающая интеграция, а не произвольная запись из render.

- Для внешнего store нужен согласованный snapshot/subscription API. Мемоизация компонента не превращает его побочный эффект в безопасный.

### Пример

```jsx
function Report({ rows }) {
  const total = rows.reduce((sum, row) => sum + row.price, 0)
  return <p>{total}</p>
}
// Здесь нет cache.set('total', total) во время render.
```

### Типичная ошибка

Публиковать промежуточные вычисления в singleton-кеш и затем считать их подтверждёнными данными UI.
