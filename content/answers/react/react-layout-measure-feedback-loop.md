**Цикл возникает, когда замер меняет state, новый UI меняет ту же геометрию, а наблюдатель снова инициирует изменение.**

<!-- wishu:answer-block -->

#### Как это работает

Сравнивайте новую метрику с прежней и определите устойчивое правило, а не колебание между двумя размерами. Разделяйте наблюдаемый и изменяемый элементы, когда это возможно; для макета часто достаточно CSS. Перенос в requestAnimationFrame может изменить расписание, но не исправляет неустойчивую логику.

`useLayoutEffect` блокирует показ, поэтому повторные синхронные циклы особенно заметны. Измеряйте только реально необходимое.

#### Пример

```jsx
setWidth((previous) => (Math.abs(previous - measuredWidth) < 0.5 ? previous : measuredWidth))
// Порог применяется только если допустим по контракту макета.
```

#### Разбор примера

Updater сохраняет прежнее число, если различие допустимо мало. Это устраняет бессмысленные обновления, но не исправляет макет, который реально колеблется между двумя размерами. Порог является частью требований, а не универсальной маскировкой ResizeObserver-ошибок.

#### Типичная ошибка

На каждое измерение записывать новый объект state и менять ширину того же контейнера без условия стабилизации.
