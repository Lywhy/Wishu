**Слияние серверной версии и локального черновика требует знания базовой версии и того, какие поля изменил пользователь.**

<!-- wishu:answer-block -->

#### Как это работает

Сравните `base`, `local` и `remote`: нетронутые локально поля можно обновить, пересекающиеся изменения - показать как конфликт по выбранной политике. При сохранении сервер может проверять version/ETag; один только optimistic UI не гарантирует отсутствие потерянной записи.

Не заменяйте черновик каждым refetch. Не обещайте универсальное глубокое merge для массивов, удалений и связанных полей: там нужны предметные правила.

#### Пример

```jsx
const conflict =
  local.title !== base.title && remote.title !== base.title && local.title !== remote.title
const nextTitle = local.title === base.title ? remote.title : local.title
// При conflict пользователь выбирает разрешение, а сервер проверяет версию.
```

#### Разбор примера

Если `local` не менялся относительно `base`, можно принять remote. Если обе стороны изменили поле одинаково, конфликта значений тоже нет. Отдельного разрешения требует случай разных новых значений; сохранение на сервере дополнительно проверяет исходную версию.

#### Типичная ошибка

Считать последнее пришедшее значение правильным независимо от локальной правки и исходной версии.
