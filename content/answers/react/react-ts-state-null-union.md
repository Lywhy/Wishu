**Инициализация null может вывести слишком узкий тип состояния; для будущего объекта задайте явный union.**

<!-- wishu:answer-block -->

#### Как это работает

Это описание допустимых состояний, а не создание объекта или проверка ответа API. Перед чтением полей сузьте null. Для запроса со статусами можно выбрать discriminated union вместо набора несвязанных полей.

#### Пример

```tsx
type User = { id: string; name: string }
const [user, setUser] = useState<User | null>(null)
const title = user ? user.name : "Гость"
```

#### Разбор примера

User | null описывает и начальное отсутствие, и будущую запись. Условие перед чтением name отделяет эти состояния. Если у загрузки есть дополнительные фазы и ошибка, их лучше включить в модель, чем скрывать null утверждением типа.

#### Типичная ошибка

Убрать null через утверждение типа и затем читать поле до загрузки данных.
