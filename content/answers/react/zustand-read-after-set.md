**После обычного синхронного set вызов get читает обновлённый снимок Zustand-store.**

<!-- wishu:answer-block -->

#### Как это работает

Переменная selector из уже выполняющегося React-render при этом остаётся прежним снимком до нового render. Асинхронное действие ещё должно дождаться своей внешней операции; синхронность set не завершает весь async-workflow.

#### Пример

```jsx
const configuration = {
  increment: () => {
    set((state) => ({ count: state.count + 1 }))
    console.log(get().count)
  },
}
```

#### Разбор примера

В обычном синхронном сценарии set уже завершил изменение store к следующей строке, поэтому get().count читает увеличенное число. Значение count, полученное ранее hook внутри компонента, при этом не переписывается задним числом: это снимок текущего рендера. После await нужно заново оценить актуальность операции. Синхронность set не защищает от позднего ответа другого запроса.

#### Типичная ошибка

После action читать старый count из замыкания React и делать вывод, что store не обновился.
