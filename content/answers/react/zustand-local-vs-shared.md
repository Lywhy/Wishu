**Zustand нужен для осмысленно общего или долгоживущего состояния; изолированный UI одного компонента часто проще оставить в `useState`.**

#### Как это работает

Оценивайте владельца, подписчиков и срок жизни данных. Общий store может сохранить то, что должно сброситься при закрытии редактора. Context со scoped-store помогает выбрать границу, но не нужен для каждого раскрытия подсказки.

#### Пример

```jsx
const [tooltipOpen, setTooltipOpen] = useState(false)
const cartCount = useCart((state) => state.items.length)
```

#### Разбор примера

tooltipOpen принадлежит конкретному компоненту и естественно исчезает при его размонтировании. Корзину, напротив, могут читать разные страницы, поэтому общий store имеет смысл. Для независимых экземпляров модального редактора глобальное поле open способно создать нежелательную связанность. Сначала определяют владельца и срок жизни данных, затем выбирают `useState`, Context или внешний store.

#### Типичная ошибка

Сделать один глобальный open для всех независимых диалогов.
