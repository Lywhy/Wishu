**RTK Query хранит результаты query по endpoint и аргументам, а не единственную глобальную копию каждой сущности во всех ответах.**

<!-- wishu:answer-block -->

#### Как это работает

Один Post может присутствовать в detail и нескольких списках. Tags помогают обновить связанные результаты, но не делают общий entity graph. Можно нормализовать отдельный ответ через entity adapter, однако это не объединит другие записи кеша автоматически.

При ручных обновлениях перечислите затронутые ключи либо используйте invalidation; учитывайте сортировки, пагинацию и агрегаты.

#### Пример

```jsx
// getPost(7), getPosts({ page: 1 }) и getPosts({ favorite: true })
// являются разными cache entries даже при наличии записи id=7.
```

#### Разбор примера

Один и тот же post может одновременно входить в detail, обычный список и список избранного. Эти результаты имеют разные cache keys, поэтому ручной patch detail не меняет остальные копии. Теги позволяют связать их повторную загрузку, а entity adapter может нормализовать один ответ. Ни то ни другое не превращает RTK Query в автоматический общий граф сущностей со всеми связями.

#### Типичная ошибка

Изменить detail через `updateQueryData` и ожидать автоматического изменения всех списков.
