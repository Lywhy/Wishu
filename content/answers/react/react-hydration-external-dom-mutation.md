**`hydrateRoot` ожидает DOM, соответствующий серверному React-выводу; вмешательство расширения или стороннего скрипта может нарушить это соответствие.**

<!-- wishu:answer-block -->

#### Как это работает

Найдите источник изменения до гидратации: переводчик, виджет, аналитический injector или ручной код. Изолируйте область стороннего владения или подключайте интеграцию после корректного mount по согласованному контракту. React не обещает исправить любое произвольное расхождение.

Диагностика recoverable errors полезна, но не заменяет устранение источника. suppressHydrationWarning применяют узко, а не ко всему приложению.

#### Пример

```jsx
hydrateRoot(container, <App />, {
  onRecoverableError(error) {
    reportHydrationIssue(error)
  },
})
// Логирование не разрешает стороннему коду менять React-owned DOM.
```

#### Разбор примера

OnRecoverableError сохраняет диагностическое свидетельство, но не разрешает внешней системе менять children React. После поиска источника вмешательства устанавливают границу владения. Просто скрыть сообщение означало бы оставить рассогласованную модель DOM.

#### Типичная ошибка

Удалять предупреждения и позволять двум системам независимо менять одни children.
