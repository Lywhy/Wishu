**`keepUnusedDataFor` задаёт срок сохранения query-записи после ухода последнего подписчика, а не обязательную свежесть ответа.**

<!-- wishu:answer-block -->

#### Как это работает

Пока есть подписчики, запись имеет другой жизненный цикл. Срок кеша, refetchOnMountOrArgChange и tag invalidation решают разные задачи. Уменьшение `keepUnusedDataFor` не превращает активную запись в периодический polling.

#### Пример

```jsx
const configuration = {
  getPost: build.query({
    query: (id) => "posts/" + id,
    keepUnusedDataFor: 30,
  }),
}
```

#### Разбор примера

Число 30 измеряется в секундах и начинает иметь значение после исчезновения последней подписки на запись. Возвращение подписчика до удаления позволяет использовать сохранённый результат. Это время хранения, а не обещание свежести: принудительное обновление при подключении, polling и invalidation настраиваются отдельно. Даже долгоживущую активную запись нужно обновлять по требованиям продукта.

#### Типичная ошибка

Считать число 30 гарантией обновления сервера каждые 30 секунд.
