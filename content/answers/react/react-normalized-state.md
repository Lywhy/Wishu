Если одна сущность встречается в списке, карточке и выбранной записи, храните её в одном месте и связывайте представления через ID. Это уменьшает риск расходящихся копий.

<!-- wishu:answer-block -->

Выбранное значение можно получать из entities по selectedId. При удалении определите, что делать с отсутствующим ID. Обновление должно сохранять иммутабельность и не менять старые снимки.

Нормализация не означает обязательное глобальное хранилище: локальный reducer тоже может использовать такую структуру. Отдельный редактируемый draft является намеренной копией со своим жизненным циклом, а не случайным дублированием серверной сущности.
