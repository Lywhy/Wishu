**React сравнивает следующее значение state с текущим через `Object.is` и может пропустить обновление при равенстве.**

<!-- wishu:answer-block -->

#### Как это работает

Мутация объекта с последующей передачей той же ссылки не сообщает о новом снимке. React иногда может вызвать компонент перед пропуском потомков; не стройте корректность на точном числе вызовов функции.

#### Пример

```jsx
setUser((previous) => ({ ...previous, name: "Анна" }))
// Новый объект, а не user.name = 'Анна'; setUser(user).
```

#### Разбор примера

Spread возвращает новую ссылку, поэтому сравнение не считает результат тем же объектом. Однако это ещё не доказательство, что имя действительно изменилось: лишнюю копию можно не создавать при отсутствии содержательного обновления. Корректность модели важнее точного числа вызовов компонента.

#### Типичная ошибка

Менять объект на месте и считать setter командой принудительной перерисовки.
