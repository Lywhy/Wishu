**`useSyncExternalStore` подключает компонент к данным за пределами состояния React.** subscribe регистрирует уведомление и возвращает отписку, а `getSnapshot` читает текущий снимок. React проверяет снимок и координирует обновление интерфейса.

<!-- wishu:answer-block -->

#### Как это работает

Неизменившийся store должен возвращать тот же снимок по `Object.is`; создание нового объекта при каждом чтении может вызвать цикл обновлений. При SSR требуется подходящий `getServerSnapshot`, согласованный между сервером и начальной гидратацией. Для обычного локального состояния используют `useState` или useReducer.

#### Контракт подписки

Неизменившийся snapshot должен быть стабилен, а при изменении возвращать подходящий новый снимок. Subscribe возвращает отписку; его случайное пересоздание может приводить к лишней переподписке. `getServerSnapshot` должен согласоваться с первым клиентским результатом.

Выборочная подписка на небольшой slice может уменьшить область обновлений, но стратегия selector/equality обычно относится к конкретному store или адаптеру. Не считайте `useSyncExternalStore` универсальным кешем любого нового объекта, создаваемого при чтении.

#### Пример

```tsx
function View() {
  const snapshot = useSyncExternalStore(store.subscribe, store.getSnapshot)
  return <p>{snapshot.count}</p>
}
// Клиентский пример: store предоставляет стабильный снимок и отписку.
```

#### Разбор примера

View читает снимок через согласованный subscribe/`getSnapshot`-контракт. Уведомление заставляет React перепроверить его, а не считать произвольное поле реактивным само по себе. При серверном render нужно дополнительно передать тот же начальный снимок для гидратации.

#### Типичная ошибка

> Возвращать новый объект из `getSnapshot` при каждом чтении без изменения данных либо отдавать изменяемый прежний объект.
