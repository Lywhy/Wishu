`useEffectEvent` выделяет событие, вызываемое из логики эффекта, которое видит актуальные props и state. Это полезно, если подписка зависит от одного набора данных, а сообщение при её событии должно читать другие текущие значения.

#### Как это работает

Например, соединение меняется по `roomId`, но оформление уведомления использует текущую тему. Effect Event не включают в зависимости и не используют как способ скрыть настоящую реактивную зависимость. Его не передают как обычный `onClick` ребёнку и не вызывают во время render.

Функции Effect Event не нужно считать универсальным обещанием стабильной идентичности. Применяйте правила и lint-интеграцию используемой версии React; API доступен в React 19.2+.

#### Пример

```tsx
import { useEffect, useEffectEvent } from "react"
function LogUpdates({ source, label }) {
  const onUpdate = useEffectEvent((value) => console.log(label, value))
  useEffect(() => {
    return source.subscribe((value) => onUpdate(value))
  }, [source])
  return null
}
// source.subscribe возвращает отписку; label не определяет саму подписку.
```

#### Разбор примера

Подписка зависит от source, а label читается при поступлении события через Effect Event. Поэтому смена подписи сама не требует переподключать источник. Если label реально определял бы выбор источника, исключать его из реактивного контракта таким способом было бы неправильно.

#### Типичная ошибка

> Заменять им все зависимости эффекта или передавать Effect Event как обычный пользовательский callback.
