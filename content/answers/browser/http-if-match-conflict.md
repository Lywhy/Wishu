**`If-Match` задаёт предварительное условие изменения: сервер применяет операцию только при подходящем текущем валидаторе представления.**

<!-- wishu:answer-block -->

### Механизм и границы

- Для проверки используется сильное сравнение `ETag` по HTTP-контракту. Несовпадение обычно даёт 412 Precondition Failed, а не молчаливое перезаписывание чужой версии.

- Сервер должен атомарно связать проверку с изменением данных. Проверка версии только в клиенте оставляет гонку.

- Не путайте `If-Match` для защиты изменения с `If-None-Match` при проверке кеша.

### Сценарий

Два редактора открыли v3; первый сохранил v4, а второй получает отказ при попытке сохранить с `If-Match`: "v3".

```http
PUT /articles/42 HTTP/1.1
Host: example.com
If-Match: "v3"
Content-Type: application/json

{"title":"Новый заголовок"}

HTTP/1.1 412 Precondition Failed
```

### Типичная ошибка

Сначала отдельно проверить версию на сервере, затем без атомарности записать данные после конкурентного изменения.
