**`Cache-Control` задаёт политику хранения и повторного использования, а `ETag` даёт валидатор версии представления.**

<!-- wishu:answer-block -->

### Механизм и границы

- Свежий ответ может использоваться без похода к origin; несвежий - требовать проверки. No-cache допускает хранение с обязательной валидацией, `no-store` запрещает соответствующее хранение.

- `If-None-Match` с подходящим `ETag` позволяет ответить 304 и переиспользовать прежнее тело. Валидатор не обещает постоянную свежесть сам по себе.

### Сценарий

Ответ с `ETag` "v2" и `no-cache` сохраняется, затем проверяется; 304 позволяет использовать тело v2 без новой передачи.

```http
HTTP/1.1 200 OK
Cache-Control: no-cache
ETag: "v2"

{"version":2}
```

### Типичная ошибка

Путать отсутствие повторного скачивания с отсутствием сетевой проверки либо считать `no-cache` запретом хранения.
