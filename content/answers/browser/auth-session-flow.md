**После проверки входа сервер связывает непрозрачный идентификатор сессии с состоянием пользователя и проверяет его в последующих запросах.**

<!-- wishu:answer-block -->

### Механизм и границы

- Идентификатор должен быть защищённым секретом, а параметры cookie - соответствовать модели угроз.

- Ротация, истечение и отзыв происходят по серверной политике. UI-флаг loggedIn не является доказательством доступа.

### Сценарий

Сервер находит сессию по cookie, затем отдельно проверяет право пользователя читать выбранный проект.

### Типичная ошибка

Возвращать приватные данные только на основании переданного клиентом userId.
