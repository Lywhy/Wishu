**Cache API даёт приложению явное хранение `Request`/`Response`, а HTTP-кеш применяет стандартные правила повторного использования сетевых ответов.**

<!-- wishu:answer-block -->

### Механизм и границы

- Сам вызов cache.put не реализует за вас TTL, revalidation и очистку устаревших версий.

- Совпадение запросов учитывает API-контракт, включая применимые правила `Vary`; это не глобальная карта любого JS-объекта. Cache API используется не только из Service Worker.

### Сценарий

Offline-оболочка хранится в именованном кеше, а код отдельно решает, когда обращаться к сети и заменять запись.

### Типичная ошибка

Ожидать, что `no-cache` автоматически задаст всю стратегию Cache API.
