**Если const { count } = reactiveState извлекает примитивное свойство, локальная переменная получает текущее значение, а не реактивный доступ к свойству.** Последующие присваивания state.count не обновят эту локальную копию.

<!-- wishu:answer-block -->

- Для сохранения связи используют toRef или toRefs. Извлечённый вложенный объект может оставаться Proxy, поэтому нельзя говорить, что любая деструктуризация всегда снимает реактивность. Компиляторные возможности деструктуризации defineProps также имеют отдельные правила и зависят от версии Vue.

<!-- wishu:answer-block -->

### Уточнения и границы

Деструктуризация примитивного свойства reactive копирует текущее значение. toRef(state, "count") и toRefs(state) дают связанные refs для чтения и записи. Извлечённый вложенный Proxy остаётся реактивным, но замена этого поля родителем не переключит старую ссылку. В Vue 3.5+ деструктуризация непосредственно defineProps в том же script setup преобразуется компилятором; это не общее правило JavaScript. Для передачи такого prop в watcher/composable нужен getter.

### Пример и разбор

```js
import { reactive, toRefs } from "vue"
const state = reactive({ count: 0 })
const { count } = toRefs(state)
state.count++ // count.value === 1
count.value++ // state.count === 2
```

Для prop: watch(() => props.count, callback), а не watch(props.count, callback).

**Типичная ошибка:** Распространять компиляторную поддержку defineProps на обычный reactive или передавать в функцию уже прочитанный примитив.

**Главная мысль:** Передавайте реактивный доступ к свойству, если нужны будущие изменения.
