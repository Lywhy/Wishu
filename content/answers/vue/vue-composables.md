**Composable - функция, объединяющая реактивные значения, вычисления и lifecycle для определённой задачи.** Обычно её имя начинается с use. Она позволяет использовать один контракт, например состояние подключения, в разных компонентах.

- Если ref создаётся внутри функции, отдельные вызовы получают отдельное состояние. Вынесение в модуль может сделать его общим, но при SSR такой singleton опасен смешением запросов. Ресурсы composable должны освобождаться вместе с владельцем.

### Уточнения и границы

Composable - функция, использующая Composition API для связной задачи. Имя обычно начинается с use. Ref внутри функции создаётся на каждый вызов, а ref в области модуля разделяется импортёрами. Удобно возвращать обычный объект refs и методов: его деструктуризация сохраняет связи. Входной ref/getter нужно читать внутри реактивного эффекта, например нормализуя toValue в watchEffect. Хуки и cleanup принадлежат компоненту-владельцу; модульное изменяемое состояние опасно при SSR.

### Пример и разбор

```js
export function useCounter() {
  const count = ref(0)
  const increment = () => count.value++
  return { count, increment }
}
```

Два вызова useCounter получают независимые счётчики, пока ref остаётся внутри функции.

**Типичная ошибка:** Выносить ref в модуль ради переиспользования функции и неожиданно делать все экземпляры общими.

**Главная мысль:** Место создания ref определяет, кто разделяет состояние.
