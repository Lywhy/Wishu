**Сброс состояния, persistence и граница доверия storage.**

По умолчанию состояние Pinia живёт в памяти и теряется после перезагрузки страницы. Option Store имеет $reset, повторно создающий state; Setup Store определяет собственный reset. $patch группирует изменения. $subscribe можно использовать для сохранения, но localStorage нужно читать с проверкой структуры, версии и обработки ошибок. Сохранение на клиенте не делает данные доверенными и не заменяет серверную сессию. При logout нужно очищать пользовательское состояние и сохранённую копию.

### Пример и разбор

```js
// В Setup Store
const items = ref([])
function $reset() {
  items.value = []
}
return { items, $reset }
```

Сброс памяти и удаление сохранённой корзины - отдельные действия.

**Типичная ошибка:** Ожидать встроенной persistence или хранить секреты в localStorage, считая store защищённым контейнером.

**Главная мысль:** Persistence и reset нужно проектировать явно для каждого типа store.
