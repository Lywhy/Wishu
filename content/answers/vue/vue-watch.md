**Watch наблюдает явно указанный источник и даёт доступ к новому и старому значению.** WatchEffect запускает функцию сразу и собирает реактивные чтения синхронной части выполнения; чтения после await автоматически не добавляются тем же способом.

- Оба подходят для побочных действий, а computed - для производного значения. Устаревшие запросы и подписки нужно освобождать через предусмотренный cleanup. Глубокое наблюдение может быть дорогим, поэтому лучше выбирать конкретное поле или getter.

### Уточнения и границы

watch принимает ref, reactive, getter или массив источников. Callback по умолчанию ленивый и получает новое и старое значение; immediate запускает его сразу. Чтения внутри callback не становятся дополнительными источниками. watchEffect запускается сразу и отслеживает реактивные чтения своей синхронной части; чтения после await не добавляются. watch(state.count, ...) передаёт уже прочитанное число, поэтому для поля нужен getter.

### Пример и разбор

```js
watch(
  () => props.userId,
  (id) => loadUser(id),
  { immediate: true },
)
watchEffect(() => {
  document.title = `Сообщений: ${unread.value}`
})
```

Первый watcher зависит только от userId, второй - от прочитанного unread.

**Типичная ошибка:** Синхронизировать через watch состояние, которое можно напрямую вычислить, или считать async watchEffect отслеживающим все чтения после await.

**Главная мысль:** Выбирайте watcher для побочного действия, computed - для производных данных.
