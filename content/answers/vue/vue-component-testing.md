**Наблюдаемое поведение и асинхронное обновление DOM.**

Компонентный тест монтирует компонент, задаёт props/slots, выполняет действия и проверяет видимый DOM или emitted events. В Vue Test Utils trigger, setValue и setProps нужно ожидать, чтобы завершилось реактивное обновление. nextTick не ожидает произвольные сетевые Promise; для их разрешения используется, например, flushPromises после подготовленного mock. Таймеры и реальные браузерные особенности требуют отдельного контроля. Внутренние имена refs менее устойчивы, чем контракт компонента.

### Пример и разбор

```js
const wrapper = mount(Counter, { props: { initial: 0 } })
await wrapper.get("button").trigger("click")
expect(wrapper.get("button").text()).toBe("1")
```

Предполагается Counter, показывающий счётчик на кнопке; это иллюстрация, а не выполненный тест.

**Типичная ошибка:** Проверять DOM сразу после действия, сравнивать только snapshots или мокать саму логику, ради которой написан тест.

**Главная мысль:** Проверяйте пользовательский контракт, ожидая соответствующий тип работы.
