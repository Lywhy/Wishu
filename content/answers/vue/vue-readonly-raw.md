**Ограничение мутаций и границы Proxy.**

readonly создаёт представление, запрещающее запись через него; изменения через исходный реактивный объект остаются видимыми. Это не копия и не механизм безопасности. toRaw возвращает исходный объект Proxy для временного доступа, но постоянные мутации через raw обходят уведомления. markRaw исключает объект из преобразования в Proxy, что полезно для некоторых внешних экземпляров. Его вложенные объекты не становятся автоматически помеченными.

### Пример и разбор

```js
const state = reactive({ count: 0 })
const publicState = readonly(state)
state.count++ // publicState.count тоже 1
console.log(toRaw(state) === state) // false
```

Один логический объект может иметь raw- и proxy-ссылку с разной идентичностью.

**Типичная ошибка:** Смешивать raw и Proxy в сравнениях по ссылке или считать readonly защитой серверных данных.

**Главная мысль:** Readonly задаёт интерфейс доступа, raw API требуют контроля владения.
