**Чистая реактивная логика и компонентный контекст.**

Composable только с ref/computed можно вызвать напрямую и проверить значения. Если он регистрирует lifecycle или использует inject, нужен host-компонент, который вызовет его в setup под нужным провайдером. После теста host размонтируют, проверяя освобождение ресурсов. Для запросов тестируют успех, ошибку и смену входа до завершения старого запроса. Для Pinia в тестах нужно контролировать экземпляр и понимать, не заглушены ли actions тестовым плагином.

### Пример и разбор

```text
Создать host -> передать provide -> вызвать composable в setup
Смонтировать -> проверить mounted-эффект
Изменить вход -> дождаться обновления
Размонтировать -> проверить cleanup
```

Для useCounter без контекста такой host избыточен.

**Типичная ошибка:** Вызывать onMounted-зависимый composable вне компонента и принимать отсутствие эффекта за дефект его логики.

**Главная мысль:** Тестовый способ вызова должен воспроизводить зависимости composable.
