**Серверный HTML и согласование с клиентским деревом.**

SSR создаёт HTML на сервере; hydration связывает его с клиентским приложением и обработчиками. Ошибки соответствия возникают из-за разного первоначального состояния, Math.random, часовых поясов или исправленной браузером невалидной вложенности. DOM-API недоступны на сервере, а mounted выполняется только на клиенте. Разделяемое модульное пользовательское состояние может смешать SSR-запросы: приложение, router и store создают на запрос. При передаче состояния в HTML нужна безопасная сериализация.

### Пример и разбор

```js
const ready = ref(false)
onMounted(() => {
  ready.value = true
})
```

Одинаковый placeholder при ready=false согласует сервер и первый клиентский рендер для части, зависящей от браузера.

**Типичная ошибка:** Использовать window при импорте модуля или скрывать mismatch вместо устранения разных исходных данных.

**Главная мысль:** Первый клиентский рендер должен соответствовать серверной разметке.
