**Стандартный v-model компонента связывает prop modelValue с событием update:modelValue.** Родитель хранит значение и принимает обновление. В современных версиях Vue defineModel позволяет описать тот же контракт короче.

<!-- wishu:answer-block -->

- Для нескольких моделей используют аргументы v-model и соответствующие имена. Это не разрешение произвольно менять все props. Значение по умолчанию модели у ребёнка требует внимания, если родитель не инициализировал своё значение: стороны могут оказаться несогласованными.

<!-- wishu:answer-block -->

### Уточнения и границы

Стандартный v-model разворачивается в prop modelValue и обработчик update:modelValue у родителя. В Vue 3.4+ defineModel объявляет этот контракт и возвращает ref модели. Аргумент v-model:title соответствует prop title и update:title; моделей может быть несколько. Модификаторы компонент обрабатывает по своему контракту. Default у ребёнка не инициализирует автоматически undefined-модель родителя, поэтому лучше согласовать начальное значение у владельца.

### Пример и разбор

```vue
<script setup>
const title = defineModel("title", { type: String, required: true })
</script>
<template><input v-model="title" /></template>
```

Родитель использует <TitleInput v-model:title="title" />. До Vue 3.4 контракт задаётся через defineProps и defineEmits.

**Типичная ошибка:** Ожидать, что мутация вложенного объекта модели обязательно отправит update:modelValue: явная замена делает уведомление понятнее.

**Главная мысль:** V-model - согласованный контракт значения и уведомления.
