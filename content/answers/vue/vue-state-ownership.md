**Владение локальными, общими и серверными данными.**

Локальное состояние поля или раскрытия панели обычно остаётся в компоненте. Для соседей можно поднять его к общему родителю. provide/inject удобен для контекста поддерева, composable - для повторной логики, но сам по себе не гарантирует общее состояние. Pinia полезна для разделяемых доменных данных и действий нескольких страниц. Серверные данные требуют также стратегии обновления, кеша и ошибок; Pinia не добавляет её автоматически.

### Пример и разбор

```text
Открыта ли подсказка -> локальный ref
Выбор строки для двух соседей -> общий родитель
Корзина между страницами -> общий store
URL фильтра, которым делятся -> query маршрута
```

Решение определяется временем жизни и способом обмена, а не размером компонента.

**Типичная ошибка:** Переносить все временные значения в глобальный store или считать каждый вызов composable общим хранилищем.

**Главная мысль:** Храните состояние у ближайшего владельца, способного обеспечить его контракт.
