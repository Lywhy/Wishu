**flush, пакетирование и принадлежность эффектов.**

Обычный watcher выполняется после обновления родителя, но до обновления собственного DOM. flush: "post" нужен для чтения уже обновлённого DOM владельца. flush: "sync" запускает watcher синхронно без обычного пакетирования и опасен при множестве мутаций массива. Watcher, созданный синхронно в setup, автоматически останавливается при unmount; созданный позже в таймере может потребовать явного stop. Возвращаемый handle позволяет прекратить наблюдение раньше.

### Пример и разбор

```js
const stop = watch(
  count,
  () => {
    console.log(element.value?.textContent)
  },
  { flush: "post" },
)
// Когда наблюдение больше не нужно:
// stop()
```

Остановка не откатывает уже совершённые внешние действия.

**Типичная ошибка:** Читать собственный DOM из watcher по умолчанию или создавать бесконтрольные watchers после асинхронной загрузки.

**Главная мысль:** Выбирайте фазу watcher по его задаче и контролируйте время жизни.
