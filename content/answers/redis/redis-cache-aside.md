**Приложение сначала читает кеш, при промахе получает данные из основного источника и сохраняет результат с подходящим сроком.** При изменении основной записи кеш обновляют или инвалидируют по выбранной стратегии.

- Между чтением, записью БД и заполнением кеша возможны гонки. Один TTL не обеспечивает строгую согласованность. Ключ должен включать параметры, влияющие на представление, а для персональных данных - безопасно разделять пользователей и права.
