**`app.request` принимает запрос и возвращает `Response`, позволяя проверить маршрут через тот же обработчик приложения без отдельного HTTP-listener.**

<!-- wishu:answer-block -->

#### Как это работает

Так проверяют статус, заголовки, JSON и отказы валидации. Для JSON-запроса нужно задать `Content-Type`, как в настоящем клиенте. Внешние сервисы и БД должны иметь контролируемую тестовую реализацию. Проверка `app.request` не покрывает автоматически настройки прокси, TLS, портов и адаптера развёртывания.

#### Пример

```typescript
const app = new Hono().get("/health", (c) => c.json({ ok: true }))
const response = await app.request("/health")
expect(response.status).toBe(200)
expect(await response.json()).toEqual({ ok: true })
// Фрагмент для выбранного тестового раннера.
```

#### Разбор примера

Ожидания проверяют наблюдаемый HTTP-контракт, а не внутреннее число вызовов функций. Помимо успешного пути полезны неверные параметры, запрет доступа и отказ зависимости. Пример здесь приведён для разбора и не выполнялся.

#### Типичная ошибка

> Ограничиться успешным JSON и пропустить неверный статус, `Content-Type` или обработку ошибки.
