**`onError` обрабатывает выброшенные ошибки при обработке запроса, а `notFound` задаёт ответ, когда подходящего маршрута нет.**

<!-- wishu:answer-block -->

#### Как это работает

Ошибку клиента удобно представить ожидаемым статусом, а неожиданный сбой - общим ответом без внутреннего stack trace. `HTTPException` позволяет связать исключение со статусом. Если `onError` перехватывает его, нужно сохранить этот контракт, а не превращать любой отказ в 500. Серверное логирование остаётся отдельным действием.

#### Пример

```typescript
import { HTTPException } from "hono/http-exception"
app.notFound((c) => c.json({ error: "Маршрут не найден" }, 404))
app.onError((error, c) => {
  if (error instanceof HTTPException) return error.getResponse()
  console.error(error)
  return c.json({ error: "Внутренняя ошибка" }, 500)
})
```

#### Разбор примера

`HTTPException` сохраняет заданный ответ, а неизвестная ошибка получает безопасный общий текст. Отсутствующий маршрут проходит через notFound. Служебные логи не должны включать секреты или целиком непроверенные пользовательские данные.

#### Типичная ошибка

> Вернуть stack trace клиенту либо обрабатывать 404 только как аварийное исключение.
