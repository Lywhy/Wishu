**`c.req.param` читает именованную часть маршрута, а `c.req.query` - строку запроса. Полученное значение ещё нужно проверить и при необходимости преобразовать.**

<!-- wishu:answer-block -->

#### Как это работает

Для /users/:id идентификатор принадлежит пути, а limit относится к query. TypeScript-аннотация не превращает строку в число во время выполнения. Отсутствующее значение, пустая строка, дробь и отрицательное число могут иметь разный смысл. Для повторяющегося параметра используйте `c.req.queries`, если API допускает несколько значений.

#### Пример

```typescript
app.get("/users/:id", (c) => {
  const raw = c.req.query("limit") ?? "20"
  const limit = Number(raw)
  if (!/^\d+$/.test(raw) || !Number.isInteger(limit) || limit < 1 || limit > 100) {
    return c.json({ error: "Некорректный limit" }, 400)
  }
  return c.json({ id: c.req.param("id"), limit })
})
```

#### Разбор примера

Проверка принимает только ограниченное положительное целое, поэтому лимит действительно имеет числовой контракт. Проверку формата самого id выполняют отдельно: факт совпадения маршрута не доказывает существование пользователя.

#### Типичная ошибка

> Использовать parseInt без проверки всей строки и незаметно принять 10abc как 10.
