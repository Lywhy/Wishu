**Валидацию выполняют до бизнес-обработчика. После успешного validator данные читают через `c.req.valid`, а не подменяют проверку приведением типа.**

<!-- wishu:answer-block -->

#### Как это работает

Для JSON нужен соответствующий Content-Type. Валидатор может отклонить запрос с 400 либо вернуть нормализованный объект для следующего обработчика. Проверка структуры не доказывает право на операцию и не гарантирует существование связанных сущностей. Эти условия проверяются отдельно сервисом.

#### Пример

```typescript
import { validator } from "hono/validator"
app.post(
  "/notes",
  validator("json", (value, c) => {
    if (typeof value?.title !== "string" || !value.title.trim()) {
      return c.json({ error: "Нужен заголовок" }, 400)
    }
    return { title: value.title.trim() }
  }),
  (c) => c.json(c.req.valid("json"), 201),
)
```

#### Разбор примера

Нижний обработчик получает нормализованный title только после проверки. Пример демонстрирует контракт валидатора и не записывает данные в БД. В реальном API дополнительно ограничивают размер и длину полей.

#### Типичная ошибка

> Написать await `c.req.json`() as Note и считать внешний JSON проверенным.
