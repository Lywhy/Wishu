**Код до await next() выполняется на входе, а код после него - при возврате из последующих middleware и обработчика.**

<!-- wishu:answer-block -->

#### Как это работает

Так строятся измерение времени, общие заголовки и другие обёртки запроса. Middleware может завершить цепочку раньше, вернув собственный `Response`, например при отказе в доступе. Регистрация и область пути определяют, какие запросы оно охватывает. Без await логика после next может выполниться до готовности ответа.

#### Пример

```typescript
app.use("*", async (c, next) => {
  const started = performance.now()
  await next()
  c.header("Server-Timing", `app;dur=${performance.now() - started}`)
})
app.get("/health", (c) => c.text("ok"))
```

#### Разбор примера

Заголовок выставляется после выполнения следующего участка цепочки. Измерение включает его асинхронное ожидание; это не чистое процессорное время и не полная задержка сети для пользователя.

#### Типичная ошибка

> Не дождаться next или вызвать его дважды, пытаясь повторить downstream-операцию.
