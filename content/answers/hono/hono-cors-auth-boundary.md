**CORS описывает доступ браузерного JavaScript к ответу с другого origin. Он не подтверждает пользователя и не запрещает запросы небраузерным клиентам.**

<!-- wishu:answer-block -->

#### Как это работает

Middleware CORS обычно регистрируют до защищённых маршрутов, чтобы корректно обработать preflight. Для cookie-запросов разрешённый origin и credentials должны быть согласованы; wildcard origin не подходит для такого чтения. Авторизация и защита от CSRF определяются отдельно по модели API, а не наличием заголовка CORS.

#### Пример

```typescript
import { cors } from "hono/cors"
app.use(
  "/api/*",
  cors({
    origin: "https://app.example.com",
    credentials: true,
  }),
)
// Проверка сессии и прав регистрируется отдельно.
```

#### Разбор примера

Настройка разрешает конкретному origin читать подходящие ответы с credentials. Это не список пользователей с доступом к данным. Сам сервер всё равно проверяет сессию, действие и объект запроса.

#### Типичная ошибка

> Считать разрешённый Origin доказательством прав или блокировать preflight как обычный запрос без сессии.
