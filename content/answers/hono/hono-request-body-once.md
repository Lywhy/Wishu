**Стандартное тело `Request` является потребляемым потоком. Повторное чтение raw `Request` после потребления может завершиться ошибкой.**

<!-- wishu:answer-block -->

#### Как это работает

Hono предоставляет кеширование некоторых способов разбора через HonoRequest, но это не разрешение произвольно смешивать raw.text(), raw.json() и чтение потока. Лучше выбрать владельца разбора и передать проверенный результат дальше. Для подписи webhook нужны исходные байты, а для проверки структуры - разобранный объект; порядок и лимит размера продумывают заранее.

#### Пример

```typescript
app.post("/hook", async (c) => {
  const raw = await c.req.text()
  // Проверка подписи должна использовать именно raw и секрет сервера.
  const parsed: unknown = JSON.parse(raw)
  return c.json({ received: typeof parsed === "object" })
})
// Ограничение размера и обработка невалидного JSON добавляются отдельно.
```

#### Разбор примера

Текст читается один раз и становится явной базой дальнейших шагов. Сам пример подпись не проверяет: комментарий указывает обязательную границу реального webhook. Повторно сериализованный объект может не совпасть с исходными байтами.

#### Типичная ошибка

> Проверять подпись после `JSON.stringify` разобранного объекта и потерять исходное представление.
