Возвращаемый тип `this` связывает результат с конкретным подтипом получателя. Поэтому метод родителя, возвращающий текущий объект, не обязан превращать наследника обратно в тип родительского класса.

<!-- wishu:answer-block -->

#### Как это работает

Это удобно для fluent API: после общего метода остаются доступны специальные методы наследника. Возврат Base зафиксировал бы только базовую форму.

Контракт `this` обычно означает возврат совместимого конкретного получателя, а не возможность создать произвольный новый Base и объявить его this. Он также не кодирует обязательную последовательность шагов: для «сначала настройка, потом запуск» нужны разные состояния API или отдельные интерфейсы.

#### Пример

```typescript
class Query {
  where(_condition: string): this {
    return this
  }
}
class PagedQuery extends Query {
  limit(_count: number): this {
    return this
  }
}
new PagedQuery().where("active = true").limit(10)
```

#### Разбор примера

Where возвращает тот же PagedQuery, поэтому после него доступен limit. Возвращаемый Query сохранил бы только базовые возможности и потерял удобство цепочки. Однако обе операции здесь являются учебными заглушками: тип `this` не реализует фильтрацию и не контролирует обязательный порядок шагов.

#### Типичная ошибка

> Считать возврат `this` автоматической проверкой порядка всех шагов builder.
