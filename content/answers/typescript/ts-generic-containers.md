**Type alias и `interface` могут принимать параметры типа, описывая целое семейство контрактов.** При использовании `Box<User>` конкретный тип подставляется в соответствующие позиции. Это не создаёт отдельный runtime-класс или проверяющую схему.

#### Как это работает

Вложенную запись читают изнутри наружу: `Promise<Box<User[]>>` - `Promise` коробки с массивом User. Важно различать generic-контейнер и generic call signature внутри него: в одном случае параметр фиксируется для всего объекта, в другом выбирается при каждом вызове. Именованные промежуточные типы помогают читать длинные конструкции.

#### Где выбирается параметр

```typescript
interface Fixed<T> {
  map(value: T): T
}
interface PerCall {
  map<T>(value: T): T
}
```

У `Fixed<number>` выбор сделан для всего контракта: `map` принимает number. У PerCall реализация обязана поддержать каждый допустимый T и сохранить связь при каждом отдельном вызове. Это существенно более сильное обещание. Функция только для чисел не становится универсальной реализацией PerCall из-за похожей формы сигнатуры.

#### Пример

```typescript
type User = { id: number }
interface Box<T> {
  value: T
}
type LoadedList<T> = Promise<Box<T[]>>
type LoadedUsers = LoadedList<User>
const box: Box<User> = { value: { id: 1 } }
```

#### Разбор примера

LoadedUsers читается как обещание коробки, внутри которой находится массив User. На каждом уровне действует свой контракт, а не новая разновидность runtime-объекта. В box значение действительно содержит id; описание Box само по себе не проверило бы такую структуру после разбора произвольного JSON.
