**При объектном spread более поздняя известная запись может заменить предыдущую. Результат конструирования не следует автоматически считать пересечением типов исходных объектов.**

<!-- wishu:answer-block -->

#### Как это работает

В intersection конфликт `string` и `number` способен дать невозможный тип свойства; spread с явной поздней записью имеет другую модель. Optional-поля и generic-источники требуют отдельного внимания: простая схема для двух конкретных литералов не описывает каждый generic-случай.

Проверяйте, какое значение и тип реально остаются после сборки объекта.

#### Пример

```typescript
const left = { id: "a", enabled: true }
const result = { ...left, id: 1 }
const id: number = result.id
type Both = { id: string } & { id: number } // id: never
```

#### Разбор примера

В result последнее id: 1 заменяет строковое значение из left, поэтому чтение имеет тип number. Both описывает совсем другое требование: одновременно удовлетворять двум несовместимым типам id. Порядок runtime-конструирования нельзя объяснять как математическое пересечение всех прежних значений.

#### Типичная ошибка

> Объяснять каждый spread как безусловный intersection.
