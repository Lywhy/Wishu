При `noUncheckedIndexedAccess` непроверенное индексное чтение учитывает undefined. Это делает видимой ситуацию, когда в массиве нет позиции или в словаре отсутствует ключ. Настройка включается отдельно от strict.

#### Как это работает

Именованное обязательное свойство и известная существующая позиция кортежа могут оставаться точными. Проверка `items.length > 0` не всегда превращает обычный массив в кортеж с доказанной первой позицией. Сохраните прочитанное значение и проверьте его либо используйте контракт непустого массива.

For...of и методы обхода помогают работать с существующими элементами, но не превращают разрежённые или непроверенные runtime-данные в корректные плотные массивы. Non-`null` assertion скрывает отсутствие, а не исправляет его.

#### Пример

```typescript
// strictNullChecks и noUncheckedIndexedAccess включены.
function label(items: string[], id: string, names: Record<string, string>) {
  const first = items[0] // string | undefined
  const selected = names[id] // string | undefined
  return first?.toUpperCase() ?? selected ?? "Нет значения"
}
```

#### Разбор примера

First и selected допускают `undefined` по разным причинам: в массиве нет позиции или в словаре нет ключа. Optional chaining и цепочка ?? задают явный порядок запасных значений. Это реальная обработка отсутствия, в отличие от assertion, которая только скроет его в типе.

#### Типичная ошибка

> Отключать проверку из-за большого числа `undefined` вместо уточнения контрактов чтения.
