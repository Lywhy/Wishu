**Mapped type может оставить ключ, если его значение соответствует условию, и заменить ключ на `never` в остальных случаях. Нужно заранее решить, как учитывать `undefined` у optional-полей.**

<!-- wishu:answer-block -->

#### Как это работает

Проверка `T[K] extends string` не обязана сохранить `name?: string`, поскольку при чтении возможен undefined. Если условие предметно относится к непустой части типа, отдельно применяют `NonNullable`, осознавая изменение смысла.

Полученный тип не фильтрует реальный объект; для новых данных нужна реализация преобразования.

#### Пример

```typescript
type Strings<T> = {
  [K in keyof T as T[K] extends string ? K : never]: T[K]
}
type View = Strings<{ name: string; age: number; nick?: string }>
// Сохраняется name; nick требует отдельной политики.
```

#### Разбор примера

Name проходит условие `string`, age отклоняется, а nick включает `undefined` и потому требует отдельного решения. Если предметно нужно сохранить необязательную строку, условие должно явно учитывать такую политику. Созданный тип View не удаляет поля из существующей записи.

#### Типичная ошибка

> Считать, что name?: `string` и name: `string` всегда проходят одно условие одинаково.
