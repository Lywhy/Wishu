**Явный список исходников и выбор tsconfig через -p задают разные способы запуска. Нельзя предполагать, что переданный файл будет проверен с теми же настройками, что и весь проект.**

<!-- wishu:answer-block -->

#### Как это работает

В TS 5.x явные входные файлы не означали автоматическое применение найденного tsconfig. В TS 6.0 поведение при наличии конфигурации изменено: предусмотрена диагностика и явный механизм игнорирования config. Учитывайте точную версию.

Для проверки реального проекта указывайте его конфигурацию и исследуйте итоговые параметры; пример-файл может зависеть от других файлов и глобальных типов.

#### Пример

```bash
tsc -p tsconfig.json --showConfig
tsc -p tsconfig.json --noEmit
```

#### Разбор примера

Выбор -p фиксирует конфигурацию воспроизводимого проекта вместе с его окружением. Передача одного файла создаёт другой сценарий запуска и может изменить диагностику. В TS 6.0 явный `ignoreConfig` подтверждает намерение не использовать найденный конфиг, а не является исправлением самой ошибки типов.

#### Типичная ошибка

> Сравнивать диагностику разных способов запуска как диагностику одной конфигурации.
