**`Set<T>` ограничивает тип элементов, `Map<K, V>` - тип ключей и связанных значений.** Параметры можно задать явно либо вывести из подходящих начальных данных. Нужны декларации стандартной библиотеки для этих API и реальная поддержка в среде.

#### Как это работает

Map.get возвращает V | `undefined`, поскольку записи может не быть. Проверка has и чтение get - отдельные операции; при значении, допускающем `undefined`, это особенно важно. Generic-аннотация не меняет правила идентичности объектных ключей и не создаёт runtime-валидацию добавлений из непроверенного JavaScript.

#### Пример

```typescript
const ids = new Set<number>([1, 2])
const users = new Map<number, { name: string }>()
users.set(1, { name: "Аня" })
const name: string = users.get(1)?.name ?? "нет пользователя"
// users.set("1", ...) не соответствует типу ключа number.
```

#### Разбор примера

`map` связывает числовой ключ с объектом пользователя, однако get даже после set статически допускает отсутствие записи. Optional chaining и запасная подпись обрабатывают этот исход. Замена числового ключа строковым нарушила бы тип, хотя JavaScript сам умеет хранить в `map` ключи обоих видов.
