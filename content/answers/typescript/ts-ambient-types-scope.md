types ограничивает набор автоматически подключаемых пакетов типов, а typeRoots задаёт каталоги поиска таких пакетов. Это помогает не включать случайно доступные глобальные объявления из соседних зависимостей.

<!-- wishu:answer-block -->

Если в браузерный проект попали тестовые или Node-глобалы, код может успешно типизироваться для API, которого нет в браузере. Разделяйте конфигурации приложения, сервера и тестов.

Эти опции не являются запретом на типы явно импортированного модуля и не удаляют встроенные декларации lib. Например, отсутствие DOM регулируется набором lib, а не одним types. typeRoots ожидает структуру корней пакетов типов, а не произвольный список отдельных .d.ts-файлов.

<!-- wishu:answer-block -->

Пример явного браузерного окружения в отдельном tsconfig:

```json
{
  "compilerOptions": {
    "lib": ["ES2023", "DOM"],
    "types": []
  }
}
```

<!-- wishu:answer-block -->

**Версия важна:** по текущей документации в TypeScript 6.0 значение types по умолчанию стало пустым списком; в более ранних версиях автоматически подключались видимые @types-пакеты. Явная настройка делает намерение проекта понятным независимо от этого изменения.

<!-- wishu:answer-block -->

[Документация TypeScript](https://www.typescriptlang.org/tsconfig/types.html).

<!-- wishu:answer-block -->

### Не полагаться на defaults другой версии

Для целевого окружения полезно явно задать нужные глобальные типы. По документации TS 6.0 default для types изменён на пустой список; поведение TS 5.9 и ранее при отсутствии настройки отличалось. Явные импорты и lib остаются отдельными источниками типов.

```typescript
// Для конкретного Node-проекта, если это соответствует среде:
// { "compilerOptions": { "types": ["node"] } }
// Для браузера не добавлять Node-глобалы без реальной необходимости.
```
