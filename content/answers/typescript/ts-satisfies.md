`satisfies` проверяет совместимость выражения с контрактом, не заменяя итоговый тип выражения этим широким контрактом. Возможность доступна с TypeScript 4.9.

<!-- wishu:answer-block -->

Аннотация задаёт тип переменной; as является утверждением о представлении значения; satisfies проверяет соответствие и сохраняет полезную информацию о выражении. Контекст при проверке может влиять на вывод, поэтому фраза «satisfies вообще не влияет на вывод» слишком категорична.

Сочетание `as const satisfies ...` позволяет сохранить литеральную точность и readonly-модификаторы, если целевой контракт с ними совместим. Это не runtime-валидация и не универсальная гарантия отсутствия лишних полей у ранее созданного объекта.

### Проверка не добавляет необязательное свойство

Целевой контракт может разрешать optional-поле, отсутствующее у конкретного выражения. Satisfies не обязан добавить это поле к итоговой форме значения. Если нужен широкий переменный контракт, задайте подходящую аннотацию.

```typescript
const config = { mode: "dark" } satisfies {
  mode: "dark" | "light"
  debug?: boolean
}
// config.debug // Поле не было объявлено в исходном выражении.
```
