**Контракт чтения свойства и допустимый вход setter могут различаться. Например, setter принимает строку или число, а getter всегда возвращает нормализованное число.**

<!-- wishu:answer-block -->

#### Как это работает

Возможности раздельной типизации accessors развивались в версиях TS; показанный контракт предполагает поддержку такого синтаксиса. Различие типов не выполняет преобразование: его реализует тело setter.

Нужно определить поведение для неподходящей числовой строки и NaN, а не полагаться только на number.

#### Пример

```typescript
class Size {
  private stored = 0
  get value(): number {
    return this.stored
  }
  set value(input: string | number) {
    const next = Number(input)
    if (!Number.isFinite(next)) throw new Error("Invalid size")
    this.stored = next
  }
}
```

#### Разбор примера

Setter Size превращает вход в `number` и проверяет конечность до сохранения. Getter затем всегда читает нормализованное число. При этом пустая строка преобразуется в ноль: если она недопустима по требованиям, проверку нужно усилить отдельно от типовой аннотации `string` | number.

#### Типичная ошибка

> Считать аннотацию setter автоматической конвертацией входа.
