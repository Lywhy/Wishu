**Абстрактный класс может содержать реализованные члены и абстрактные требования.** TypeScript запрещает непосредственно создавать его через new; конкретный наследник должен реализовать необходимые абстрактные члены. Это помогает совместить общий код с обязательным контрактом.

#### Как это работает

`interface` обычно полностью удаляется и не предоставляет реализации, а класс остаётся runtime-значением. `abstract` - типовое ограничение, не самостоятельный универсальный запрет new для непроверенного JavaScript. Наследование стоит выбирать, когда действительно нужна общая модель, а не только совпадающая форма данных.

#### Пример

```typescript
abstract class Formatter {
  abstract format(value: number): string
  label(value: number): string {
    return `Значение: ${this.format(value)}`
  }
}
class DecimalFormatter extends Formatter {
  format(value: number): string {
    return value.toFixed(2)
  }
}
```

#### Разбор примера

Formatter предоставляет готовый label, который вызывает обязательный format. DecimalFormatter реализует недостающий шаг, поэтому может использовать общее поведение. Если нужна только форма внешнего объекта без общего кода, интерфейс выразит её проще и без runtime-базового класса.
