**Поддерживающий package exports режим разрешения выбирает ветвь по доступным условиям и формату обращения. Декларации должны соответствовать именно выбранной runtime-точке входа.**

<!-- wishu:answer-block -->

#### Как это работает

Порядок и структура conditions имеют значение; не заменяйте проверку реального потребителя чтением одного поля types. `typesVersions` и exports не являются двумя независимыми слоями, которые всегда применяются последовательно: выбранный алгоритм может изменить использование этих полей.

Проверяйте ESM/CJS-потребителей и поддерживаемые версии, а не только импорт внутри монорепозитория.

#### Пример

```json
{
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./dist/index.js"
    }
  }
}
```

#### Разбор примера

В показанной ветви types ведёт к декларации, а default к исполняемому входу. Оба файла должны описывать один публичный модуль и подходящий формат. Если ESM и CJS имеют разные входы, эту структуру нужно проектировать под оба потребителя, а не считать пример универсальным шаблоном.

#### Типичная ошибка

> Думать, что поле types всегда перекрывает все условия exports.
