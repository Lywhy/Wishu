Параметр типа у `request<T>()` сам не проверяет серверный ответ. Более честный API принимает parser из `unknown` в T: результат становится T только после успешной проверки.

#### Как это работает

Generic связывает возвращаемый тип с переданной функцией проверки. Сам parser должен быть корректен: компилятор не доказывает правдивость вручную написанного утверждения или предиката. Можно использовать runtime-схему, из которой выводится тип, чтобы уменьшить расхождение схемы и аннотации.

Отдельно обрабатывайте HTTP-ошибку, синтаксис JSON и несоответствие структуры. Эти ошибки возникают на разных границах. Смена контракта сервера не становится безопасной только из-за совпадения имени интерфейса в клиенте.

#### Пример

```typescript
async function request<T>(url: string, parse: (value: unknown) => T): Promise<T> {
  const response = await fetch(url)
  if (!response.ok) throw new Error("HTTP " + response.status)
  const raw: unknown = await response.json()
  return parse(raw)
}
// Тип результата определяется parse, а не произвольным as T внутри request.
```

#### Разбор примера

Request получает сырые данные как `unknown` и возвращает только результат parse. Поэтому выбранный валидатор определяет и проверку, и успешный тип T. Отказ HTTP обрабатывается до разбора JSON, а нарушение структуры возникает на следующей границе; их полезно различать при диагностике.

#### Типичная ошибка

> Писать `return` response.json() as `Promise<T>` и называть это типобезопасным API-клиентом.
