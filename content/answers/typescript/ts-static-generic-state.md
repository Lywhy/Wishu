**Подстановки generic-класса не создают отдельный JavaScript-конструктор для каждого T. Статическое состояние общее для значения класса, поэтому параметр экземпляра нельзя произвольно использовать как тип отдельного static-хранилища.**

<!-- wishu:answer-block -->

#### Как это работает

Если состояние зависит от T, храните его на экземпляре или создайте специализированный контейнер через фабрику. Статический generic-метод может объявить собственный параметр типа.

Не рассчитывайте на автоматический отдельный кеш для `Box<string>` и `Box<number>`.

#### Пример

```typescript
class Box<T> {
  constructor(public value: T) {}
  static of<U>(value: U): Box<U> {
    return new Box(value)
  }
}
const item = Box.of(1)
```

#### Разбор примера

Of вводит собственный U для каждого вызова и возвращает `Box<U>`. Это допустимо, потому что статический метод не заимствует неизвестный параметр экземпляра T. Само значение Box остаётся одним конструктором, независимо от количества его типовых специализаций.

#### Типичная ошибка

> Объяснять generic-класс как отдельный сгенерированный класс на каждый тип.
