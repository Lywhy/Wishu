Union двух объектов сам по себе не всегда запрещает объект, содержащий оба набора полей. Добавьте в каждый вариант альтернативное свойство с типом `never`, чтобы несовместимое сочетание стало явно недопустимым.

#### Как это работает

Такой контракт подходит для выбора ровно одного источника данных: id либо готовый объект, URL либо содержимое. Сначала уточните, должен ли разрешаться вариант без обоих параметров.

`prop?: never` означает запрещённую запись с учётом правил optional-свойств. Без `exactOptionalPropertyTypes` явное `undefined` имеет дополнительные послабления; при включённом флаге отсутствие отделяется от записи undefined. Это статическая модель конфигурации, а внешние данные всё равно нужно проверить.

#### Пример

```typescript
type User = { id: string; name: string }
type Source = { id: string; user?: never } | { user: User; id?: never }

const byId: Source = { id: "u1" }
const byUser: Source = { user: { id: "u1", name: "Анна" } }
// { id: 'u1', user: { id: 'u1', name: 'Анна' } } не соответствует Source.
```

#### Разбор примера

ById выбирает ветвь с обязательным id и запрещённым user, а byUser другую ветвь с обратными требованиями. Поэтому объект с обоими значениями не удовлетворяет ни одной форме. Для внешнего ввода это правило нужно также проверить в runtime, а не только выразить в Source.

#### Типичная ошибка

> Объявить оба параметра optional и ожидать, что checker сам выберет бизнес-правило.
