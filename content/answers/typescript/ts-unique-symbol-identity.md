**Unique `symbol` описывает идентичность конкретного символа, а не любого значения Symbol. Его можно использовать как отдельный ключ и как часть номинально различимого контракта.**

<!-- wishu:answer-block -->

#### Как это работает

Ссылка на такой тип обычно записывается через `typeof` конкретного const-символа. Разные символы не становятся одним ключом из-за одинакового описания.

Объявление `declare const` описывает наличие значения, но не создаёт его в runtime. Для настоящего доступа нужен реальный символ.

#### Пример

```typescript
const id = Symbol("id")
type Entity = { [id]: string }
const entity: Entity = { [id]: "u1" }
type IdKey = typeof id
```

#### Разбор примера

Entity использует именно символ id как ключ, поэтому для создания и чтения записи нужна та же идентичность. Новый `symbol` с тем же описанием не обозначил бы это поле. `typeof` id сохраняет конкретный ключ на уровне типов и не создаёт ещё один символ.

#### Типичная ошибка

> Создавать новый `symbol`("id") при каждом чтении и ожидать прежний ключ.
