`object` исключает примитивы. Тип `{}` при `strictNullChecks` допускает любое значение, кроме `null` и `undefined`, включая строки и числа. `Object` описывает общий объектный интерфейс и обычно тоже слишком широк для прикладного контракта.

#### Что выбрать

- Нужен непроверенный вход: `unknown`.
- Нужны конкретные поля: опишите их явно.
- Нужен словарь: определите тип ключей и значений, например `Record<string, unknown>`. Это отдельный контракт, а не универсальный синоним любого объекта.

Пустой объектный тип не означает «объект без свойств». Структурная типизация не задаёт точную форму только отсутствием объявленных полей.

#### Пример

```typescript
const a: {} = 42 // Допустимо при strictNullChecks
const b: object = { name: "Анна" }
// const c: object = 42 // Ошибка: примитив
// const d: {} = null // Ошибка при strictNullChecks
```

#### Разбор примера

Число 42 подходит типу {}, хотя примитив не является допустимым object. Значит, название «пустой объект» вводит в заблуждение: этот тип не требует отсутствия полей. Для функции, которая читает name, нужен контракт с name, а для неизвестного ввода безопаснее начать с unknown.

#### Типичная ошибка

> Использовать {} как универсальный безопасный тип объекта или замену unknown.
