**`void` у функции обычно выражает, что вызывающая сторона не должна использовать её результат.** Это отличается от обещания конкретного значения `undefined` и от `never`. При явном объявлении function f(): `void` нельзя вернуть обычное полезное значение вроде числа.

#### Как это работает

Но функция, возвращающая число, может быть присвоена ожидаемому типу () => `void`: результат просто игнорируется в этом контракте. Так callback `forEach` может вызывать `push`, который возвращает длину. `void` не преобразует runtime-значение в `undefined`; он описывает допустимое использование статического результата.

#### `void` не означает ожидание асинхронной работы

Контекст, игнорирующий возвращаемое значение callback, может принять и `async`-функцию. Но вызывающая сторона не начнёт автоматически ожидать её Promise. Необработанное отклонение останется runtime-проблемой. Если ожидается завершение работы, контракт и реализация должны явно учитывать Promise. Для fire-and-forget нужен осмысленный обработчик ошибки, а не один оператор void.

#### Пример

```typescript
const values: number[] = []
const add: (value: number) => void = (value) => values.push(value)
const result = add(1) // статический тип void
// Реальный callback вернул результат push, но контракт add его не предоставляет.
```

#### Разбор примера

`push` действительно возвращает новую длину, однако ссылка add описана как функция с неиспользуемым результатом. Поэтому result имеет статический тип `void`, хотя само JavaScript-значение не было специально преобразовано. Важен контракт вызывающей стороны: она не должна строить дальнейшую логику на этом скрытом результате.
