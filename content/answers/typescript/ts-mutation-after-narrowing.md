**Да. TypeScript не выполняет полный анализ всех побочных эффектов произвольного вызова. Проверенное свойство может измениться через другую ссылку, хотя локальное сужение ещё выглядит допустимым.**

<!-- wishu:answer-block -->

#### Как это работает

Одна функция может удалить optional-поле или заменить его значение. Сохранение проверенного примитива в локальную const-переменную помогает, если последующая работа должна использовать именно этот снимок.

`readonly`-контракты полезны для ограничения операций, но не являются универсальной защитой от чужих aliases.

#### Пример

```typescript
type Box = { value?: string }
function clear(box: Box) {
  delete box.value
}
function use(box: Box) {
  if (box.value !== undefined) {
    const text = box.value
    clear(box)
    // box.value.toUpperCase() // Может обратиться к удалённому полю.
    return text.toUpperCase() // Сохранили проверенный примитив.
  }
}
```

#### Разбор примера

Clear удаляет поле через ту же ссылку, поэтому повторное чтение box.value уже не эквивалентно проверенному. Локальная text сохраняет прежний строковый примитив и остаётся пригодной для использования. Это решение подходит, если алгоритму нужен снимок, а не актуальное поле после мутации.

#### Типичная ошибка

> Считать зелёную типизацию доказательством отсутствия побочных мутаций.
