**Найдите, какой тип требуется и какой передан, затем двигайтесь к первому содержательному несовпадению внутри структуры. Внешняя generic-обёртка часто только показывает путь к реальной причине.**

#### Как это работает

Проверьте nullability, optional, `readonly`, конкретное поле и вход/выход callback. Сведите пример к минимальной форме, сохранив версию и существенные параметры проверки.

Не добавляйте двойной as до выяснения, ошибочны данные, модель или публичный контракт.

#### Пример

```typescript
type User = { lastSeen: Date }
const dto = { lastSeen: "2026-01-01" }
// const user: User = dto // Причина: string не является Date.
const user: User = { lastSeen: new Date(dto.lastSeen) }
```

#### Разбор примера

У dto нужное имя lastSeen уже есть, но его значение является строкой, а не Date. Создание new Date исправляет представление; для внешних данных дополнительно проверяют допустимость самой даты. Двойной assertion сохранил бы исходную строку и только спрятал содержательную причину несовместимости.
