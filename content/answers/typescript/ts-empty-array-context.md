**У пустого литерала нет элементов, из которых можно вывести нужный предметный тип. В частности, при строгой конфигурации поле объекта без другого контекста может получить `never`[].**

<!-- wishu:answer-block -->

#### Как это работает

Поведение отдельно объявленного изменяемого массива и массива в поле объекта не обязано совпадать: вывод может использовать разные правила. Задавайте тип состояния или контейнера на границе создания. Это полезнее последующих as и any.

Не выводите универсальное правило «любой [] - `never`[]»: важны контекст и настройки проверки.

#### Пример

```typescript
type State = { items: string[] }
const state: State = { items: [] }
state.items.push("first")
// Без State у поля items может не быть контекста для string.
```

#### Разбор примера

Аннотация State задаёт тип элемента ещё до добавления первой строки. `push` поэтому проверяется относительно `string`, хотя начальный массив пуст. Это подходящее место для контракта состояния: позднее утверждение типа только замаскировало бы недостаток информации при его создании.

#### Типичная ошибка

> Исправлять вывод пустого массива через `any`[] без понимания модели.
