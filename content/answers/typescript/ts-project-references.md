Project `references` задают зависимости между отдельными TypeScript-проектами. В режиме build компилятор обходит граф, учитывает порядок и актуальность результатов вместо повторной обработки всего как одного бесформенного проекта.

#### Как это работает

Ссылаемые проекты используют composite и соответствуют его ограничениям, включая явный состав входных файлов и выпуск деклараций. Инкрементальная информация позволяет сокращать повторную работу. Настройки конкретного emit нужно согласовать с ролью проекта в графе.

`references` не являются npm-зависимостями, настройкой runtime-alias или заменой exports пакета. Кроме того, `extends` наследует конфигурацию, а `references` описывают другой вид связи: граф сборки.

Пример корневого tsconfig, дочерние проекты настраиваются отдельно:

```json
{
  "files": [],
  "references": [
    {
      "path": "./packages/core"
    },
    {
      "path": "./packages/app"
    }
  ]
}
```

#### Разбор примера

Пустой `files` у корневого решения оставляет ему роль координатора, а `references` перечисляет дочерние проекты. Зависимость app от core должна быть отражена и в их собственном графе. Один порядок записей корня не заменяет объявление реальных зависимостей и настройку публикации пакетов.

#### Типичная ошибка

> Ожидать, что ссылка на tsconfig автоматически настроит package.json и runtime-импорты.
