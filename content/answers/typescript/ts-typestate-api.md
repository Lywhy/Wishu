Представьте разные состояния разными контрактами: метод перехода возвращает интерфейс следующего состояния, где доступны только допустимые операции. Так тип проверяет порядок действий у типизированного потребителя.

#### Как это работает

Это называют typestate-подходом. Он полезен для небольшого числа важных переходов, например настроить соединение перед отправкой. Возврат `this` сам по себе такого порядка не задаёт: все методы могут оставаться доступными сразу.

Реализация всё равно должна обеспечивать инварианты в runtime, особенно при работе из JavaScript или через any. Не размножайте состояния ради несущественных комбинаций: слишком сложный builder ухудшает диагностику и сопровождение.

#### Пример

```typescript
interface Draft {
  connect(url: string): Connected
}
interface Connected {
  send(message: string): Promise<void>
}
declare const client: Draft
const connected = client.connect("https://example.com")
connected.send("hello")
// client.send('hello') // Метод недоступен до перехода в Connected.
```

#### Разбор примера

Client в состоянии Draft предоставляет только connect. Возвращённый Connected открывает send, поэтому типизированный код не может вызвать его до перехода. `declare` здесь описывает существующий API, а не реализует подключение; фактический клиент должен сам обеспечивать такой порядок и обрабатывать сбои соединения.

#### Типичная ошибка

> Считать сложный fluent builder с возвращаемым `this` проверкой всех бизнес-переходов.
