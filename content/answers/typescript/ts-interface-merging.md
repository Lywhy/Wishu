**Совместимые объявления `interface` одного имени в одной области объединяются в общий контракт.** Это позволяет расширять некоторые библиотечные декларации без изменения исходного файла. Одноимённые нефункциональные свойства должны иметь согласованные типы; нельзя произвольно заменить чужое поле новым типом.

#### Как это работает

Функциональные сигнатуры могут образовать перегрузки со своими правилами порядка. Слияние не добавляет runtime-свойства и не исправляет отсутствующую реализацию. Type aliases с одним именем так не объединяются. Для модулей и глобальных расширений важно правильно выбрать область объявления.

#### Пример

```typescript
interface Preferences {
  theme: string
}
interface Preferences {
  language: string
}
const value: Preferences = { theme: "dark", language: "ru" }
// Это единый контракт с обоими полями, а не два разных объекта.
```

#### Разбор примера

Оба объявления Preferences описывают одну итоговую форму, поэтому value обязан содержать и theme, и language. Повторное объявление не выбирает одну из версий и не подставляет отсутствующее поле. Это особенно важно при расширении библиотек: реализация должна действительно поддерживать заявленные возможности.
