**`public` доступен снаружи и используется по умолчанию.** `protected` ограничивает доступ кодом класса и наследников с дополнительными правилами совместимости. `private` TypeScript ограничивает доступ рамками класса при статической проверке и влияет на совместимость типов.

#### Как это работает

Обычный `private`-модификатор TypeScript не создаёт ту же runtime-приватность, что #поле JavaScript: после удаления типов данные могут оставаться обычными свойствами. # использует отдельный механизм языка. Эти варианты не следует смешивать с `readonly`, который ограничивает запись, а не определяет круг читающего кода.

#### Происхождение `private`-членов

Два независимо объявленных класса с одинаково названным `private`-членом не становятся совместимыми только из-за одинаковой видимой формы. Наследник сохраняет происхождение члена базы; это важное исключение из упрощённого объяснения структурной модели.

```typescript
class A {
  private tag = 0
  read() {
    return this.tag
  }
}
class B {
  private tag = 0
  read() {
    return this.tag
  }
}
// const item: A = new B() // Разное происхождение private tag.
```

#### Пример

```typescript
class Account {
  public name = "гость"
  protected role = "reader"
  private internalCode = "example"
  #secret = 1
  describe(): string {
    return `${this.name}:${this.#secret}`
  }
}
// private и # проверяются разными механизмами.
```

#### Разбор примера

Account сочетает несколько независимых механизмов: name открыт, role предназначен наследникам, internalCode закрыт статической проверкой, а #secret защищается JavaScript. Describe получает доступ к приватному элементу из допустимой области. Удаление TypeScript-аннотаций не превращает обычный `private` в #.
