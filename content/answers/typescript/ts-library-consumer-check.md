**Проверяйте опубликованные файлы и публичные entrypoints из независимого проекта. Это выявляет проблемы, которые могут скрываться общими aliases, исходниками и зависимостями монорепозитория.**

<!-- wishu:answer-block -->

#### Как это работает

Нужны допустимые вызовы, ожидаемые ошибки и проверка runtime-экспортов. Выберите целевые ESM/CJS-режимы и версии TypeScript по заявленной поддержке библиотеки.

Source import из соседней папки не является достаточной проверкой реально поставляемого пакета.

#### Пример

```typescript
// Пример структуры проверки, без выполнения:
// consumer/ package.json -> устанавливаемая поставка библиотеки
// consumer/index.ts -> import из публичного имени пакета
// consumer/tsconfig.json -> заявленный режим потребителя
```

#### Разбор примера

Отдельный consumer импортирует публичное имя пакета и видит только поставляемые файлы. Поэтому он обнаруживает зависимость декларации от скрытого alias или внутреннего workspace-пути. Проверка исходников внутри монорепозитория могла бы случайно предоставить эти недоступные обычному пользователю зависимости.

#### Типичная ошибка

> Считать локальный workspace-import полной проверкой публикации.
