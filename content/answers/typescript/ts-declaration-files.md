Файл .d.ts описывает существующий JavaScript API для checker и редактора. Реализация может поставляться вместе с пакетом, а декларации - внутри пакета, в @types или в локальном объявлении.

<!-- wishu:answer-block -->

При отсутствии типов сначала проверьте собственные декларации пакета и подходящий пакет @types. Локальный shim полезен для небольшого реально известного API, но его точность становится вашей ответственностью.

Короткое `declare module "library";` фактически скрывает контракт за any. Ambient-объявление с экспортами позволяет описать нужную поверхность точнее. Оно не устанавливает пакет и не создаёт его реализацию. Для расширения уже типизированного модуля важен корректный модульный контекст, иначе можно случайно объявить новый контракт вместо augmentation.
