Стандартные поля класса определяются как собственные свойства, а историческое преобразование TypeScript могло использовать присваивания. Это различие влияет на унаследованные setter и повторное объявление полей.

<!-- wishu:answer-block -->

#### Как это работает

При define-семантике поле без инициализатора тоже может создать собственное свойство со значением `undefined` и затереть значение после super. Поэтому аннотация поля в наследнике не всегда является только безобидным уточнением типа: смотрите на emit и target.

Если нужен только типовой контракт без нового runtime-поля, применяют `declare` в подходящем объявлении. Это не инициализация и не доказательство истинности уточнённого типа. Поведение определяется используемым компилятором или транспилятором; конфигурацию emit необходимо согласовать между инструментами.

#### Пример

```typescript
class Model {
  value: string | undefined = "значение родителя"
}
class View extends Model {
  declare value: string | undefined // Не создаёт нового runtime-поля.
}
// Сравнивайте emit без declare только при явно выбранных target
// и useDefineForClassFields: это может быть другое runtime-поведение.
```

#### Разбор примера

`declare` в View уточняет видимое поле, не создавая нового собственного значения после конструктора Model. Поэтому оно не должно затирать родительскую инициализацию. Без `declare` подходящий emit поля может изменить поведение, и сравнение требует явных `target` и useDefineForClassFields.

#### Типичная ошибка

> Считать любое объявление свойства в наследнике полностью стираемой аннотацией.
