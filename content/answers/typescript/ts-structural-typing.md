**При структурной проверке важен подходящий набор членов и их типов, а не совпадение названия объявления.** Объект с дополнительными полями может соответствовать более узкому контракту. Номинальная модель обычно связывает совместимость с именем или происхождением типа.

- Для свежих объектных литералов есть дополнительные проверки лишних свойств, поэтому присваивание литерала и уже существующей переменной может вести себя по-разному. Private и protected у классов добавляют ограничения происхождения членов. Поэтому фраза «любые одинаковые объекты всегда совместимы» слишком широка. Бренды позволяют моделировать дополнительное различие, но не валидируют данные автоматически.

### Свежий литерал и уже созданное значение
Дополнительная проверка лишних свойств помогает находить опечатки при передаче свежего объектного литерала. Она не превращает структурный тип в точный закрытый объект. Передача ранее созданной переменной может быть допустима, хотя та содержит дополнительные данные. Сохранение объекта в переменную не удаляет поля и не является способом безопасной сериализации.

```typescript
function greet(value: { name: string }) { return value.name }
const full = { name: "Анна", debug: true }
greet(full) // Структурно совместим.
// greet({ name: "Анна", debug: true }) // Лишнее поле свежего литерала.
```
