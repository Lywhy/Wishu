DeepReadonly рекурсивно запрещает запись через полученный тип. Сначала нужно определить поддерживаемые данные: обычные объекты, массивы и кортежи нельзя без объяснения приравнивать к Date, `map`, Set или функциям.

#### Как это работает

Для простых данных mapped type рекурсивно сохраняет ключи и добавляет readonly. Массивы и кортежи обрабатываются по правилам соответствующего mapped-преобразования. Примитивы можно оставить без изменения.

Универсальная версия требует отдельных ветвей для специальных контейнеров и стратегии ограничения глубины. Она не вызывает `Object.freeze`, не уничтожает изменяемые alias и не делает runtime-граф ацикличным. В примере контракт намеренно ограничен простыми данными без специальных экземпляров.

#### Пример

```typescript
type DeepReadonlyData<T> = T extends object
  ? { readonly [K in keyof T]: DeepReadonlyData<T[K]> }
  : T

type Model = DeepReadonlyData<{
  user: { name: string }
  tags: string[]
}>
// Только простые данные: Date, Map, Set и функции сюда не входят.
```

#### Разбор примера

Model запрещает запись name и мутации tags через полученный контракт простых данных. Ветка для object продолжает преобразование вложенных полей. Если передать `map` или функцию, похожий обход свойств уже не обязательно выразит нужное поведение, поэтому ограничения helper являются частью его корректности.

#### Типичная ошибка

> Считать любой рекурсивный mapped type корректной глубокой защитой всех JavaScript-объектов.
