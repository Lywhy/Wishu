**Нельзя предполагать универсальное частичное заполнение списка параметров типа. Если API неудобно специализируется, можно разделить выбор типов на два вызова или изменить источник вывода.**

<!-- wishu:answer-block -->

#### Как это работает

Параметры без defaults обычно требуют полного подходящего списка при явном задании. Default - конкретное правило выбора, а не обещание, что пропущенная позиция всегда выведется так, как при полностью неявном вызове.

Фабрика позволяет зафиксировать один тип снаружи и вывести другой при вызове возвращённой функции.

#### Пример

```typescript
const withError =
  <E>() =>
  <T>(value: T) => ({ value, error: null as E | null })
const result = withError<Error>()(123)
// T выбран по аргументу второго вызова.
```

#### Разбор примера

Первый вызов withError фиксирует E, а второй получает новый собственный T из значения 123. Разделение создаёт две реальные точки выбора типов. Это не специальный синтаксис пропущенного аргумента: API намеренно переносит оставшийся вывод в возвращаемую функцию.

#### Типичная ошибка

> Путать default параметра типа с произвольной дыркой для вывода.
