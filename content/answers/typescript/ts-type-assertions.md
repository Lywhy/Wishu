**As просит компилятор рассматривать значение как указанный совместимый с правилами assertion тип.** Это не конвертация и не runtime-валидация. Assertion иногда нужен при дополнительном знании внешнего контракта, которое инструмент не может вывести, но правильность этого знания остаётся ответственностью автора.

#### Как это работает

Двойное приведение через `unknown` способно обойти многие ограничения, но не делает данные правильными. Non-`null` assertion ! также ничего не проверяет. Если форму можно установить проверкой, guard или схемой, это надёжнее слепого as. При реальном преобразовании числа нужна `number`(value), а не value as number.

#### Пример

```typescript
function unsafeLabel(value: unknown): string {
  return (value as { name: string }).name
}
// Пример намеренно показывает риск: значение не проверено.
// Для безопасной границы нужны реальные проверки формы.
```

#### Разбор примера

UnsafeLabel разрешает доступ к name только в представлении checker. Вызов с `null` способен выбросить ошибку, а объект без name может вернуть `undefined` вопреки обещанному string. Аннотация результата и assertion не добавляют проверку, которая исправила бы эти реальные пути.
