**Mixin-фабрика принимает подходящий конструктор и возвращает класс, расширяющий его возможностями. Важен тип конструктора, а не только интерфейс уже созданного экземпляра.**

<!-- wishu:answer-block -->

#### Как это работает

Ограничение описывает, какие экземпляры можно расширять; не обещайте совместимость любого exotic-конструктора. Нужно учитывать передачу аргументов, поля и ограничения `private`/`protected` в выбранном паттерне.

Если наследование не нужно, композиция объектов может дать более простой проверяемый контракт. `any`[] в типичном ограничении mixin-конструктора - технический паттерн сигнатуры rest; это не повод терять точные типы всего публичного API.

#### Пример

```typescript
type Constructor<T = object> = new (...args: any[]) => T
function Named<TBase extends Constructor>(Base: TBase) {
  return class extends Base {
    name = "item"
  }
}
const Item = Named(
  class {
    id = 1
  },
)
const value = new Item() // id и name
```

#### Разбор примера

Named возвращает настоящий подкласс переданного Base. Поэтому новый Item объединяет id исходного класса и name добавленного слоя. Ограничение принимает конструктор, поскольку фабрика должна наследовать его поведение; один интерфейс экземпляра не дал бы такой runtime-возможности.

#### Типичная ошибка

> Путать mixin-фабрику с копированием произвольных методов через Object.assign.
