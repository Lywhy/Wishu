**`any` разрешает многие операции без доказательства и распространяет потерю информации дальше по программе.** `unknown` принимает любое значение, но не позволяет произвольно читать свойства или вызывать его без проверки. Для непроверенных входных данных `unknown` обычно честнее отражает контракт.

#### Как это работает

Narrowing, проверенный type guard или runtime-схема превращают неизвестное значение в пригодное для использования. `any` иногда нужен на временной границе миграции или несовместимой библиотеки, но его стоит локализовать и документировать. Явное `any` не запрещается одним `noImplicitAny`: эта настройка прежде всего обнаруживает неявное отсутствие типа.

#### Пример

```typescript
function format(value: unknown): string {
  if (typeof value === "string") return value.trim()
  return ""
}
// Вызов value.trim() без проверки для unknown не проходит проверку типов.
```

#### Разбор примера

Format не обещает, что любой вход является строкой. Она сначала проверяет это предположение и лишь затем вызывает trim. При `any` такой вызов был бы разрешён сразу, но ошибка могла бы проявиться на числе или null. `unknown` сохраняет необходимость доказательства на границе, не мешая принимать произвольные данные.

#### Типичная ошибка

> Считать, что приведение as проверяет внешние данные во время выполнения. Оно меняет представление типов для компилятора, а не валидирует значение.
