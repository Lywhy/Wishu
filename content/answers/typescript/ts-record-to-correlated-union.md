**Сначала создайте для каждого ключа отдельный объект с соответствующим типом значения, затем извлеките union этих объектов. Так связь не превращается в два независимых объединения.**

<!-- wishu:answer-block -->

#### Как это работает

`key: keyof T; value: T[keyof T]` допускает смешивание ключа одного поля со значением другого. Промежуточный mapped type сохраняет корреляцию в каждом свойстве.

После получения union для удобного использования полезна обязательная метка, по которой можно сузить вариант. Для optional-полей отдельно выберите политику `undefined`: -? убирает необязательность промежуточной записи, но не обязан исключить `undefined` из самого T[K].

#### Пример

```typescript
type Change<T> = {
  [K in keyof T]-?: { key: K; value: T[K] }
}[keyof T]
type UserChange = Change<{ name: string; age: number }>
// {key:"name";value:string} | {key:"age";value:number}
```

#### Разбор примера

Mapped type сначала создаёт отдельную запись для name и отдельную для age. Последующее индексирование извлекает их union, поэтому строковое имя связано со строковым значением, а возраст с числом. Два независимых union позволили бы ошибочно соединить key name и числовой value.

#### Типичная ошибка

> Описывать пару независимыми объединениями и ожидать взаимной проверки.
