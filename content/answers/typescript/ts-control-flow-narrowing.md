**Narrowing уточняет статический тип в точке программы по проверкам и путям выполнения.** Typeof различает подходящие примитивы, instanceof проверяет runtime-цепочку конструктора, равенство помогает исключить конкретные варианты. После return из одной ветви оставшийся код тоже может получить более узкий тип.

- In проверяет свойство вместе с прототипами. Optional-свойство может присутствовать в обеих ветвях сужения, поэтому это не универсальное доказательство конкретного варианта. Truthy-проверка отбрасывает и допустимые 0 или пустую строку. Компилятор следует известным ему правилам, но не выполняет проверку внешних данных вместо вашего кода.

### Что именно доказано проверкой
Narrowing относится к определённой точке программы. Новое присваивание может снова изменить текущий тип, оставаясь в рамках объявленного union. Проверка in учитывает прототипную цепочку; optional-свойство не делает вариант исключительным для ветви true или false. Для discriminated union выбирайте обязательную литеральную метку.

При проверке внешнего объекта начинайте с защиты от null и неподходящего typeof, затем проверяйте форму. Ни совпадение имени свойства, ни truthy-проверка сами по себе не доказывают полный бизнес-контракт.
