**Runtime-тест подтверждает выполнение, а типовой пример - принятие или отклонение кода выбранным checker и конфигурацией. Для библиотеки нужны оба слоя проверки.**

#### Как это работает

Положительные примеры фиксируют вывод результата и допустимые вызовы. Отрицательные примеры с @ts-expect-error должны соответствовать конкретному запрету; посторонняя ошибка на строке может замаскировать изменение контракта.

Фиксируйте версию и настройки. Улучшение вывода в новой версии способно изменить ожидания без изменения runtime.

#### Пример

```typescript
function acceptsId(id: string) {
  return id
}
acceptsId("u1")
// @ts-expect-error: числовой ID не входит в контракт
acceptsId(1)
// Это пример для проверки пользователем, здесь он не запускался.
```

#### Разбор примера

Строковый вызов демонстрирует допустимый вход, а числовой помечен как ожидаемое нарушение. Если функция случайно начнёт принимать `number`, неиспользованный expect-error поможет обнаружить изменение. Однако посторонняя ошибка на той же строке тоже может удовлетворить директиву, поэтому отрицательный пример должен быть минимальным.

#### Типичная ошибка

> Считать успешный runtime-тест доказательством правильного generic-вывода.
