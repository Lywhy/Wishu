**Интерфейсное значение содержит динамический тип и значение. Оно равно `nil`, когда отсутствуют оба; указатель `nil` внутри известного динамического типа этого не обеспечивает.**

<!-- wishu:answer-block -->

#### Как это работает

Это часто проявляется при возврате error: типизированный `nil`-указатель, преобразованный к error, остаётся ненулевым интерфейсом. На успешном пути возвращают непосредственно nil. Возможность вызвать метод на `nil` receiver зависит от реализации метода и не означает, что интерфейс пустой.

#### Пример

```go
type MyError struct{}
func (*MyError) Error() string { return "ошибка" }
var pointer *MyError
var err error = pointer
fmt.Println(pointer == nil, err == nil) // true false
```

#### Разбор примера

В err записан динамический тип *MyError и `nil`-значение этого типа. Сравнение с `nil` учитывает устройство интерфейса, а не только адрес внутри него. Для печати нужен импорт fmt.

#### Типичная ошибка

> Вернуть переменную типа *MyError со значением `nil` как error и считать успешный исход пустым интерфейсом.
