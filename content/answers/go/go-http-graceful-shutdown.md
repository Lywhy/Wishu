**Server.Shutdown прекращает приём новых соединений и ждёт завершения подходящих активных запросов с ограничением через Context.**

<!-- wishu:answer-block -->

#### Как это работает

Процесс должен дождаться окончания `Shutdown`, а не выйти сразу после возврата `ListenAndServe` с ErrServerClosed. Для WebSocket и других hijacked-соединений нужна отдельная координация. По истечении deadline приложение выбирает дальнейшую политику и закрывает собственные фоновые ресурсы; `Shutdown` не откатывает выполненные бизнес-операции.

#### Пример

```go
// Вызывается владельцем процесса после сигнала остановки.
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
if err := server.Shutdown(ctx); err != nil {
    log.Printf("shutdown: %v", err)
}
// Главная горутина дожидается этого шага и завершения фоновых работников.
```

#### Разбор примера

Пятисекундный deadline ограничивает ожидание. Обработчики и собственные зависимости должны поддерживать завершение, иначе одного вызова `Shutdown` недостаточно. Повторно запускать тот же Server после `Shutdown` нельзя.

#### Типичная ошибка

> Завершить main немедленно, не дождавшись процедуры остановки, либо забыть долгоживущие соединения.
