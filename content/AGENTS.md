# Контент

Перед изменением вопросов читать docs/content-editor-rules.md из корня. Команды content:* разрешены агенту; приложение, Docker, миграции, seed, проверки UI/сервера и примеры не запускать.

- Начинать с компактного content:find/context. Читать полный ответ только для изменяемого/сравниваемого ID.
- Источники: questions/<section>/<subsection>.json и answers/<section>/<id>.md. Generated и серверный seed отдельно не редактировать.
- Сначала учебные цели и пересечения, затем ответы. ID сохранять; близость слов не доказывает дубль.
- Sources брать из references/sources.json через sourceRefs; общие оговорки держать на уровне темы. Спорные версии перепроверять.
- Текущий пакет хранить в batches: рабочие ID, хеши, решения и следующие действия. Ответы и историю чата туда не копировать.
- Неизменённые материалы повторно не анализировать; перед каждой правкой читать актуальный файл. Изменённый файл перечитать.
- После форматирования собрать контент и выполнить полную content:check. Частичная проверка её не заменяет.

Процесс: docs/lean-content-workflow.md. Расширенные форматы: docs/content-workflow-v2.md. Профили, примеры, пересечения и версии: preparation/catalog.json; данные собеседований добавлять только по реальным наблюдениям.
