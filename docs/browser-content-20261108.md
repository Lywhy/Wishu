## Учебные границы и пересечения

Первый проход зафиксировал согласованную карту, исходные 12 ID и границы с JavaScript и HTML/CSS. Второй проход добавил ответы, сценарии, источники и связи. Основной объём посвящён базе и прикладным сценариям среднего уровня; продвинутые вопросы касаются изоляции, partitioning, конкурентных изменений, атак на кеш, HTTP/3, bfcache, потоков и конфликтов версий.

В JavaScript остаются канонические объяснения event loop, Fetch API, AbortController, Web Storage, IndexedDB, Workers, WebSocket и Service Worker. В HTML/CSS остаются канонические темы загрузки скриптов, resource hints, шрифтов и операций макета. Здесь добавлены границы браузерной платформы, сетевые условия и диагностика; связанные карточки закрепляются ссылками с действующими названиями.

Близкие пункты объединены по навыкам: методы HTTP рассматриваются по контракту операции; основные статусы - по семействам и сценариям успеха/ошибок; cookie-флаги остаются в одном исходном ответе. Общий вопрос Cache-Control/ETag сохранён, а отдельные сценарии валидации, ключа Vary, общего кеша и деплоя проверяют применение разных правил. Идемпотентность метода не объединена с ключом повторной бизнес-операции: это разные гарантии. Storage partitioning и third-party cookie также не объявлены одним механизмом.

Физического слияния или удаления существующих вопросов нет. Число карточек и ready/covered не являются гарантией подготовки ко всем собеседованиям.

## Оформление и источники

Ответ содержит короткий вывод, механизм и границы, конкретный сценарий, типичную ошибку, источники и, где полезно, ссылки для закрепления. Технические обозначения выделены inline-кодом. В 22 ответах добавлены блоки HTTP, JavaScript, HTML или схемы данных; остальные используют содержательные сценарии без искусственного кода. Отдельные поля code/pitfall не дублируют Markdown.

Источники зарегистрированы в content/references/sources.json на уровне подраздела и подключены через sourceRefs. Использованы HTTP RFC, MDN, Chromium, web.dev, Chrome DevTools, OWASP и первичные исследования PortSwigger. checkedAt отражает проверку конкретного URL в этом проходе. Поддержка privacy-механизмов, bfcache, изоляции и Web API оговорена без обещаний единого поведения всех браузеров.
