# Быстрая работа над проектом

Начинать с [карты проекта](project-map.md) и [шаблона доработки](development-recipes.md), затем открывать только файлы выбранной области. Контентные команды ниже разрешены агенту с 2026-11-07. Проверки UI/сервера, lint, приложение, Docker и seed запускает пользователь. Это инфраструктура подготовки и проверки; производительность самого сайта в этой задаче не измерялась и не менялась.

## Создание вопроса одной командой

Из корня проекта:

```sh
pnpm content:new -- --section javascript --subsection functions --title "Как определить границы кеша функции?"
```

Команда подбирает свободный order, формирует ID из раздела и названия, добавляет редакторские поля и TODO-заготовки. Записывается только draft в существующий файл подраздела. Seed, индекс и PostgreSQL не изменяются. ID после создания сохраняем при доработке названия.

Дополнительные параметры: `--id js-cache-boundary`, `--difficulty "Продвинутый"`, `--goal core`, `--dry-run`. Последний показывает план без записи. Если goal не задан, используется первая цель подраздела; её нужно уточнить при редакторском разборе. Раздел/подраздел заранее должны быть зарегистрированы, недоступный раздел сначала нужно подготовить в catalog.json.

Совпадающее название внутри выбранного подраздела пропускается без перезаписи. Близкие названия в других местах показываются как подсказка. Явно заданный занятый ID считается ошибкой. Автоматического объединения ответов нет.

## Пакетный импорт

Подготовить UTF-8 TXT: один заголовок на строку, можно с нумерацией или маркерами. Без заголовка группы и многострочных ответов. JSON-вариант - массив строк или объектов с title, необязательными id, difficulty, learningGoal, keywords и goalIds. Примеры: `content/templates/import-example.txt` и `import-example.json`.

```sh
pnpm content:import -- --file content/templates/import-example.txt --section javascript --subsection functions
pnpm content:import -- --file content/templates/import-example.txt --section javascript --subsection functions --write
```

Первый вызов показывает предварительный результат, второй сохраняет черновики. Можно указать --goal и общую --difficulty; в JSON отдельная строка может переопределить эти редакторские данные. Повторный импорт тех же названий в тот же подраздел пропустит их.

Перед записью готовится весь пакет: ошибка входа не сохраняет его часть. Подраздел блокируется на время записи и повторно читается для обнаружения параллельных изменений. Если процесс аварийно завершился и оставил .json.lock, после завершения процесса файл блокировки нужно удалить вручную. Ответы автоматически не генерируются и не объявляются готовыми. Проверяются свежие исходники всего каталога для выбора глобально свободных ID.

## Локальная работа с подразделом

```sh
pnpm content:report -- --section javascript --subsection functions
pnpm content:check -- --section javascript --subsection functions
```

В этих режимах загружаются только исходники выбранной области; остальное берётся из последнего индекса. Локальная check проверяет структуру источников и известные связи, но не актуальность собранных артефактов. Несобранные изменения в других разделах ей неизвестны. При переносе ID между подразделами и перед заполнением базы нужна полная проверка.

Для свежего индекса используется content:build. Сначала посмотреть report: сборка обновляет seed, относительно которого строится отчёт. Полная content:check сверяет все исходники и три артефакта. Guard перед db:seed/db:init всегда выполняет полный вариант.

## Проверки по области изменений

| Команда              | Что выполняет                                                                         |
| -------------------- | ------------------------------------------------------------------------------------- |
| `pnpm lint:ui`       | Oxlint для src и Vite-конфига                                                         |
| `pnpm typecheck:ui`  | TypeScript-проекты UI и Vite без генерации JS и Vite bundle; может обновить кеш типов |
| `pnpm check:ui`      | Линтер и проверка типов UI                                                            |
| `pnpm lint:server`   | Oxlint для server/src                                                                 |
| `pnpm check:server`  | Линтер и существующая проверка типов сервера                                          |
| `pnpm lint:content`  | Oxlint контентных CLI-скриптов                                                        |
| `pnpm check:content` | Линтер контентных инструментов и полная проверка каталога                             |
| `pnpm check:all`     | Последовательно контент, UI и сервер                                                  |

Ни одна из check-команд не запускает приложение, PostgreSQL, Docker, миграции или seed. Они не проверяют правильность решений задач, учебных ответов и пользовательских сценариев. После изменений запускать подходящую область; полный набор нужен для изменений общих контрактов или итогового контроля.

## Завершение пакета вопросов

```sh
pnpm content:report
pnpm content:build
pnpm check:content
pnpm db:seed
```

Перед публикацией заполнить TODO, проверить источники и связи, выбрать ready и осмысленно обновить coverageGoals. Draft не попадает в seed. Импортированные вопросы не переводятся в ready автоматически. База не меняется, пока пользователь не запустит db:seed.

## Обновлённый контентный цикл

С 2026-11-07 контентные команды разрешены агенту. Ответы находятся в content/answers, подробные навыки - в coverageGoals, источники - в content/references/sources.json, решения - в content/decisions.json, планы - в content/batches. Отчёт по умолчанию сравнивает только изменения; --all включает полный обзор. [Актуальная инструкция](content-workflow-v2.md) уточняет прежние ограничения запуска и формат импорта. Приложение и seed запускает пользователь.

## Компактный контекст

По умолчанию вывод короткий, подробности включаются параметрами. Find/context используют компактный lookup; show открывает ответ по ID. Batch хранит рабочие ID и хеши, источники доступны через sourceRefs. [Текущий процесс](lean-content-workflow.md) уточняет параметры и заменяет прежние примеры подробного вывода по умолчанию.
