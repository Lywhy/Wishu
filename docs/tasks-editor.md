# Задачи: рабочее пространство и проверка

Каталог: 28 задач, пагинация по 8, фильтры и страница в URL. Редактор Monaco сохраняет черновики локально. Условие остаётся рядом с редактором; разбор открывается в широкой боковой панели shadcn Sheet. На узком экране панель занимает почти всю ширину.

## Отчёт проверки

Под редактором находятся переключатели «Тесты» и «Консоль». Каждый тест раскрывает конкретные входные параметры или действия, ожидаемое и фактическое значение, ошибку и свой вывод консоли. Неуспешные тесты раскрыты сразу. Общая консоль объединяет записи с указанием сценария. Перехватываются log/info/warn/error/debug; ограничение - 80 записей на сценарий, до 12000 символов на сериализованное значение. Пустой вывод и отсутствие результата показаны явно. Сравнение структур выполняется рекурсивно, включая длину массивов.

## Наборы сценариев

У каждой задачи пять runtime-сценариев: два фиксированных базовых, два случайных средних, один случайный сложный. Генерация происходит заново внутри sandbox через crypto.getRandomValues. Конкретные входы сохраняются в текущем отчёте. Отдельная проверка контрактов TypeScript и запрета явного any дополняет эти пять тестов.

- Массивы: порядок, повторы, пустой вход, отрицательные числа, новая ссылка и замороженные входные данные. Для chunk меняется размер группы, для flatten - вложенность, для partition - порог и число вызовов предиката.
- Строки: регистр, пробелы и Unicode code points.
- groupBy и mapValues: случайные ключи/значения, собственный ключ **proto** в сложном сценарии; mapValues также проверяет количество вызовов callback.
- TypeScript: результаты функций, пустые коллекции, сохранение типов полей, readonly, недопустимые ключи и типы, литеральный дискриминант, замена типов при merge. first дополнительно получает строки и объекты.
- debounce: случайные задержки, серии вызовов, отсутствие раннего вызова, отмена старых таймеров, последний аргумент и контекст. Используются виртуальные таймеры.
- DOM: вложенный элемент кнопки, динамическое добавление, случайные data-id, игнорирование пустого элемента и кнопки вне списка.
- React: настоящий ReactDOM, нажатия и состояние, случайные props/последовательности действий, aria-состояния, границы пагинации, удаление элементов без изменения пропсов, сброс счётчика и оценки.

Статус «Решена» присваивается, только если есть все пять runtime-результатов и успешны все проверки, включая типовые. Изменение кода снимает статус. Ранее сохранённые статусы и черновики сохраняются.

## Ограничения

Это учебная локальная проверка, а не защищённый серверный judge. Рандомизация затрудняет подстановку готовых ответов, но не исключает обход и не доказывает корректность на любых входах. Структурные требования вроде использования функционального setState или единственного обработчика DOM требуют также просмотра реализации; поведенческие проверки сами по себе их не доказывают.

Подготовка идёт в worker с TypeScript 5.9.3, выполнение - в sandbox iframe без allow-same-origin. CSP ограничивает внешние ресурсы. Кооперативная проверка времени помогает с обычными циклами, но не гарантирует ограничение памяти или блокирующих встроенных операций. Для недоверенных решений нужен серверный процесс с лимитами ресурсов.

Приложение, сборка, линтер и решения не запускались. Визуальная проверка в браузере не проводилась. Выполнено форматирование. Ручная проверка: корректные/ошибочные решения всех 22 задач, повторные запуски со сменой параметров, console.log, исключения, редактирование во время проверки, переход между задачами, обе темы, узкий экран и клавиатурная навигация в панели разбора.
