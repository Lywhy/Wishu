# Проверка стилей через shadcn lint

Установлен @shadcn/lint 0.2.5 как корневая dev-зависимость pnpm workspace. Он подключён к существующему Oxlint 1.90 через jsPlugins в .oxlintrc.json. Отдельный ESLint и парсер не добавлялись. Package manager обновил pnpm-lock.yaml; install-скрипты зависимостей не запускались.

## Использование

```powershell
pnpm lint:styles
```

Команда проверяет frontend существующими правилами Oxlint и новым правилом shadcn/no-unknown-classes. Эта же конфигурация применяется в lint, lint:ui, check:ui и check:all. Сервер и контентные CLI не подпадают под новое правило. Предупреждения сами по себе не дают ненулевой exit code; ошибки существующих правил сохраняют прежнее поведение.

## Начальная политика

Для src/**/\*.ts и src/**/*.tsx включена проверка неизвестных Tailwind-классов с уровнем warn. UI-библиотека src/components/ui не исключена: опечатки в базовых компонентах тоже важны. Плагин использует установленный Tailwind v4, включая тему, импорты и utilities. При невозможности построить тему он сообщает об этом и использует собственную грамматику; такой запуск не равнозначен полноценной проверке по установленной теме.

components.json уже указывает на src/index.css и @/components/ui. Корневой tsconfig.json содержит paths для @/*. Дополнительные переопределения обнаружения не нужны.

Остальные политики пока не включены. no-raw-colors требует заранее определить исключения для смысловых статусов и цветов категорий. no-arbitrary-values требует различать случайные размеры и намеренные responsive-макеты/CSS-переменные. no-restyle требует согласованных контрактов Button, Card и остальных частей. require-static-classes может сообщать о корректных импортированных наборах классов, которые анализатор не умеет раскрыть. Их следует вводить отдельно после разбора текущих употреблений, без массового подавления предупреждений.

Изменять правила нужно в override для src внутри .oxlintrc.json. Основные правила React, a11y, TypeScript, исключения файлов и Oxfmt сохранены.

## Границы проверки

Это статическая проверка классов, а не визуальный аудит, проверка контраста, доступности всех сценариев или адаптивной вёрстки. Линтер не запускает приложение, но команда оставлена пользователю согласно правилам проекта. Агент выполнил установку зависимости, редактирование конфигурации и форматирование; lint, UI/серверные проверки и приложение не запускал. Загрузка плагина при реальном lint ещё не подтверждена запуском.
