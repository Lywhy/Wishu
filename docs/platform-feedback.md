# Баги, предложения и пополнение общей базы

В шапке рядом с поиском, настройками и темой находится ссылка на `/feedback`. Страница использует существующие shadcn Tabs, Select, Card, Input, Textarea и Button, общий стиль и компоненты появления страниц.

## Пользовательский сценарий

- Баг: страница, необязательный путь без query/hash и описание проблемы. При переходе из шапки путь подставляется, если ещё нет заполненного черновика.
- Предложение: Обучение, Вопросы, Задачи или Собеседования. У первых трёх есть выбор между дополнением материалов и улучшением интерфейса.
- Материалы: группа -> раздел -> необязательный подраздел -> темы через запятую, точку с запятой или перенос строки. Можно предложить новый раздел/подраздел и добавить до 10 блоков в обращение. В одном блоке до 50 тем по 200 символов; регистронезависимые повторы убираются. Для обучения подсказка ориентирована на лекции и практику, для задач - на практические навыки, для вопросов - на вопросы для собеседований.
- Собеседования: описание желаемого изменения без учебной таксономии.
- Черновики сохраняются в браузере, отдельно для бага и для каждой страницы предложений. При недоступном storage показывается существующее предупреждение LocalSaveNotice. Текст не очищается при ошибке запроса. Если сервер недоступен, последнюю неуспешную попытку можно скачать отдельным JSON с draft=true; это не подтверждение сохранения.

Сначала обращение сохраняется на сервере конкретной установки. Подтверждение проверяет ID. Повтор того же запроса с тем же UUID возвращает прежнее сохранение; другой текст с занятым UUID даёт 409. Изменения формы получают новый UUID. В серверном payload сохраняются названия разделов на момент отправки.

## Передача автору через GitHub

В корневом `.env` у владельца репозитория и в распространяемом `.env.example` укажите `VITE_FEEDBACK_GITHUB_REPOSITORY=owner/repository`. Эта настройка публичная, токен GitHub не требуется. После изменения перезапустите Vite; для production UI переменная должна присутствовать при сборке.

После сохранения доступны скачивание JSON и, если репозиторий настроен, открытие подготовленного issue. Пользователь сам проверяет текст и публикует его на GitHub. Нужен доступ к репозиторию и включённые Issues. При большом объёме вместо слишком длинного URL предлагается приложить полный JSON. Если репозиторий не настроен, UI честно предлагает передать файл вручную и не сообщает, что автор уже получил обращение.

Используется [документированный GitHub-механизм query-параметров title/body](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/creating-an-issue). Автоматической публикации, токенов в клиенте и отправки данных внешнему сервису при сохранении нет.

## Сервер и хранение

Новая миграция: `server/database/migrations/005_platform_feedback.sql`. Уже применённые файлы не изменяются. Обращения хранятся в `platform_feedback`; профиль нужен для проверки повторной отправки. Его удаление обнуляет ссылку, сохраняя само обращение. Содержимое - отдельный JSONB-документ; сортировка выгрузки и внешний ключ индексированы.

`POST /api/questions/platform-feedback`: cookie-профиль и проверка Origin из существующего QuestionProfilesService, DTO с ограничениями размеров, проверка принадлежности раздела группе и подраздела разделу. Новый контроллер имеет префикс `/questions`, чтобы использовать существующую cookie с Path=/api/questions. Баги и свободные предложения работают независимо от загрузки каталога. Общедоступного GET всех обращений нет.

Для автора есть `pnpm feedback:export`: выгрузка последних 1000 локальных обращений в `exports/feedback/`, без profile_id и хеша запроса. Имеющиеся файлы не перезаписываются. Папка исключена из Git. Эта команда собирает сервер и обращается к PostgreSQL; агент её не запускал.

Полученный JSON - редакторский вход, а не готовый seed. Автор сопоставляет темы с существующими вопросами, объединяет пересечения, готовит ответы через контентный цикл и публикует изменения репозитория. Пользовательские предложения не меняют общую базу автоматически. Пользователи обновляют код и выполняют `pnpm db:seed`; сохранённые ID продолжают связывать прогресс.

## Короткая подготовка

Вход перенесён из главной навигации в заголовок страницы вопросов. Основной адрес - `/questions/preparation`; старый `/session` перенаправляет туда. Обновлены поиск, breadcrumbs, баннер сессии и ссылки возврата. Маршрут `/api/questions/session` остаётся серверным API cookie-профиля.

## Ручная проверка

Агент не запускал приложение, линтеры, TypeScript, Docker, миграции, seed и обращения к БД. Выполнено форматирование изменённых TS/TSX/JSON/Markdown-файлов. Пользователь выполняет:

```powershell
pnpm db:migrate
pnpm check:ui
pnpm check:server
pnpm dev:all
```

Проверить: переход из шапки и прямой `/feedback`; Back/Forward; тёмную/светлую тему; клавиатурную навигацию вкладок и Select; узкий экран; независимые черновики; смену группы с очисткой зависимых полей; новый раздел и подраздел; добавление/удаление блоков; совпадающие темы; ошибку сервера и повторную отправку; отсутствие каталога; сохранение и JSON; пустую/заданную GitHub-настройку; большое обращение с приложением JSON. На короткую подготовку должна вести кнопка внутри вопросов, а `/session` должен перенаправлять на новый адрес с сохранением данных сессии.
