# Баги, предложения и пополнение общей базы

В шапке рядом с поиском и настройками находится ссылка на `/feedback`. Страница использует существующие shadcn Tabs, Select, Card, Input, Textarea и Button, общий стиль и компоненты появления страниц.

## Пользовательский сценарий

- Баг: страница, необязательная ссылка и короткое описание. Полную HTTP/HTTPS-ссылку можно вставить из браузера: адрес сервера, query и hash удаляются. При переходе из шапки путь подставляется, если ещё нет заполненного черновика. В shadcn Collapsible доступны необязательные шаги повторения и ожидаемый результат; они добавляются в details без изменения серверной схемы.
- В открытом вопросе рядом с заголовком есть кнопка с иконкой бага, доступная и в режиме сосредоточения. Она открывает shadcn Dialog без ухода со страницы. Название вопроса, раздел, подраздел, ID и ссылка заполняются автоматически. Можно выбрать тип проблемы: ответ, объяснение, пример, интерфейс или другое. Выделенный внутри блока ответа текст захватывается при нажатии кнопки (до 1500 символов); его можно убрать. Пользователь вводит описание, проверяет подготовленный текст и выбирает способ передачи. Ссылка «Полная форма» открывает `/feedback?question=<id>`. Текст и отдельные черновики вопросов сохраняются в браузере. Контекст, тип проблемы и фрагмент включаются в details, поэтому серверная схема не меняется. Общий черновик и сообщения о других вопросах не перезаписываются. В лекциях и задачах прежний ContentFeedback сохранён.
- Предложение: Обучение, Вопросы, Задачи или Собеседования. Новые черновики открываются в простом режиме улучшения страницы. У первых трёх можно выбрать дополнение материалов. Существующие черновики и их режимы сохраняются.
- Материалы: группа -> раздел -> необязательный подраздел -> темы через запятую, точку с запятой или перенос строки. Можно предложить новый раздел/подраздел и добавить до 10 блоков в обращение. В одном блоке до 50 тем по 200 символов; регистронезависимые повторы убираются. Для обучения подсказка ориентирована на лекции и практику, для задач - на практические навыки, для вопросов - на вопросы для собеседований.
- Собеседования: описание желаемого изменения без учебной таксономии.
- Черновики сохраняются в браузере, отдельно для бага и для каждой страницы предложений. При недоступном storage показывается существующее предупреждение LocalSaveNotice. «Подготовить обращение» проверяет форму и открывает предпросмотр без POST на сервер. Из него доступны GitHub, копирование текста, JSON и возврат к редактированию. При недоступном clipboard текст можно выделить вручную. Подтверждение копирования скрывается через 3 секунды.

Сохранение на сервере конкретной установки необязательно и находится в отдельном раскрывающемся блоке предпросмотра. Подтверждение проверяет ID. Повтор того же запроса с тем же UUID возвращает прежнее сохранение; другой текст с занятым UUID даёт 409. Изменения формы получают новый UUID. В серверном payload сохраняются названия разделов на момент отправки. Ошибка локального сохранения не блокирует копирование и скачивание. JSON до подтверждённого сохранения содержит draft=true, а также человекочитаемое message с названиями групп и разделов.

## Передача автору через GitHub

В корневом `.env` у владельца репозитория и в распространяемом `.env.example` укажите `VITE_FEEDBACK_GITHUB_REPOSITORY=owner/repository`. Эта настройка публичная, токен GitHub не требуется. После изменения перезапустите Vite; для production UI переменная должна присутствовать при сборке.

Из предпросмотра доступны скачивание JSON и, если репозиторий настроен, открытие подготовленного issue. Локальный сервер для бага и свободного предложения не нужен; каталог для выбора материалов загружается как прежде. Пользователь сам проверяет текст и публикует его на GitHub; скриншот можно добавить там. Нужен доступ к репозиторию и включённые Issues. Заголовок включает краткое описание или первые предложенные темы. При большом объёме вместо слишком длинного URL предлагается скопировать полный текст либо приложить JSON. Если репозиторий не настроен, основное действие - копирование. UI не сообщает, что автор уже получил обращение.

Одинаковый FeedbackDelivery используется в быстром диалоге и полной форме. При настроенном репозитории основная кнопка - GitHub, остальные действия находятся в shadcn Dropdown Menu «Другие способы»: копировать, JSON и самостоятельный HTML-отчёт. Без GitHub основным остаётся копирование. Dropdown Menu взят из официального реестра shadcn base-nova и адаптирован под установленный lucide; новые пакеты не нужны.

## Скриншоты и ошибки формы

До 3 PNG/JPEG по 3 МБ: выбор файла или вставка изображения из буфера, когда фокус в блоке скриншотов. Есть предпросмотр и удаление. Изображения хранятся в памяти с отдельным ключом обращения, поэтому доступны при переходе из диалога в полную форму. При перезагрузке они теряются; текстовые черновики сохраняются как прежде. Base64 не записывается в localStorage.

HTML-отчёт содержит текст и встроенные изображения в одном файле, без скриптов, приложения или сетевой загрузки ресурсов. Пользовательский текст и имена файлов экранируются. JSON, clipboard и локальный API содержат только текст. GitHub query-ссылка тоже не загружает бинарные файлы: выбранные изображения пользователь прикрепляет в issue отдельно. Это ограничение явно объясняется рядом с изображениями. [GitHub: прикрепление файлов](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/attaching-files).

В полной форме валидация показывает ошибки рядом с соответствующими полями, включая группу, раздел, подраздел и темы. Поля получают aria-invalid и aria-describedby, после отправки фокус переходит к первой ошибке. Исправления пересчитываются по текущему черновику. В быстром диалоге ошибка описания также связана с textarea. Общее сообщение используется для отказа сервера или слишком большого обращения.

Используется [документированный GitHub-механизм query-параметров title/body](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/creating-an-issue). Автоматической публикации, токенов в клиенте и отправки данных внешнему сервису при сохранении нет.

## Сервер и хранение

Новая миграция: `server/database/migrations/005_platform_feedback.sql`. Уже применённые файлы не изменяются. Обращения хранятся в `platform_feedback`; профиль нужен для проверки повторной отправки. Его удаление обнуляет ссылку, сохраняя само обращение. Содержимое - отдельный JSONB-документ; сортировка выгрузки и внешний ключ индексированы.

`POST /api/questions/platform-feedback`: cookie-профиль и проверка Origin из существующего QuestionProfilesService, DTO с ограничениями размеров, проверка принадлежности раздела группе и подраздела разделу. Новый контроллер имеет префикс `/questions`, чтобы использовать существующую cookie с Path=/api/questions. Баги и свободные предложения работают независимо от загрузки каталога. Общедоступного GET всех обращений нет.

Для автора есть `pnpm feedback:export`: выгрузка последних 1000 локальных обращений в `exports/feedback/`, без profile_id и хеша запроса. Имеющиеся файлы не перезаписываются. Папка исключена из Git. Эта команда собирает сервер и обращается к PostgreSQL; агент её не запускал.

Полученный JSON - редакторский вход, а не готовый seed. Автор сопоставляет темы с существующими вопросами, объединяет пересечения, готовит ответы через контентный цикл и публикует изменения репозитория. Пользовательские предложения не меняют общую базу автоматически. Пользователи обновляют код и выполняют `pnpm db:seed`; сохранённые ID продолжают связывать прогресс.

Проверить пустую/заданную GitHub-настройку и большое обращение: в URL только краткая инструкция, полный текст остаётся в предпросмотре и JSON. Открытие GitHub не означает публикацию. ## Изменения 2026-11-13

Закрытие быстрого диалога по крестику, Escape или внешней области очищает описание, выбранный фрагмент, тип проблемы, дополнительные детали, предпросмотр и скриншоты текущего вопроса. Метаданные самого вопроса остаются для нового обращения. Счётчик сессии и отписка компонента загрузки не дают позднему FileReader восстановить очищенные изображения. Переход по ссылке «Полная форма» является продолжением заполнения, а не отменой; во время чтения файлов он отключён.

Поле скриншотов использует бесплатный ReUI Compact File Upload и use-file-upload в стиле base-nova. Доступны перетаскивание с подсветкой области, кнопка выбора, вставка из буфера, прежние лимиты, предпросмотр и удаление. Исходник адаптирован под русский интерфейс, существующий HTML-экспорт и хранение в памяти. Object URL освобождаются; внешние callback не выполняются внутри React-updater. Новых npm-зависимостей нет. Источник: https://reui.io/docs/components/base/file-upload.

Ручная проверка: закрыть диалог пустым, заполненным, с изображением и во время чтения, затем открыть заново; данные не должны возвращаться. Проверить Escape, крестик, фон, перетаскивание допустимых и ошибочных файлов, лимиты, повторный выбор того же файла и освобождение превью. Приложение и UI-проверки агент не запускал.
