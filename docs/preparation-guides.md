# Профили и редакторские ориентиры

Реестр: content/preparation/catalog.json. Профиль задаёт целевую роль, области и глубину, но не обещает формат каждого собеседования и не скрывает сложные основы.

Эталонные записи выбраны после чтения текущих ответов: closures, closures-in-loops, js-proxy-internal-slots. Это образцы структуры и глубины, не неизменяемые идеальные ответы. Хранятся только ID, без копирования Markdown.

Карта пересечений указывает канонические и прикладные объяснения для замыканий, event loop и HTTP-кеша. Дальше добавлять связи по фактическим редакторским решениям. VersionNotes указывает, когда перепроверять зависимые от runtime темы; lastVerifiedAt:null не обозначает актуальную проверку.

Реальные затруднения собеседований добавлять в interviewFeedback по шаблону content/templates/interview-feedback.json, затем связывать с каталогом. Наблюдения не выдумывать; браузерный трекер собеседований автоматически не экспортируется в этот реестр.

Все эти данные подключаются к content:context только явно: --profile frontend-middle, --examples, --boundaries, --feedback, --version-notes. По умолчанию их нет в кратком выводе.
