# Подробные правила контента

## План и границы

Определить раздел, подраздел и учебный навык. Группу брать из существующего каталога. Сначала сопоставить с матрицей и соседними темами, затем готовить пакет. Числового потолка вопросов нет; разнообразие сложности определяется навыками, а не квотами.

Смысловая цель важнее совпадения слов. Точные дубли не добавлять. Близкие формулировки объединять, когда их раскрывает один связный ответ. Разные навыки оставлять отдельно, даже если они связаны общей технологией. Родственные методы группировать по задаче. Для закрепления ссылаться на канонический вопрос.

Материал можно перенести в более подходящий подраздел; объяснить классификацию в отчёте. Широкий вопрос не превращать в несвязный перечень тем.

## Ответ

Ясный заголовок, краткий summary, прямой ответ, механизм и границы, полезный пример, типичная ошибка и одна главная мысль. Использовать Markdown, списки/таблицы по смыслу и выделения; глубина соответствует уровню. Не увеличивать объём ради количества.

Указывать существенные условия: среда, strict mode, script/module, версия и поддержка. Сверять неоднозначные, новые и зависящие от версии факты с первичными источниками. Не называть вручную разобранный пример выполненным тестом. Приоритет не равен сложности. Reviewed/imported не объявлять полной проверкой.

Draft до редакторской готовности; ready требует заполненных полей, источников и отсутствия TODO. SourceRefs относится к реестру того же подраздела; sources[] допустим как совместимый вариант, но не вместе с refs. Существенные условия ответа нельзя прятать только в редакторских оговорках.

## Сохранность

Сохранять ID при уточнении. Реальное слияние разных ID требует отдельного переноса прогресса и избранного, с явным разрешением конфликтов статусов. Удаление из JSON не удаляет запись PostgreSQL: seed выполняет upsert. Пользовательские вопросы из UI автоматически в исходники не экспортируются. Применённые миграции не менять.

Контентные команды разрешены агенту. Приложение, Docker, сборку/проверки UI и сервера, миграции, seed и решения задач запускает пользователь. Итоговую полную content:check не заменять локальной.

## Состояние и результат

Работать в два прохода: цели/пересечения/решения, затем ответы/примеры/источники. Фиксировать решения в журнале и следующие действия в плане, без копирования ответов и переписки. Перед правкой читать актуальный файл; хеш служит только для пропуска повторного анализа.

В результате сообщать добавления, расширенные канонические ответы, объединения, уточнения размещения и проверки. Для объединений указывать исходные вопросы и итоговую формулировку. Не выдавать число вопросов или статус covered за гарантию подготовки ко всем собеседованиям.
