# Как наполняем каталог вопросов

Правила применяются ко всем разделам. Число вопросов - результат анализа покрытия, а не заранее установленный предел или квота.

## Что считаем покрытием

До расширения раздела составляем матрицу: тема, подтема, проверяемый навык, базовый механизм, применение, сложные границы, разбор кода, канонический ID и источник. Сопоставляем её с текущим каталогом и соседними разделами.

Для каждой темы рассматриваем понятие, поведение, практический выбор, типичные ошибки и значимые исключения. Не каждая тема требует отдельной карточки каждого уровня: узкий метод не растягиваем в искусственную серию. Глубину определяет навык, а не редкость API.

- Базовый: объяснить понятие, простой контракт и обычный пример.
- Средний: применить механизм, сравнить подходы, объяснить ограничения и найти ошибку.
- Продвинутый: рассуждать о взаимодействии механизмов, владении, времени жизни, гонках, протоколах и версиях среды.

Границы раздела фиксируем явно. ECMAScript, браузерные API, Node.js, TypeScript и фреймворки связаны, но имеют разные контракты. Не обещаем покрыть все будущие собеседования одним конечным каталогом. Новые пробелы добавляем по матрице без числового потолка.

## Как избегаем повторов

1. Сравниваем учебную цель и ожидаемое объяснение, включая соседние подразделы.
2. Если новый нюанс отвечает на тот же вопрос, расширяем канонический ответ с сохранением ID.
3. Родственные методы группируем по задаче, а не создаём карточку на каждый метод справочника.
4. Отдельный прикладной вопрос допустим, если нужно другое рассуждение: например, определение Promise и гонка read-modify-write через await.
5. Повторное применение для закрепления обозначаем явно и связываем с теорией. Разбор кода содержит прогноз, механизм и исправление, а не пересказ определения.
6. Межраздельные темы связываем ссылками. Не копируем ответ ради заполнения количества.

## Как оформляем ответ

Короткий прямой ответ, затем механизм и границы, подходящий пример с пояснением, типичная ошибка и главная мысль. Используем Markdown: подзаголовки, списки, таблицы там, где есть сравнение, выделение важных выводов и ссылки на закрепление. Не подменяем объяснение набором терминов и не делаем каждый ответ длиннее ради объёма.

Для примера указываем существенный контекст: browser/Node, classic script/module, strict mode, совместимость и временные условия. Отделяем гарантии стандарта от деталей движка, приблизительных оценок и поведения старых версий. Результат ручного разбора не называем результатом выполненного теста.

Спорные и новые возможности сверяем с первичными источниками: спецификации, документация платформы и авторов реализации. Living draft ECMAScript не равен последней опубликованной редакции; наличие в документации не доказывает поддержку во всех runtime. Предложения и ограниченно поддерживаемые API маркируем. В контенте используем дефис вместо длинного тире.

## Сохранность и результат

Сохраняем ID, ссылки, прогресс и избранное. Применённые миграции не меняем. Удаление записи из seed не удаляет её из базы; реальное слияние разных ID требует отдельного плана переноса данных.

Отчёт содержит добавленные вопросы, расширенные канонические ответы, распределение по темам и сложности, связи для закрепления и оставшиеся границы. Не выдаём количество за доказательство полноты.

В этом проекте приложение, Docker, seed, миграции, сборку, lint и тесты запускает пользователь. Агент может подготовить данные и отформатировать изменённые файлы; код примеров не исполняет.

## Файлы и инструменты

Рабочие исходники находятся в `content/questions/<sectionId>/<subsectionId>.json`; `server/database/seeds/questions.json` - собранный результат. Используем [индекс, карту покрытия и редакторский процесс](question-content-workflow.md). Импортированная цель из summary требует смыслового пересмотра, а общий core не доказывает полноту подраздела. Сборку и проверки выполняет пользователь.

## Обновлённый контентный цикл

С 2026-11-07 контентные команды разрешены агенту. Ответы находятся в content/answers, подробные навыки - в coverageGoals, источники - в content/references/sources.json, решения - в content/decisions.json, планы - в content/batches. Отчёт по умолчанию сравнивает только изменения; --all включает полный обзор. [Актуальная инструкция](content-workflow-v2.md) уточняет прежние ограничения запуска и формат импорта. Приложение и seed запускает пользователь.
