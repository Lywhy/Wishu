# Работа с компактным контекстом

## Два уровня чтения

Сначала использовать content:find или content:context. Они читают question-lookup.json без ответов, источников и подробных графов. По умолчанию показывают не больше трёх записей с ID, названием, целью и путями. Полный ответ открывать через content:show только для изменяемого или сравниваемого вопроса.

```sh
pnpm content:find -- "замыкания"
pnpm content:context -- --section javascript --subsection functions "closure"
pnpm content:show -- --id closures
```

Context по умолчанию не загружает Markdown-ответы или полную карту. Явные --skills, --sources, --decisions, --neighbors добавляют только нужную часть, --answers включает ответы, --all расширяет подборку. --json сохраняет тот же выбор полей, а не включает скрытые подробности. --limit меняет размер подборки.

## Актуальность и снимки файлов

При сборке формируется content-files.json с SHA-256 исходников и Markdown. Context сравнивает снимки выбранной области и сообщает об устаревшем индексе. --fresh читает свежие исходники, но не переписывает индекс; content:build обновляет снимки. Неизвестный ID нового вопроса становится доступен в content:show после сборки.

Хеш используется для определения необходимости повторного анализа, а не как доказательство правильности ответа. Он проверяет байты файла; изменение форматирования тоже считается изменением. Перед каждой правкой читать актуальный файл, даже когда он не изменился после снимка. Индекс не заменяет полный content:check перед завершением пакета.

## Компактное продолжение пакета

```sh
pnpm content:batch -- --new js-closures --section javascript --subsection functions
pnpm content:batch -- --id js-closures --remember --questions closures,closures-in-loops --next "Сравнить примеры захвата переменных"
pnpm content:batch -- --id js-closures
pnpm content:context -- --batch js-closures
```

Workspace хранит только рабочие ID, ссылки на решения, хеши зависимых файлов и следующие действия. Ответы, код и история чата туда не копируются. Одно действие ограничено 280 символами; список - восемью действиями. --decisions у remember принимает ID записей журнала через запятую. --dry-run показывает подготовку снимка без записи.

После выбора рабочих ID content:context --batch ограничивается ими. Изменения в JSON подраздела, общих источниках, журнале и инструкциях также инвалидируют снимок. Неизменённые материалы не требуют повторного разбора; изменённые файлы читать заново. Внешние изменения в других темах могут повлиять на пересечения: итоговый отчёт и полную проверку не пропускать.

Batch по умолчанию показывает только текущий проход, следующие действия и число изменённых файлов. Полный план и baseline доступны через --json; --all расширяет список путей. Baseline начала пакета и workspace последнего рабочего снимка имеют разное назначение и не перезаписывают друг друга.

## Короткий вывод команд

Build/check выводят одну строку успеха. Find/context ограничивают подборку. Report по умолчанию сопоставляет только изменённые записи, summary показывает счётчики, а new/import показывают не больше трёх записей каждой группы. Для подробностей использовать:

```sh
pnpm content:report -- --verbose
pnpm content:summary -- --json
pnpm content:import -- --file content/templates/full-import-example.json --section javascript --subsection functions --full --verbose
```

Ошибки структуры и ссылок выводятся подробно и сохраняют ненулевой код выхода. Сокращение обычного вывода не скрывает ошибки. --all в report расширяет область сопоставления кандидатов; он не включает ответы автоматически.

## Общие источники и оговорки

У источника темы есть стабильный id. В вопросе можно хранить editorial.sourceRefs вместо копий title/url. Референс относится к библиотеке того же подраздела. Поддерживается прежний sources[] для нового материала; нужно выбрать ровно один вариант. При загрузке refs разрешаются для проверки, а runtime seed не содержит редакторских полей.

Caveats темы хранит общие оговорки. CheckedAt:null обозначает отсутствие свежей проверки. Спорные утверждения и поддержку новых API всё равно проверять по первичным источникам. Не переносить в общие оговорки особенности, меняющие основной ответ: существенное условие должно быть видно читателю вопроса.

## Инструкции и проверка результата

Корневые правила содержат обязательные ограничения и маршруты к инструкциям областей. Подробные правила качества читаются при работе с контентом, правила CLI - при изменении инструментов. Не копировать одинаковые правила в каждый план или вопрос.

Агенту разрешены контентные команды. Приложение, Docker, сборка/проверки UI и сервера, миграции, seed и код примеров остаются за пользователем. До завершения работы агент форматирует изменённые исходники, выполняет content:build и полный content:check. Хеши исходников фиксируются после форматирования; повторная правка исходников требует новой сборки снимков.

Измерять можно размер файлов индекса и длину фактического вывода. Это не точный счётчик токенов модели и не обещание фиксированной экономии: результат зависит от выбранных вопросов и задачи.
