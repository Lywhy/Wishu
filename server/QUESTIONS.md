# Сервер раздела «Вопросы»

Используется существующий NestJS и `pg`. ORM и регистрация пользователей не добавлены.
Каталог, ответы, отметки и избранное хранятся в PostgreSQL. Прогресс привязан
к анонимной сессии браузера через HttpOnly-cookie со сроком 180 дней.
В базе хранится хеш случайного токена, сам токен недоступен JavaScript.

## Первый запуск

Из корня Wishu, после настройки существующих `.env`:

```powershell
pnpm install
docker compose up -d postgres
pnpm db:init
pnpm dev:all
```

`db:init` собирает backend, применяет миграции и наполняет каталог.
Эта команда не запускает HTTP-сервер. Она использует `server/.env`:
для текущей локальной базы `PGHOST=127.0.0.1`, `PGPORT=15432`.
Настройки пользователя, пароля и базы должны совпадать с корневым `.env`.

Отдельные операции:

```powershell
pnpm db:migrate
pnpm db:seed
```

Миграции запускаются явно, записываются в `schema_migrations`, выполняются
транзакционно под advisory lock. Изменение уже применённого файла обнаруживается
по checksum. Для последующих изменений создавайте следующий SQL-файл.

Наполнение берётся из `server/database/seeds/questions.json`. Повторный seed
обновляет каталог по стабильным идентификаторам и не удаляет дополнительные
записи или прогресс. Редактируйте этот файл для изменения начального контента.

## Запуск API в Docker

Если API тоже работает в контейнере, после запуска PostgreSQL выполните:

```powershell
docker compose --profile api build api
docker compose --profile api run --rm --no-deps api node dist/database/cli.js init
docker compose --profile api up -d api
```

Это использует окружение Compose с хостом базы `postgres:5432`.
Миграции и seed включены в runtime-образ. Для frontend используйте `pnpm dev`;
локальный `pnpm dev:server` одновременно с контейнером API запускать не нужно.

## API

Все адреса ниже имеют префикс `/api/questions`.

| Метод | Адрес                   | Результат                                                   |
| ----- | ----------------------- | ----------------------------------------------------------- |
| GET   | `/catalog`              | Группы, разделы, подразделы и вопросы в заданном порядке    |
| GET   | `/:questionId`          | Отдельный вопрос; неизвестный идентификатор - 404           |
| POST  | `/session`              | Создание/восстановление анонимной сессии и текущий прогресс |
| GET   | `/progress`             | Отметки, избранное, настройка раскрытия ответов             |
| PATCH | `/progress/:questionId` | Частичное обновление `status` и/или `saved`                 |
| PATCH | `/settings`             | Обновление `autoRevealAnswers`                              |
| POST  | `/progress/import`      | Однократное начальное заполнение прогресса профиля          |

`status`: `repeat`, `learned`, `skipped` или `null` для снятия отметки.
`saved` и `autoRevealAnswers` - boolean. Некорректные значения и неизвестные поля
отклоняются с HTTP 400. Прогресс без действующей сессии - HTTP 401.
Изменение настроек или отметки не затрагивает другие поля.

Клиент при первом создании сессии переносит локальные отметки и избранное.
Повторный импорт не перезаписывает существующие отметки. При последующих
загрузках источником прогресса служит сервер. Черновики задач остаются локальными.

## Подключение frontend

В режиме разработки Vite проксирует `/api` на `http://127.0.0.1:3000`.
В запросах к API передаются cookie. Для другого адреса API можно задать
`VITE_API_URL` в корневом `.env.local`; при этом нужно настроить reverse proxy,
допустимый origin и cookie для выбранной схемы развёртывания.

Рабочая схема - UI и API на одном сайте, с префиксом `/api`. `CORS_ORIGIN`
должен точно соответствовать origin интерфейса. Для HTTPS-развёртывания
задайте `COOKIE_SECURE=true`; в локальном Docker Compose используется `false`.
Сессия не является аккаунтом и не синхронизирует прогресс между устройствами.
При удалении cookie без локальной резервной копии прежний профиль не восстановится.

Сбой API показывает состояние ошибки вместо демонстрационных данных.
Сбой записи оставляет прежнее состояние, выводит ошибку и позволяет повторить действие.

## Ручная проверка

```powershell
Invoke-RestMethod http://localhost:3000/api/questions/catalog
Invoke-RestMethod http://localhost:3000/api/questions/equality
Invoke-RestMethod -Method Post http://localhost:3000/api/questions/session -SessionVariable wishuSession
Invoke-RestMethod -Method Patch http://localhost:3000/api/questions/progress/equality -WebSession $wishuSession -ContentType 'application/json' -Body '{"status":"learned"}'
Invoke-RestMethod http://localhost:3000/api/questions/progress -WebSession $wishuSession
```

В браузере проверьте переходы раздел → подраздел → вопрос, боковое меню,
три отметки, снятие отметки, избранное и глобальное раскрытие ответов.
После обновления страницы отметки должны загружаться из базы. Проверьте
изолированный профиль в другом браузере, отклонение недопустимого статуса,
поведение при выключенном API и сохранение прогресса при повторном `db:init`.

Сервер, контейнеры, миграции, seed, сборка и проверки при реализации не запускались.

## Добавление вопросов

Для блока «Частая ошибка» используется необязательное строковое поле `pitfall`.
Оно добавляется миграцией `003_question_pitfalls.sql` и возвращается в каталоге
и отдельном вопросе. Если значения нет, блок не отображается. В seed добавлены
конкретные оговорки для 17 существующих вопросов; ID и прогресс сохранены.

Перед использованием обновлённого API выполните `pnpm db:migrate`, затем
`pnpm db:seed`. Команды выполняются пользователем самостоятельно.

Правила анализа, объединения дублей и сохранения прогресса зафиксированы в
[database/seeds/AGENTS.md](database/seeds/AGENTS.md).

## Метаданные каталога

Миграция `002_catalog_metadata.sql` добавляет два boolean-поля:

- `sections[].inDevelopment` в seed/API (`in_development` в БД): недоступная карточка с пометкой «В разработке». По умолчанию `false`.
- `questions[].popular`: редакционная пометка «Популярный» в списке и на странице вопроса. По умолчанию `false`; она не зависит от личных отметок или избранного. Для выбранных вопросов укажите `true` в seed и повторите наполнение.

Перед запуском обновлённого API выполните `pnpm db:migrate`, затем `pnpm db:seed`. Существующие ID вопросов и прогресс сохраняются.

Сложность имеет нейтральный бейдж. Отметки: повторить - янтарный, изучил - зелёный, пропустить - фиолетовый; избранное - синий, популярность - розовый, разработка - нейтральный пунктирный. Текст сохраняет смысл независимо от цвета. PostgreSQL размещён в группе «Базы данных» вместе с SQL и Redis.
